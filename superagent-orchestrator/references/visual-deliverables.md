# 视觉类交付手册（海报 / 信息图 / 知识地图）

本文件是 `superagent-orchestrator` 的视觉域专项手册；通用编排流程与其它领域见 `SKILL.md`、`domain-playbooks.md`。

适用于需要一个「可看的成品」而不是文档的任务：横版/竖版海报、知识地图、信息图、封面、课程路线图。核心原则：**模型只负责无文字底图，中文与版式全部本地可控；审查只看最终像素。**

## 1. 先定成品契约

开工前把下列数值写进 `plan.json` 的 `goal`、`acceptance` 和 `assumptions`，不要留到渲染时再猜：

| 项目 | 示例 |
|------|------|
| 格式 | PNG / RGB（印刷另定 CMYK） |
| 尺寸 | 5248×2944（4K 16:9），不是“约 4K” |
| 用途 | 屏幕、投屏、A3 横向打印 |
| 文字 | 简体中文；技术缩写保留英文 |
| 禁用词 | 用户明确要求删除的词（如“自学/转行”） |
| 水印 | 无可见水印、无模型名、无生成署名 |
| 内容量 | 20 站 × 5 知识点 + 20 实战，共 100 + 20 项 |

同一事实会在标题、副标题、AC、报告和图内重复出现，必须用**同一数据源**生成并复算。反例：AC 要求报告 7 个部分，任务边界却写“六个必备部分”。

### 1.1 项目目录与输出位置

- 视觉项目默认整体放在 `<cwd>/out/superagent-<主题>/`，`plan.json`、`plan.state.json`、`work/`、`assets/`、`out/`、`report.md` 全在其中。
- 最终 PNG/报告在项目内 `out/`；会话根 `out/` 可再平铺一份便于取用的副本，但副本不替代项目目录。
- 用户说“结果放 out”时，默认理解为**项目目录整体进 out**，不是只复制最终图片；若只想要成品，用户会明确说“只放图片/报告”。
- 交付后移动项目目录，必须同步修正报告里的绝对路径与再生成命令，并用 `grep` 扫描旧路径；路径失效视为交付缺陷。

## 2. 推荐 DAG（生成与排版解耦）

```text
T1 内容大纲 ──┬──────────────────────────────┐
              │                              │
T2 API/密钥规范 ──> T3a 生图提示词 ──> T5 底图 │
              │                              │
              └──> T3b 版式 spec ──> T4 渲染脚本 ──> T6 合成 ──> T7 独立审查 ──> T8 报告
```

- T1 与 T2 可并行；T3a/T3b 可并行；T5 只依赖 T3a/T2，**排版迭代不重生成底图**。
- T4 依赖 T1 + T3b；T6 依赖 T4 + T5；T7 不参与实现；T8 只消费 T7 的结论。
- 若提示词与版式放在同一节点，底图就会被迫依赖整个版式；一旦改字号或文案，底图被连带重跑。拆成 `T3a/T3b` 是更稳的形态。
- `inputs` 中读取的任何任务产物，都必须在直接或传递上游的 `outputs` 中；`validate` 会拒绝“读取 T3 的 prompt，却只依赖 T2”的计划。

可直接套用的节点骨架：

```json
[
  { "id": "T3a", "deps": ["T1", "T2"], "outputs": ["work/prompt.txt"] },
  { "id": "T3b", "deps": ["T1", "T2"], "outputs": ["work/poster-spec.json"] },
  { "id": "T5",  "deps": ["T2", "T3a"], "outputs": ["assets/base.png"] },
  { "id": "T4",  "deps": ["T1", "T3b"], "outputs": ["work/render_poster.py"] },
  { "id": "T6",  "deps": ["T4", "T5"], "outputs": ["out/final.png"] }
]
```

底图已干净且风格未变时，保留 `assets/base.png` 与其哈希，直接复用；只有风格、主体或比例变化才重新调用图像 API。

## 3. 视觉 AC 配方

至少覆盖以下 10 类，按项目裁剪，但不要只写“好看/清晰”：

| 编号 | 判据 | 验证方法 | 证据 |
|------|------|----------|------|
| V1 | 成品存在，PNG/RGB，尺寸与比例精确 | PIL 打开断言 `size/mode`；独立复算宽高比 | 命令输出 |
| V2 | 内容数量、顺序、文字与大纲一致 | 脚本断言 outline 的 13×5+13；逐站核对 | 断言输出 + 审查表 |
| V3 | 版式层级成立：根→阶段→站点→叶子，连接连续 | 全图 + 100% 裁切；核对坐标/连接数 | 全图与裁切图 |
| V4 | 无截断、无重叠、无不可读的最小字号 | 100% 裁切最密区域与最长标题 | 裁切图 |
| V5 | 对比度足够，底图不抢字 | 6 项美观检查：对齐/间距/字号/色彩/对比/背景干扰 | 审查表 |
| V6 | 中文无乱码、无方框、无问号替代符 | 字体存在 + 字形覆盖 + U+FFFD 扫描 + 目视 | 字体日志 + 扫描输出 |
| V7 | 无可见水印、模型名、生成署名 | 源码扫描 + 底图四角/页脚/中心裁切目视 | 裁切图 + 扫描 |
| V8 | 无用户禁用词 | 对 spec/outline/渲染脚本做词表扫描，再目视成品 | 扫描输出 |
| V9 | API Key 未落盘 | `grep -rE 'sk-[A-Za-z0-9]{20,}' .` 与私钥头扫描无匹配 | 退出码 1 + 无输出 |
| V10 | 独立 reviewer 判 PASS | 审查者不参与渲染；每条 AC 附证据 | review.md |

补充：最终图必须由本地脚本可重复生成；报告写明模型、尺寸、耗时、底图路径与再生成命令。

## 4. 生图提示词契约

底图只生成氛围、材质、空间与留白，不生成任何可读文字。提示词中明确写入：

```text
no text, no letters, no words, no numbers, no labels,
no watermark, no logo, no signature, no creator mark,
no UI mockup, no fake interface, no illegible glyphs
```

同时给出：

- 用途与比例：`16:9 horizontal poster background, 4K`
- 主体：工业配电柜/产线/实验室等，靠左或靠右留出文字区
- 风格：深色工业风、低对比背景、可叠加文字的负空间
- 负面：不要文字、不要水印、不要品牌、不要密集纹理、不要高亮抢字

生成后先验底图：四角、中心、页脚区域无文字/水印；尺寸正确；主体不压未来文字区。底图不合格就重生成，不要靠后期糊掉水印。

## 5. 本地中文渲染规则

1. **固定字体**：显式加载本机中文字体（如微软雅黑 `msyhbd.ttc`/`msyh.ttc`），启动时校验文件存在并记录路径；禁止默认字体静默回退。
2. **字形覆盖**：逐字符检查字体是否有字形；用 U+E000/U+E001 的 `.notdef` 作为对照，发现替代框立即失败。
3. **Pillow alpha 陷阱**：在 RGBA 上 `ImageDraw` 是替换像素而不是混合，最后 `convert("RGB")` 又会丢掉 alpha，半透明填充会变成实色，导致文字与底色同色“消失”。先把颜色与底色预混合，再画实色：

```python
def mix(hex_color, alpha, base):
    a = alpha / 255.0
    return tuple(round(c * a + b * (1 - a)) for c, b in zip(rgb(hex_color), base[:3])) + (255,)
```

4. **分层绘制**：底图 → 压暗/渐变 → 连接线 → 面板 → 文字 → 页脚。每层用实色或预混色，不依赖运行时 alpha。
5. **文字安全**：按字体度量计算行高与换行；给最长标题、最密列表、最小字号留余量；文本块不要贴边，至少留 20–30px 内边距。
6. **脚本落盘**：渲染逻辑写进 `work/render_poster.py`，不要用超长 `python -c` 或 shell 内联正则改源码；便于复现、审阅和回归。
7. **输出 RGB**：最终 `convert("RGB")` 保存；记录尺寸、字节数、耗时、唯一可见字符数与字体路径到 `work/render-log.txt`。

## 6. 独立视觉审查

审查者与渲染执行者分离，审查对象是**最终 PNG**，不是 spec 或脚本。

1. 先看整图：层级、阅读顺序、留白、阶段配色、是否有明显空洞或拥挤。
2. 再看 100% 裁切：标题区、首站、末站、最密知识点、最长实战任务、页脚、四角、最小字号。
3. 逐项判：截断、重叠、对比度、对齐、连接线遮挡、底图干扰、水印/署名、禁用词。
4. 抽查内容：至少每阶段 1 站，核对知识点与实战任务是否与技术常识一致。
5. 修复后重跑**同一组裁切**，做回归；不能只看修复点，防止修 A 坏 B。
6. 审查结论写 `work/review.md`：每条 AC 的 PASS/FAIL/PARTIAL + 证据路径；FAIL 不进入交付。

常见视觉缺陷与修法：

| 现象 | 根因 | 修法 |
|------|------|------|
| 站点编号/标签“消失” | RGBA 半透明填充变实色，与文字同色 | 预混色后画实色 |
| 右侧底图太亮，文字发灰 | 只压暗了左侧 | 左右边缘分别做暗角渐变 |
| 徽标贴边/被裁 | 文本宽度按经验估 | 用 `fit_font` 按可用宽度收缩，增加内边距 |
| 站点之间大片空洞 | 行高固定、站数少 | 拉开节点高度或增加枝干/留白设计，不要只放大字号 |
| 页脚出现模型署名 | 模板默认带 credit | 删除 credit，AC 明确“无生成署名” |
| 中文方框 | 字体缺字或回退到 Latin 字体 | 字形覆盖检查 + 显式字体路径 |

## 7. 密钥与外部 API

- Key 只从环境变量读取（如 `AGNES_API_KEY`），不写进脚本、JSON、prompt、日志、报告、图片元数据。
- 不把 Key 拼进 URL query；放认证头；不要 `set -x`、不要 `echo` 请求头。
- 失败重试日志只记录状态码、耗时、错误摘要，不记录请求体中的认证信息。
- 交付前扫描 run 目录：

```bash
grep -rE 'sk-[A-Za-z0-9]{20,}' .
grep -rE -- '-----BEGIN [A-Z ]*PRIVATE KEY-----' .
```

两条命令都应“无输出、退出码 1”。若命中，先删除/轮换密钥，再重新扫描；不要把命中内容贴进报告。

## 8. 已落地案例（2026-11）

三张地图都采用同一流程：大纲 JSON → 无水印底图 → 本地 Pillow 中文渲染 → 合成 → 独立像素审查 → 报告；底图只在风格变化时重生成，改文案/间距只重跑渲染。

| 案例 | 结构 | 成品 | 项目目录（现位置） |
|---|---|---|---|
| 首版电工/PLC 地图 | 13 站 × 5 + 13 实战 | 5248×2944，3,842,294 B，11.4s，360 字符 | 已被 15 站版替代 |
| 电工装配 × PLC | 15 站 × 5 + 15 实战，5 阶段各 3 站，100h | 5248×2944，3,718,782 B | `out/superagent-electrical-plc-poster/` |
| 上位机 × 机器视觉 | 20 站 × 5 + 20 实战，5 阶段各 4 站，600h | 5248×2944，3,459,149 B | `out/superagent-upper-computer-vision-map/` |

实现过程与结果：

1. 两个项目均为 9 任务 DAG：T1 大纲、T2 API 规范、T3 版式、T3B 提示词、T4 渲染脚本、T5 底图、T6 合成、T7 独立审查、T8 报告；T1/T2/T3/T3B 首批并行。
2. 底图均由 `agnes-image-2.5-flash` 生成，4K 16:9；PLC 版底图复用一次，上位机版首次生成 18.7s、9,921,308 B；均无文字/水印。
3. 两张成图分别 3,718,782 B 与 3,459,149 B，独立审查 AC 全 PASS；上位机版首轮发现 U12/U15 内容重叠、PLCSIM 表述、页脚线 52px 缺口，修订后复审关闭。
4. 两个项目目录连同 `plan/work/assets/out/report` 整体放入会话 `out/`；最终 PNG/报告在会话 `out/` 另有平铺副本。

复盘：

- 初版 T5 曾读取未声明上游的 `prompt.txt`；现由 `validate` 拒绝，节点必须拆清“提示词/版式/底图”。
- RGBA 半透明直接绘制会让编号/标签“消失”，必须预混色。
- 只复制最终文件到 `out/` 不算“结果放 out”；用户要求的是项目目录整体进入。
- 移动目录后必须改报告里的绝对路径，否则再生成命令失效。
