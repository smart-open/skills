# 已验证办公场景库

本文件记录 2026-11 用 5 个日常办公场景跑通编排器的实测结果，可作为选型与计划模板参考。所有场景产物在 `out/superagent-office/`（运行时目录，不入库）。

> 视觉/图像类交付（海报、信息图、知识地图）不在本表，见 `references/visual-deliverables.md`；该手册包含 4K 中文知识地图的实测 DAG、视觉 AC 与踩坑记录。

> 这 5 个场景在「执行前人工确认门禁」加入前完成；复现时在 `validate` 之后、`next --claim` 之前，先按 `references/acceptance-playbook.md` 出确认包并 `approve`。下表指标不含确认环节，其余流程与当前版本一致。

## 1. 场景总览

| # | 场景 | 复杂度 | 任务/AC | DAG 形态 | 实测结果 |
|---|------|--------|---------|----------|----------|
| 1 | 会议纪要 → 行动项 + 跟进邮件 | 低 | 2 / 3 | 纯串行 T1→T2 | 2 轮，0 重试，0 重置 |
| 2 | 三份运营日志 → 周报 + 独立复核 | 中 | 5 / 3 | 3 路并行 → 合并 → 复核 | 5 轮，最大并行 3；复核 FAIL 触发 1 次重置 |

## 2. 场景拆解要点

### 低复杂度：单链双任务

- 行动项提取（表格：编号/事项/负责人/截止/优先级/来源）→ 跟进邮件（引用全部编号）。
- 验收用唯一 ID 前缀：`grep -c '^| A[1-5] '`，不用宽泛的“表格行数”。
- 适合验证最小闭环：validate → claim → done → status。

### 中复杂度：扇出 + 合并 + 复核

- 周报：3 份日摘要互不依赖，必须同批派发；合并任务读三份产物；复核任务独立读原始日志。
- 日摘要模板要固定（5 指标 / 2 亮点 / 1 风险），否则合并阶段字段不齐。
- 数值类汇总（订单月报）拆成“计算”和“独立复算”两条并行支路，分别用 Python 与 awk，避免同源错误。

### 高复杂度：分层依赖 + 交叉审查

- 合同审查把“制度合规”和“风险分级”拆开并行：合规只答是否符合，风险另评可能性/影响；两者结论再汇入谈判与报告。
- 项目启动包包含 5 份主文档，必须追加“一致性审查”任务，固定核对日期、预算、范围、角色、指标、风险映射、沟通覆盖、窗口期、合规。
- 一致性审查发现的缺口（如满意度指标未落到里程碑）应在启动前补入，而不是留到执行期。

## 3. 可复用模式

| 模式 | 适用 | 关键控制 |
|------|------|----------|
| 提取 → 成文 | 纪要、邮件、通知 | 成文任务只消费结构化产物，不重新读原始长文 |
| 扇出 → 合并 | 多日志、多来源周报 | 同一模板、同一指标口径、合并任务负责总数 |
| 计算 ∥ 审计 | 报表、结算、月报 | 两种实现独立复算，审计结论必须 PASS |
| 合规 ∥ 风险 | 合同、制度、招投标 | 合规与风险分表，避免“合规即无风险” |
| 多文档 + 一致性审查 | 项目启动包、方案包 | 审查任务有独立输出与 PASS/未解决计数 |

## 4. 本次实战暴露的问题

1. **宽前缀统计会串表**：合同报告的偏差表与谈判表都以 `| P` 开头，`grep '^| P[1-7]'` 会把谈判行一起计数。AC 验证必须限定章节或使用唯一编号前缀，复杂结构改用脚本断言。
2. **审查 FAIL 不是任务失败**：复核任务已产出结论时先置 done；再重开缺陷上游（done→pending），脚本自动重置其已完成下游（resets+1），修复后重跑复核。直接带 FAIL 汇总会破坏“无证据不交付”。
3. **brief 缺输出模板会导致返工**：并行 worker 必须拿到固定章节/表格列定义；只说“整理成摘要”会得到结构不一致的三份文件。
4. **多文档场景必须有一致性审查**：单独看每份文档都合格，跨文档的日期、角色、指标仍可能对不上。
5. **数值 AC 要能复算**：不要只断言“文件存在”；至少断言关键数字，并用独立实现再算一遍。

## 5. 复现建议

1. 按 `references/task-dag-spec.md` 建 plan，AC 的 `method` 写成可直接执行的命令或脚本断言；读取任何任务产物都要在 `deps` 中声明，`validate` 会检查输入来源。
2. 运行 `node scripts/superagent.mjs validate <plan>`，零错误后出人工确认包；`approve <plan> --note "..."` 通过门禁，再 `next --claim`。
3. `next --json` 已返回完整任务字段，可直接组装 worker brief（七要素）。
4. 每个任务完成前先跑自己的 AC；全流程结束后再逐条判 AC、做边界三查，最后写 report。
5. 改脚本后先跑 `node scripts/smoke.mjs`，再做场景回归。
