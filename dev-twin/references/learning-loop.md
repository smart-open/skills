# 学习闭环操作规程（仅复盘时加载）

## 一、语料记录格式（写入 corpus/raw-corpus.md 待复盘区）

```
### [序号] [日期] [任务类型]
- 场景：什么任务下被纠正
- 分身做法：当时的处理
- 用户纠正：正确做法
- 涉及画像层：coding / architecture / workflow / tools / core
```

## 二、复盘流程（语料≥10项触发，或用户主动发起）

1. **读语料**：Read `corpus/raw-corpus.md` 待复盘区全量
2. **预生成总结**：按涉及画像层分组 → 每条语料提炼为"候选画像条目"（可执行的规则表述），分类标注：
   - ✅ 个人风格（保留） / 🏆 最佳实践（遵循） / ⚠️ 历史包袱修正（避免）
   - 冲突条目标注冲突点，给出合并建议
3. **用户逐条确认**（AskUserQuestion 分批，每批≤4条）：采纳 / 修改后采纳 / 放弃
4. **入库**：
   - 采纳条目写入对应画像层（追加编号，保持原有编号连续）
   - 冲突条目合并改写原条目（不删除原编号，改写内容并标注修订日期）
   - 涉及执行标准的重大变更 → 同步写入 core 层决议表
5. **版本更新**：发生入库的画像层版本号 +0.1（如 v0.2→v0.3），头部日期更新；画像库 README 版本同步
6. **语料归档**：已复盘语料移入 `corpus/raw-corpus.md` 的"已归档复盘"区（保留原文，永不删除）

## 三、淘汰规则（每次复盘顺带执行）

- 统计画像条目引用情况：依据可获得的本轮任务决策留痕 + 用户印象，共同判断哪些条目长期未命中
- 连续3个月未被引用的条目 → 列入淘汰候选，向用户展示并说明理由
- 用户确认淘汰 → 移入该画像层文件底部"归档区"（不物理删除，保留恢复能力）；用户否决 → 保留，下次复盘再评估

## 四、纪律

- 未经用户确认，任何内容不得写入正式画像层
- 原始语料永不删除；画像层可从语料重建
- 复盘产出（候选条目总结）必须先展示给用户，再执行写入
