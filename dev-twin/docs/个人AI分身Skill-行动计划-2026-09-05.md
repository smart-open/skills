# 🛠️ 个人AI分身Skill行动计划
*制定日期：2026-09-05*

---

## 📅 一、分步实施计划

| 阶段 | ⏰ 时间 | 🎯 要达成什么 | ✅ 怎么算完成 | 👤 谁负责 |
|------|------|------------|------------|--------|
| 第一阶段：画像奠基 | 第1-3周 | 画像v0.1提炼 + 只读加载机制 + 代码分身能力 | 分身按画像写出用户"无需大改"的代码；画像按层加载、token可控 | 用户（提供素材、确认画像）+ AI（提炼、构建） |
| 第二阶段：思维分身 | 第4-6周 | 需求分析 + 系统/分布式架构设计能力 | 给定真实需求，分身产出用户简单review即通过的分析与设计文档 | 用户（提供案例、把关方向）+ AI |
| 第三阶段：进化闭环 | 第7-10周 | 纠错学习闭环 + 画像淘汰机制 + 决策分级 | 纠正→语料→复盘→入库闭环跑通；画像库容量受控；自主决策比例提升 | 用户（复盘确认）+ AI |
| 第四阶段：产品化 | 第11周起 | 画像可替换架构 + 他人画像接入 | 他人替换画像数据即可生成分身，个人私有数据隔离 | 用户（产品决策）+ AI |

> 💡 用户明确：三大核心能力（思考决策/写代码/自我迭代）缺一不可，但有先后——先"只写代码分身"+"只读画像"（只用不学），再需求分析与架构设计，最后自我学习迭代。

## 📋 二、具体行动清单

### 🚀 行动1：交付画像素材（阶段一起点）

- **🎯 目标**：提供画像提炼所需的全部原材料
- **👤 谁来做**：用户
- **⏰ 什么时候完成**：第1周初
- **💰 需要什么**：简历、个人开发经验文档、开发流程文档、代表性工程代码目录（10W+行中圈定精华模块）
- **✅ 怎么验证成功**：素材齐备，AI可开始分析；代码圈定范围明确（哪些模块最能代表个人最佳实践）
- **⚠️ 有什么风险**：个人经验文档零散不成体系 → 应对：允许口语化、碎片化提供，AI负责结构化
- **🔗 依赖什么**：无（起点任务）

### 🚀 行动2：定义画像分层结构与存储格式

- **🎯 目标**：确定画像库的目录结构、分层维度、文件格式，内置容量控制规则
- **👤 谁来做**：AI设计 → 用户确认
- **⏰ 什么时候完成**：第1周
- **💰 需要什么**：对四类画像层的定义（编码习惯/架构偏好/决策原则/工作方法）
- **✅ 怎么验证成功**：结构文档产出，用户确认分层合理；每层预设容量上限与淘汰标记字段
- **⚠️ 有什么风险**：分层不合理导致后期频繁重构 → 应对：参考"角色/类别"维度划分，预留扩展层
- **🔗 依赖什么**：行动1（素材到位后可校准分层）

### 🚀 行动3：提炼画像v0.1

- **🎯 目标**：从简历+个人经验起步（最易结构化、最代表思考方式），AI辅助提炼决策原则、编码习惯、架构偏好
- **👤 谁来做**：AI提炼 → 用户逐条确认
- **⏰ 什么时候完成**：第1-2周
- **💰 需要什么**：行动1素材；双重校准策略（个人风格×业界最佳实践择优融合）
- **✅ 怎么验证成功**：画像v0.1产出（含：决策原则清单、编码习惯清单、架构偏好清单），每条用户已确认
- **⚠️ 有什么风险**：提炼失真——把项目历史包袱当作个人最佳实践 → 应对：AI提炼时标注"个人风格/最佳实践/疑似历史包袱"三类，疑似项与用户讨论定夺
- **🔗 依赖什么**：行动1、行动2

### 🚀 行动4：构建只读画像加载机制（决策引擎雏形）

- **🎯 目标**：实现"任务触发角色 → 按需加载对应画像层"的机制，token可控
- **👤 谁来做**：AI构建 → 用户验证
- **⏰ 什么时候完成**：第2周
- **💰 需要什么**：画像库结构（行动2）；任务-画像层映射规则
- **✅ 怎么验证成功**：单次任务只加载所需画像层；对比测试token消耗显著低于全量加载方案
- **⚠️ 有什么风险**：映射规则遗漏导致该加载的画像层未加载 → 应对：建立映射清单并持续补全；分身发现画像缺失时主动提示
- **🔗 依赖什么**：行动2、行动3

### 🚀 行动5：代码分身端到端验证

- **🎯 目标**：选定一个真实小项目，让分身按画像完成设计→编码→测试→自查的完整流程
- **👤 谁来做**：AI执行 → 用户review
- **⏰ 什么时候完成**：第3周
- **💰 需要什么**：真实小项目需求；画像v0.1；只读加载机制
- **✅ 怎么验证成功**：产出的代码用户无需大改即可使用；代码可读可维护；每个决策可追溯（引用了画像哪条原则）
- **⚠️ 有什么风险**：小项目验证通过不代表大工程不跑偏 → 应对：预留"工程规模爬坡测试"，逐步扩大项目规模观察表现
- **🔗 依赖什么**：行动3、行动4

### 🚀 行动6：需求分析与架构设计能力构建

- **🎯 目标**：分身能按画像完成需求分析、系统架构设计、分布式系统设计
- **👤 谁来做**：AI构建 → 用户提供历史案例校准
- **⏰ 什么时候完成**：第4-6周
- **💰 需要什么**：用户过往的需求分析/架构设计产出（作为画像校准素材）；架构决策原则画像层
- **✅ 怎么验证成功**：给定真实需求，分身产出的分析与设计文档用户简单review即通过
- **⚠️ 有什么风险**：用户预判此环节最可能先失望（需求理解/架构设计）→ 应对：从结果反推问题环境；设计文档每步标注决策依据，便于定位偏差源头
- **🔗 依赖什么**：行动5（代码分身验证通过后启动）

### 🚀 行动7：学习闭环构建

- **🎯 目标**：实现"用户纠正 → 自动写入原始语料库 → 累计10项以上 → 提醒复盘 → 用户确认后写入画像库"的完整闭环
- **👤 谁来做**：AI构建 → 用户执行复盘纪律
- **⏰ 什么时候完成**：第7-8周
- **💰 需要什么**：原始语料库结构；复盘提醒机制；确认入库流程
- **✅ 怎么验证成功**：一轮完整闭环跑通：纠正→语料→复盘→确认→入库→下次任务体现学习效果
- **⚠️ 有什么风险**：复盘流于形式 → 应对：复盘提醒绑定语料数量阈值（10项），AI在复盘时预生成结构化总结供用户确认，降低用户负担
- **🔗 依赖什么**：行动5、行动6（在使用中产生纠正语料）

### 🚀 行动8：画像淘汰与进化机制

- **🎯 目标**：画像库容量控制——过时经验归档、冲突原则合并、低频画像降权
- **👤 谁来做**：AI设计规则 → 用户确认执行
- **⏰ 什么时候完成**：第9-10周
- **💰 需要什么**：画像使用统计（哪些原则被引用、哪些从未命中）；淘汰规则
- **✅ 怎么验证成功**：画像库经过一轮淘汰后容量受控、质量提升；被淘汰项可追溯（归档不删除）
- **⚠️ 有什么风险**：误淘汰仍有效的经验 → 应对：淘汰先归档后删除，保留恢复能力
- **🔗 依赖什么**：行动7（学习闭环运行一段时间，积累使用数据）

### 🚀 行动9：画像可替换产品化

- **🎯 目标**：画像数据与skill引擎彻底分离，他人替换画像数据即可生成自己的分身
- **👤 谁来做**：AI实施 → 用户产品决策
- **⏰ 什么时候完成**：第11周起
- **💰 需要什么**：画像模板化（空白画像模板 + 素材提炼流程）；私有数据隔离
- **✅ 怎么验证成功**：用第二个人的素材跑一遍提炼流程，成功生成其个人分身，且与用户画像数据完全隔离
- **⚠️ 有什么风险**：过早产品化分散精力 → 应对：以用户自己的分身成熟度为准，画像覆盖达到80%目标前不对外推广
- **🔗 依赖什么**：行动1-8全部完成

## 🏆 三、成功的标准

### 📊 数字指标

- **画像覆盖度**：达到用户完整画像的80%（用户评估）
- **自主决策比例**：随阶段推进持续提升（阶段三起按月统计：自主决策数/总决策数）
- **复盘节奏**：每积累10项纠正语料完成一次复盘入库
- **token效率**：按需加载模式下的token消耗 ≤ 全量加载方案的30%
- **返工率**：分身产出的代码/文档，用户大改（重写>30%）的比例逐月下降

### 💎 质量标准

- **代码质量**：可读、可维护，符合个人编码风格，达生产级
- **系统质量**：满足性能、可扩展性、鲁棒性要求
- **决策质量**：100%决策可追溯（每个决策可定位到画像依据或用户确认记录）
- **画像质量**：入库内容100%经用户确认；定期淘汰，库容受控

### ⏱️ 时间标准

- **阶段一**：第1-3周完成画像v0.1 + 代码分身验证
- **阶段二**：第4-6周完成需求分析/架构设计能力
- **阶段三**：第7-10周完成学习闭环 + 淘汰机制
- **里程碑**：每阶段结束进行一次阶段评审，通过后进入下一阶段

## 🛡️ 五、风险应对

### 🔥 高风险怎么办

1. **画像膨胀导致token失控/跑偏**
   → 行动2内置容量上限字段；行动8建立淘汰机制；按角色/类别分层 + 按需加载双保险；被淘汰项归档可恢复

2. **提炼失真（历史包袱≠最佳实践）**
   → 行动3采用"个人风格/最佳实践/疑似历史包袱"三分类标注；AI结合外部优秀经验择优筛选；保留个人编码风格；疑似项与用户讨论定夺

3. **需求理解/架构设计不达预期（用户预判最先失望的环节）**
   → 行动6设计文档每步标注决策依据，从结果反推定位偏差源头；用用户历史设计产出校准；不过关则回退补画像，不硬推进

### ⚠️ 中风险怎么监控

1. **隐性知识无法结构化**
   → 监控：画像提炼时统计"说不清"的比例；预案：说不清的交用户决策，与AI讨论后共同生成，讨论结果本身成为新的结构化画像素材

2. **小项目验证通过但大工程跑偏**
   → 监控：行动5后安排工程规模爬坡测试，逐步扩大规模观察；预案：画像分层加载在大型工程下补充"工程结构画像层"（模块组织、依赖管理习惯）

3. **复盘纪律难以坚持**
   → 监控：语料库积压量（超过20项未复盘即预警）；预案：AI预生成结构化复盘总结，用户只做确认，把复盘成本降到最低

### 🚨 出问题了怎么办

- **📢 问题定位**：所有决策留痕 → 先查该决策引用的画像条目 → 判断是画像错（修正画像）还是执行错（修正流程）
- **🎯 决策机制**：画像库的重大变更（大规模淘汰、分层重构）由用户拍板；日常入库由复盘确认流程把关
- **🔧 应急回退**：画像库每次变更留版本记录；分身行为异常时可回退到上一个画像版本；原始语料库永不删除，画像可随时重建
