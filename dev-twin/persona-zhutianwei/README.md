# 📖 画像库说明（Persona Library）

*画像主体：朱天伟 | 版本：v0.13 | 建库日期：2026-09-05*

## 🎯 设计原则

1. **分层沉淀**：画像按角色/类别分文件存放，每个文件聚焦一类画像
2. **按需加载**：任务只触发加载所需的画像层，严格控制token消耗
3. **可替换**：本画像库是私有数据，与skill引擎分离。他人替换本目录即可生成自己的分身
4. **HITL进化**：纠正语料进入 `corpus/`，累计10项经用户复盘确认后才写入对应画像层

## 📂 结构与加载策略

| 文件 | 必需性 | 内容 | 触发加载的任务类型 |
|------|--------|------|------------------|
| `profile-core.md` | **必需** | 基础画像 + 领域专长 + 决策原则 + 决策行为模式 | **所有任务必加载** |
| `profile-coding.md` | 可选 | 编码习惯 + 测试规范 + 包袱清单 | 编码、改代码、调试、代码审查任务 |
| `profile-architecture.md` | 可选 | 架构偏好 + 组件设计哲学 + 系统/分布式设计 + ADR决策留痕（三条件门槛+备选空间广度+改进审查交互纪律） + 契约先行 + 架构红线 | 系统设计、架构、分布式设计、组件开发、对外文档任务 |
| `profile-workflow.md` | 可选 | 9步开发流程（含测试节奏） + 交互与合并纪律（理解失败即澄清/merge冲突） + 需求分析方法论（七维拷问+术语锐化+AC规范+假设清单提请+事实与约束分离+产出物模板含实现决策与测试接缝） + 九大类审查清单（含热点聚焦）+ **黑盒审查机制**（子代理信息隔离审查） + 文档机械自查五查 + 调试六纪律 + 提交规范 | 需求分析、需求澄清、任务推进、审查任务 |
| `profile-tools.md` | 可选 | 技术栈 + AI方法论（含Agent文档写作纪律） + skill组合策略（**主动应用纪律+动态发现+自动安装**） | 选型、环境搭建、工具决策任务 |

> 引擎约定：`profile-core.md` 是画像库的唯一必需项；其他层缺失时引擎正常工作，仅提示该层缺失。画像内容冲突时优先级：core决策原则(D编号) > 分层条目（标注"决议"的条目优先于普通条目）。决议历史不单独留存——入库条目即本体，演进历史见 dev-twin README 版本表。

## 🔄 进化机制

```
用户纠正分身 → 语料追加到 corpus/raw-corpus.md
→ 累计 ≥10 项 → 提醒用户复盘
→ AI预生成结构化总结 → 用户逐条确认
→ 写入对应画像层文件（标注版本与日期）→ 语料移入归档区（不物理删除，画像可随时从语料重建）
```

进阶：完整案例结束后可做**案例反向校准**（对照画像规则核对案例实际行为→正例确认+偏差定位→用户逐条确认入库→复盘编号归档）。

淘汰规则：复盘时按三问评估画像条目——**no-op 测试**（该条目是否改变行为，还是与默认行为无异）/ **引用频率**（连续3个月未被任何决策引用）/ **沉积检查**（是否已随环境变化过期）——命中者提议归档（移入文件底部"归档区"，不物理删除）。
