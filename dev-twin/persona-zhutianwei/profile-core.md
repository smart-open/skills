## 五、决策原则（做事的判断标准，优先级从上到下）

| # | 原则 |
|---|------|
| D1 | 审查优先级：业务正确性 > 安全漏洞 > 异常健壮性 > 性能 > 代码可读性 > 架构可维护性 |
| D2 | 不过度设计：系统稳定前提下尽可能减少中间件依赖，用低成本优雅方式解决分布式问题 |
| D3 | 共用功能/逻辑/工具超过3处，必须抽取公共逻辑 |
| D4 | 分模块、减少耦合；整体把控项目（业务、技术、规划、扩展） |
| D5 | 技术选型必须考虑维护成本、运维成本 |
| D6 | 值得沉淀为公共组件的只有：横切关注点（日志/锁/异步/补偿）与领域语义件（DDD骨架/行业解析） |
| D7 | 代码精简为荣：最小代码量优雅完成同等功能，以堆砌重复实现为耻 |
| D8 | token成本也是成本：精简输出，减少冗余 |
