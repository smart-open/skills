# 龙虎榜 T+3 涨停推荐与自进化模型（a-stock-lhb-rec）

> 把「龙虎榜上榜个股 → 后期（T+1~T+3）仍有涨停冲高」做成可复用的概率模型。
> 每天收盘后自动出候选；每天用「昨日推荐 vs 今日实际涨停」验证，并把新实际结果喂回训练，
> 模型版本随时间外 AUC 不劣则 +1，**越用越准**。

## 能力说明

- **盘后推荐**：每个交易日 17:00 后，拉取当日龙虎榜，用当前模型对全部上榜股输出 `P(T+3涨停)` 并排序，给出「纳入观察」候选（满足 主线+连板+净买比+优质买方+未过度透支）。
- **低位连板聚焦（执行层）**：在全量 Top20 之上再叠一层过滤 —— 剔除**高度板（≥3板）**与今日未涨停上榜，只留「刚刚 1-2 板」，按综合分给 **Top5**。全量 Top20 保留供自学习/回测，聚焦清单供人执行（`daily` 自动产出）。
- **三维归因**：个股技术 × 席位手法 × 行情研判，可解释（逻辑回归评分卡）。
- **席位画像**：自动构建游资席位画像（打板/低吸/接力风格、EB 收缩综评、样本可信度），含紫阳东路专项解读。
- **自我进化**：`optimize` 补最新实际结果 → 重训 → 时间外 AUC 不劣于当前则版本 +1，轨迹写入 `model_history.json`；`verify` 逐日核对推荐命中率。
- **模型择优（LR vs GBDT）**：训练时在**同一时间外测试集**上比较逻辑回归与梯度提升树，GBDT 明显更优且样本充足（≥300）时自动采用 GBDT 作生产模型，否则回落 LR（稀疏样本下 LR 更稳），模型类型记入 `model_kind`。
- **暴雷一票否决**：推荐输出阶段对 ST/退市/立案调查/违规处罚/业绩预亏等风险股强制剔除（即使模型概率高也不纳入观察候选）。
- **Markdown 报告**：方法论 / 赢家共性 / 席位手法 / 评估 / 评分卡 / 实战验证 / 进化轨迹 / 买入策略（带日期，落 `<cwd>` 根目录）。

## 何时使用

- 用户说「龙虎榜推荐 / 盘后选龙虎榜 / T+3 涨停预测 / 游资后期涨停 / 上榜后还能涨的票」
- 用户说「每天收盘后给我龙虎榜候选 / 5点后龙虎榜」→ 跑 `daily`
- 用户说「优化模型 / 让模型更准 / 模型迭代」→ 跑 `optimize`
- 用户说「某席位手法 / 紫阳东路怎么样」→ 看席位画像章节
- 定时自动化（可选）：每个交易日 17:00 后触发 `daily`；该命令**自身已内嵌「生成报告后自动自我学习」**，无需另行配置 cron 任务

## 第一步：首次全量构建（仅一次）

```bash
py scripts/run.py init
```
- 拉取近 90 天龙虎榜（board / 买卖席位 / 同花顺题材 / 全量日 K线，约 10~15 分钟，增量可断点续跑）
- 构建席位画像 → 特征集 → 训练首版模型（v1）→ 生成当日推荐 → 生成报告
- 产物：`a-stock-lhb-rec/data/*` + `a-stock-lhb-rec/model/model_t3.joblib` + `a-stock-lhb-rec/model_history.json` + `龙虎榜T+3涨停推荐模型报告-*.md`（报告落 `<cwd>` 根目录）

## 第二步：每日盘后主流程（核心，可自动化）

```bash
py scripts/run.py daily            # 默认=最近已发布交易日(今天需≥17:00)
py scripts/run.py daily 2026-08-28 # 指定日
```
`daily` 依次执行：
1. `pipeline.fetch_latest()` —— 增量抓取当日龙虎榜（board/seats/hot/kline，跳过已有）
2. `recommend` —— 对当日全部上榜股打分，输出 Top20 候选 + `recommend_{日期}.csv`
3. `verify` —— 核对前 4~10 个交易日（T+3 已完全结算）的推荐实际 T+1/T+2/T+3 涨停，追加 `verify_history.csv`
4. `report` —— 刷新 Markdown 报告（含最新进化轨迹与验证记录）
5. `optimize`（**自动**）—— 生成报告后自动自我学习：把最新实际结果补入训练集、重训、版本决策（时间外 AUC 不劣则 +1），无需额外定时任务

> **5 点以后逻辑**：`pipeline.board_ready_day()` 在 17:00 前返回上一交易日、17:00 后返回当日，确保龙虎榜数据已发布。

## 第三步：按需子命令

```bash
py scripts/run.py recommend 2026-08-28   # 单日推荐(不抓数据, 用缓存)
py scripts/run.py verify 2026-08-28      # 验证某日推荐命中(需 T+1..T+3 已可得)
py scripts/run.py focus 2026-09-15 5     # 低位连板聚焦: 剔除高度板, 1-2板综合分 TopN(缺省5)
py scripts/run.py optimize               # 手动触发自我进化重训
py scripts/run.py report                 # 重新生成报告(生成后自动触发自我学习)
py scripts/run.py train                   # 仅重训(不抓数据)
```

## 低位连板聚焦（1-2 板，执行层）

> 全量 Top20 用于**自学习/回测**足够，但给人看太多。`focus` 在其上再叠一层可执行过滤：
> 剔除**高度板（≥3 板）**与**今日未涨停上榜**，只留「刚刚 1-2 板」，按综合分给 TopN（缺省 5）。
> `daily` 已内嵌该步骤，每天自动产出 `低位连板聚焦-{日期}.md`，无需单独调用。

**综合分口径**（各分量归一化到 0~1，可解释）：
`0.40×P + 0.20×净买比 + 0.18×质量(主线/游资) + 0.12×换手健康 + 0.10×位置 − 透支惩罚 − 纯机构主买惩罚`

- 换手健康：2%~16% 理想；`<2%` 缩量惜售略扣；`>16%` 递减，`>25%` 加速扣分。
- 惩罚：前3日透支 ≥35% 扣 0.25、25~35% 扣 0.12；纯机构主买 扣 0.18。
- 连板高度由 K 线**逐日向前真实判定**（非 `CONSEC_ZT` 的「近3日涨停天数」上限3 口径），可区分 1 板 / 2 板 / ≥3 板。

## 自进化机制（为什么越来越准）

> `daily` / `init` / `report` 每次生成报告后都会**自动**运行 `optimize` 完成自我学习（记录当日数据 → 重训 → 版本决策），全程无需手动或额外 cron 定时任务。

- **数据闭环**：每个交易日 `daily` 抓取的新龙虎榜，其 T+1/T+2/T+3 实际涨幅随 K 线延伸而「解冻」为标签；`optimize` 把这些真实结果并入训练集，模型持续吸收近期行情特征。
- **版本门控（同集可比）**：`train` 用按日期 80/20 的时间外切分（测试集均为已可知标签的前瞻样本，杜绝未来泄漏）；并在【同一个时间外测试集】上同时评估新旧模型 AUC，新模型不劣于当前（-1% 容差）才接受并版本 +1，否则保留旧模型。避免旧版「不同测试集 AUC 直接比」导致的退化误判。
- **防未来泄漏（因果特征）**：`causal.py` 保证席位质量分与题材主线仅用「截至样本日期」已可观测信息——席位 T+5 表现只计入已结算(结算日≤样本日)的记录，主线题材 TopK 只用该日前的热榜累计；榜单标签统一由 K 线收盘价按板块阈值计算，与 `verify` 完全同口径。
- **正则化稳健**：训练集内部分层 5 折 CV 自动选 `C`（不用测试集选超参），并对样本量/正例数过少给出提示。
- **轨迹可查**：`a-stock-lhb-rec/model_history.json` 记录每版样本量/时间外 AUC/同集旧模型 AUC/Top20 命中/决策；报告第七章展示进化轨迹与逐日验证命中率。
- **局限**：因果化后 AUC 更真实（不会虚高）；但弱势市（涨停情绪<10%）模型仍失效，应停用；样本量有限，建议每个交易日跑 `daily` 保持新鲜。

## 买入策略（推荐输出口径）

- **主口径**：TopN 概率排序（含 P 值）＋当日市场强弱门控。「纳入观察」仅辅助标注（`P≥30%` 且 `前3日透支<38%` 且 非纯机构主买），不再用「主线+净买比≥0.55」等硬门槛筛掉高 P 股票（90 日 PIT 回溯证明该框命中 27.3% 低于纯 Top20 的 31.2%）。
- **回避**：纯机构主买 / 前3日透支≥38% / 高位连板≥5 / 科创创业涨停上榜（已充分定价）。
- **风控**：T+1 不涨停即减仓，跌破上榜日收盘止损；弱市（当日上榜涨停占比处于历史低分位）自动降级并提示勿追高。

## 变更日志

- **v1.4.1（2026-09-24）· fetch_hot 增加重试与缺失告警**
  - 背景：2026-09-23 的 daily 运行时，题材接口 `zx.10jqka.com.cn` 遭遇一次瞬时网络拦截（空响应 → `Expecting value: line 1 column 1`），`fetch_hot` 仅打印一行 ERR 便静默跳过，导致该日 `hot_2026-09-23.json` 缺失，**当日 Top20 的「主线」标记全为空**（题材维度特征丢失，P 值也随之偏移）。
  - 修复：`fetch_hot` 对每个缺失日期**重试 3 次**（退避 1.5/3/4.5 秒），全部失败才记入 `missed` 并打印**醒目告警**（提示「主线维度将缺失，重跑 daily 会自动补抓」）。
  - 自愈特性说明：因 `fetch_hot` 以「文件是否存在」为判据，重跑 `daily`（或 `recommend`→`focus`→`report`）即自动补齐缺失题材并修正标记，无需手工删缓存。
  - 当日处置：补抓 `hot_2026-09-23.json`（14.8KB）后重跑三件套，主线标记恢复（新华传媒 85.3%、华丽家族 79.8%、南威软件 75.7% 等），低位聚焦 Top5 重排为 胜利精密/雪龙集团/三峡新材/澳弘电子/浩欧博。

  - 新增 `scripts/focus.py` + `run.py focus [DATE] [N]`：硬剔除 **≥3 板高度板** 与 **今日未涨停上榜**，只留 1-2 板，按综合分给 TopN（缺省 5）。
  - 综合分：`0.40×P + 0.20×净买比 + 0.18×质量(主线/游资) + 0.12×换手健康 + 0.10×位置 − 透支惩罚 − 纯机构主买惩罚`。
  - 连板高度改用 K 线**逐日向前真实判定**（`consec_boards`），修正 `CONSEC_ZT`「近3日涨停天数、上限3」无法区分 1 板/2 板的局限。
  - `daily`/`init` 已内嵌该步骤，自动产出 `低位连板聚焦-{日期}.md`；全量 Top20 照常保留供自学习。
- **v1.3.3（2026-09-10）· 修复 daily 回溯窗口对同一交易日的重复验证**
  - 缺陷：`cmd_daily` 按自然日回退 4~10 天且跳过周末，同一批次会被多个 back 值回退到同一天（如 9-10 跑批时 9-04 批次被重复验证 3 次）。数据无损（按 date 去重覆盖）但浪费计算与日志冗余。
