# A股市场操盘手技能

本技能为A股市场提供两大核心能力：**个股六维诊断分析**和**市场资讯与选股推荐**。适用于短线博弈与长线价投，帮助系统性避开雷区、捕捉机会。

## 产物落点（必须遵守）

生成的 **Markdown 报告（带日期）**一律写入**当前会话/工程的工作目录根**，绝不可写进本技能安装目录（`os.path.dirname(os.path.abspath(__file__))` 所在的技能目录，或任何技能库目录）。
- 落点优先级：用户显式指定的工程目录 > 当前工作目录（会话 cwd）。可先 `os.getcwd()` 确认当前目录再落盘。
- 若当前工作目录恰好是技能安装目录，则应把报告写入其父级工程目录或用户在对话中指定的股票报告工程目录。
- 报告文件名需自描述，如 `{股票名}_个股诊断_{YYYYMMDD}.md` / `行情复盘_{YYYYMMDD}.md`。
- **报告统一为原生 Markdown 文档**（带日期），不使用 HTML 可视化；数据/过程产物（如有）放到当前会话工程下的 `a-stock-operator/` 子目录。

## 输出模式判断（必须先判断再执行）

**根据用户输入意图，判断输出模式，禁止无脑输出两份报告：**

| 模式 | 触发条件 | 输出内容 | 不输出 |
|:---:|:---|:---|:---|
| **模式A：仅个股诊断** | 用户提及个股名称/代码+成本价，或明确要求"诊断/分析某只股票" | 个股六维诊断报告（1份 Markdown） | 市场报告、涨停选股、板块分析 |
| **模式B：仅行情分析** | 用户要求"行情分析/市场资讯/今日涨停/选股推荐/首板/突破"等，未提及具体个股 | 市场资讯与选股报告（1份 Markdown） | 个股诊断报告 |
| **模式C：两者都要** | 用户既提及个股诊断，又要求行情/市场分析 | 个股诊断报告 + 市场报告（2份 Markdown） | 无 |

### 判断规则
1. **关键词检测**：
   - 个股诊断关键词：股票代码（6位数字）、股票名称、"诊断""分析这只股""成本价""盈亏""止损""加仓"
   - 行情分析关键词："今日行情""市场资讯""涨停""首板""突破""选股""板块""龙虎榜""大盘"
2. **优先级**：如果用户输入同时包含两类关键词→模式C；仅含个股类→模式A；仅含行情类→模式B
3. **默认行为**：无法判断时询问用户需要哪种报告，而非默认输出两份

## 板块范围规则（选股默认排除创业板/科创板）

**默认行为：选股推荐仅覆盖主板股票，排除创业板和科创板。用户可显式覆盖此规则。**

| 配置项 | 默认值 | 用户覆盖方式 | 生效范围 |
|:---:|:---|:---|:---|
| **创业板（300/301）** | ❌ 排除 | 用户输入含"包含创业板""含创业板""加上创业板""创业板也要"等明确表述 → ✅ 包含 | 仅市场报告的选股推荐（输出二、输出三） |
| **科创板（688）** | ❌ 排除 | 用户输入含"包含科创板""含科创板""加上科创板""科创板也要"等明确表述 → ✅ 包含 | 仅市场报告的选股推荐（输出二、输出三） |

### 规则细节
1. **仅影响选股推荐**：本规则仅作用于市场报告中的「首板低位突破」和「突破放量热点」选股环节，不影响个股诊断（模式A）——用户指定诊断的个股无论是哪个板块都正常分析
2. **ST/*ST永远排除**：无论用户是否要求包含创业板/科创板，ST/*ST股票始终排除，不可覆盖
3. **判断优先级**：用户明确说"包含创业板/科创板" → 包含；用户未提及 → 排除；用户说"只要主板" → 排除（强化默认）
4. **报告标注**：报告须标注当前板块范围，如"本次选股范围：沪市主板+深市主板（默认排除创业板/科创板）"或"本次选股范围：沪市主板+深市主板+创业板（用户指定包含）"
5. **API参数联动**：
   - 默认（仅主板）：`fs=m:0+t:6,m:1+t:2`（深市主板+沪市A股）
   - 包含创业板：追加 `m:0+t:80`
   - 包含科创板：追加 `m:1+t:23`
   - 包含全部：`fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23`

### MCP工具（实时行情数据源——必须使用）

通过 `integrated_code_mode` MCP的Exec工具调用Shell/WebFetch/browser等子工具，直接从东方财富API获取实时数据。**生成报告前必须先通过MCP获取实时数据，禁止仅凭搜索结果编造数据。**

#### MCP调用方式
```
run_mcp → server_name: "integrated_code_mode" → tool_name: "Exec"
```
在Exec的code中通过 `await tools.Shell({command: "Invoke-RestMethod -Uri '...' "})` 调用东方财富API。

#### 核心API端点

**1. 实时行情（个股）**
```
http://push2.eastmoney.com/api/qt/stock/get?secid={市场代码}.{股票代码}&fields=f43,f44,f45,f46,f47,f48,f50,f57,f58,f60,f116,f117,f162,f167,f168,f169,f170,f171,f292&ut=fa5fd1943c7b386f172d6893dbbd1d0c
```
- 市场代码：沪市=1，深市=0（如火炬电子：secid=1.603678）
- 字段含义：f43=最新价 f44=最高 f45=最低 f46=开盘 f47=成交量(手) f48=成交额 f50=量比 f57=代码 f58=名称 f60=昨收 f116=总市值 f117=流通市值 f162=PE(动态) f167=PB f169=涨跌额 f170=涨跌幅 f171=振幅
- **注意**：价格类字段需除以100（如f43=4012表示40.12元），PE/PB也需除以100

**2. 日K线历史**
```
http://push2his.eastmoney.com/api/qt/stock/kline/get?secid={市场代码}.{股票代码}&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61&klt=101&fqt=1&beg={开始日期}&end={结束日期}&ut=fa5fd1943c7b386f172d6893dbbd1d0c
```
- klt=101(日K)/102(周K)/103(月K)，fqt=0(不复权)/1(前复权)/2(后复权)
- **技术分析必须使用fqt=1（前复权）**，否则除权除息日会出现虚假缺口导致均线失真；仅在查看真实成交价格时用fqt=0
- 返回klines数组，每行格式：日期,开盘,收盘,最高,最低,成交量(手),成交额,振幅%,涨跌幅%,涨跌额,换手率%
- **数据完整性验证**：返回klines.length应与请求交易日天数接近（差异>3天需排查停牌或参数错误）；最后一行日期应为最近交易日

**3. 资金流向**
```
http://push2.eastmoney.com/api/qt/stock/fflow/daykline/get?secid={市场代码}.{股票代码}&fields1=f1,f2,f3,f7&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61,f62,f63,f64,f65&lmt={天数}&klt=101&ut=fa5fd1943c7b386f172d6893dbbd1d0c
```
- 返回klines数组：日期,主力净流入,小单净流入,中单净流入,大单净流入,超大单净流入,...
- **已知问题**：lmt参数在某些股票上可能只返回1天数据（如近期有大涨大跌或停牌的股票），需验证返回天数，不足时改用K线接口辅助推算
- **资金流平衡验证**：主力净流入 + 小单净流入 + 中单净流入 ≈ 0（三者之和应接近0，差异>1%说明数据异常）
- **主力净流入验证**：主力净流入 = 超大单净流入 + 大单净流入（两者之和应等于主力净流入）

**4. 财务指标**
```
https://emweb.securities.eastmoney.com/PC_HSF10/NewFinanceAnalysis/ZYZBAjaxNew?type=0&code={SH/SZ+股票代码}
```
- 返回最近6期财务数据：每股收益(EPSJB)、每股净资产(BPS)、营收(TOTALOPERATEREVE)、净利(PARENTNETPROFIT)、毛利率(XSMLL)、ROE(ROEJQ)、资产负债率(ZCFZL)、经营现金流(MGJYXJJE)等

**5. 公司概况**
```
https://emweb.securities.eastmoney.com/PC_HSF10/CompanySurvey/PageAjax?code={SH/SZ+股票代码}
```
- 返回公司基本信息：总股本、行业分类、高管、主营业务等

**6. 大盘指数实时行情**
```
http://push2.eastmoney.com/api/qt/stock/get?secid={市场代码}.{指数代码}&fields=f43,f44,f45,f46,f47,f48,f57,f58,f60,f170&ut=fa5fd1943c7b386f172d6893dbbd1d0c
```
- 常用指数secid：`1.000001`(上证指数)、`0.399001`(深证成指)、`0.399006`(创业板指)、`1.000300`(沪深300)、`1.000688`(科创50)
- f43=最新价(需除以100，如380469=3804.69点)、f170=涨跌幅(需除以100，如-62=-0.62%)

**7. 涨停股列表（全市场涨停池）**
```
https://push2ex.eastmoney.com/getTopicZTPool?ut=7eea3edcaed734bea9cbfc24409ed989&dpt=wz.ztzt&Pageindex=0&Pagesize=500&sort=fbt:asc&date={YYYYMMDD}
```
- 返回data.pool数组：c=代码、n=名称、fund=封板资金、fbt=首次封板时间、lbt=最后封板时间、zbc=炸板次数、lbc=连板数、hybk=所属行业
- 同类端点：`getTopicZBPool`(炸板池)、`getTopicDTPool`(跌停池)、`getTopicJSPool`(强势股池)

**8. 板块涨跌排行（行业/概念板块）**
```
# 行业板块排行
https://push2.eastmoney.com/api/qt/clist/get?fid=f3&po=1&pz=50&pn=1&np=1&fltt=2&invt=2&ut=8dec03ba335b81bf4ebdf7b29ec27d15&fs=m:90+t:2&fields=f12,f14,f2,f3,f62,f184
# 概念板块排行（fs=m:90+t:3）
```
- f12=板块代码、f14=板块名称、f2=最新价、f3=涨跌幅、f62=主力净流入、f184=主力净流入占比
- 板块成分股：将fs改为`b:{板块代码}`（如`b:BK0729`）

**9. 全市场条件选股（按涨幅/成交额等排序筛选）**
```
https://push2.eastmoney.com/api/qt/clist/get?fid=f3&po=1&pz=50&pn=1&np=1&fltt=2&invt=2&ut=bd1d9ddb04089700cf9c27f6f7426281&fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23&fields=f12,f14,f2,f3,f4,f5,f6,f7,f8,f15,f16,f17,f18,f20,f21,f23,f100,f115
```
- fs市场范围：`m:0+t:6`=深市主板、`m:0+t:80`=创业板、`m:1+t:2`=沪市A股、`m:1+t:23`=科创板
- fid排序字段：f3=涨跌幅、f6=成交额、f7=振幅、f8=换手率
- fields关键字段：f12=代码、f14=名称、f2=最新价、f3=涨跌幅、f6=成交额、f8=换手率、f15=最高、f16=最低、f17=今开、f18=昨收、f20=总市值、f21=流通市值、f23=市净率、f100=所属板块、f115=PE
- **注意**：东方财富原生clist不支持复合数值条件（如"涨幅5%-7%"），需取回数据后在代码中二次过滤

#### MCP完整调用代码模板（含数据验证）
```javascript
// 在integrated_code_mode的Exec中执行
// 1. 并行获取个股全量数据
const secid = '1.603678'; // 沪市=1, 深市=0
const results = await Promise.all([
  // 实时行情
  tools.Shell({ command: "(Invoke-RestMethod -Uri 'http://push2.eastmoney.com/api/qt/stock/get?secid=" + secid + "&fields=f43,f44,f45,f46,f47,f48,f50,f57,f58,f60,f116,f117,f162,f167,f168,f169,f170,f171,f292&ut=fa5fd1943c7b386f172d6893dbbd1d0c') | ConvertTo-Json -Depth 5 -Compress" }),
  // 日K线（近60日，前复权fqt=1）
  tools.Shell({ command: "(Invoke-RestMethod -Uri 'http://push2his.eastmoney.com/api/qt/stock/kline/get?secid=" + secid + "&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61&klt=101&fqt=1&beg=20260601&end=20260730&ut=fa5fd1943c7b386f172d6893dbbd1d0c') | ConvertTo-Json -Depth 5 -Compress" }),
  // 资金流向（近5日）
  tools.Shell({ command: "(Invoke-RestMethod -Uri 'http://push2.eastmoney.com/api/qt/stock/fflow/daykline/get?secid=" + secid + "&fields1=f1,f2,f3,f7&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61,f62,f63,f64,f65&lmt=5&klt=101&ut=fa5fd1943c7b386f172d6893dbbd1d0c') | ConvertTo-Json -Depth 5 -Compress" }),
  // 财务指标
  tools.WebFetch({ url: 'https://emweb.securities.eastmoney.com/PC_HSF10/NewFinanceAnalysis/ZYZBAjaxNew?type=0&code=SH603678' })
]);

// 2. 解析数据（含异常检测）
const quote = JSON.parse(results[0].stdout);
const kline = JSON.parse(results[1].stdout);
const fund = JSON.parse(results[2].stdout);

// 3. 数据可靠性验证
const q = quote.data;
const warnings = [];

// 3.1 停牌检测：成交量为0或成交额为0
if (q.f47 === 0 || q.f48 === 0) {
  warnings.push('⚠️ 停牌警告：成交量为0，该股票可能处于停牌状态');
}

// 3.2 价格异常检测
const price = q.f43 / 100;
const prevClose = q.f60 / 100;
const changePct = q.f170 / 100;
if (price <= 0) warnings.push('⚠️ 价格异常：最新价为0或负值');
if (Math.abs(changePct) > 20) warnings.push('⚠️ 涨跌幅异常：' + changePct + '%');

// 3.3 PE/PB合理性检测
const pe = q.f162 / 100;
const pb = q.f167 / 100;
if (pe < 0) warnings.push('⚠️ PE为负：公司亏损，PE指标无意义');
if (pe > 1000) warnings.push('⚠️ PE极高：' + pe + '倍，估值严重偏高');

// 3.4 K线完整性验证
const klines = kline.data?.klines || [];
if (klines.length === 0) warnings.push('⚠️ K线数据为空');
// 验证最后一根K线日期是否为最近交易日
const lastKlineDate = klines.length > 0 ? klines[klines.length-1].split(',')[0] : 'N/A';

// 3.5 K线收盘价 vs 实时行情价格交叉验证
if (klines.length > 0) {
  const lastClose = parseFloat(klines[klines.length-1].split(',')[2]);
  if (Math.abs(lastClose - price) / price > 0.005) {
    warnings.push('⚠️ 价格不一致：K线收盘' + lastClose + ' vs 实时' + price + '，差异>0.5%');
  }
}

// 3.6 资金流向平衡验证
const fundLines = fund.data?.klines || [];
if (fundLines.length > 0) {
  const parts = fundLines[fundLines.length-1].split(',');
  const main = parseFloat(parts[1]);    // 主力
  const small = parseFloat(parts[2]);   // 小单
  const mid = parseFloat(parts[3]);     // 中单
  const sum = main + small + mid;
  if (Math.abs(sum) > Math.abs(main) * 0.01) {
    warnings.push('⚠️ 资金流不平衡：主力+小单+中单=' + sum + '（应≈0）');
  }
}

text('价格:' + price + ' PE:' + pe + ' PB:' + pb + ' 换手:' + (q.f168/100) + '%');
text('K线天数:' + klines.length + ' 最后日期:' + lastKlineDate);
text('资金流向天数:' + fundLines.length + (fundLines.length < 5 ? '（少于请求5天，可能存在停牌或数据不完整）' : ''));
if (warnings.length > 0) text('数据警告:\n' + warnings.join('\n'));
```

**注意**：Windows PowerShell中 `curl` 是 `Invoke-WebRequest` 的别名，不能使用 `-s` 参数。必须使用 `Invoke-RestMethod` 并配合 `ConvertTo-Json -Depth 5 -Compress` 获取可解析的JSON。

### 数据采集流程
1. **MCP获取实时行情**（必须）：通过integrated_code_mode MCP调用东方财富API，获取个股实时价格、涨跌幅、成交额、换手率、PE、PB、资金流向等硬数据
2. **MCP获取K线+财务**（必须）：获取近30日日K线数据和最近6期财务指标，用于技术面分析和基本面排雷
3. **网站抓取补充**：并行抓取五大财经网站（财联社/东方财富/证监会/中登/证券时报），获取最新资讯、政策、公告
4. **WebSearch扩展搜索**：补充搜索今日涨停、首板、龙虎榜、政策等关键词
5. **交叉验证**：MCP实时数据与网站数据交叉验证，同一信息至少两个来源确认
6. **标注时效**：区分"收盘数据"与"盘中数据"，明确数据时间戳。MCP数据标注"东方财富API实时获取"

### 数据可靠性验证体系（生成报告前必须执行）

**本体系是数据质量的最后一道防线，所有MCP获取的数据必须通过以下6层验证后才能写入报告。**

#### 第1层：交易日与时段验证
| 验证项 | 规则 | 处理方式 |
|:---|:---|:---|
| 周末/法定节假日 | A股仅在周一至周五交易（节假日休市） | 非交易日获取的数据为上一交易日收盘数据，须标注"非交易日，数据为最近交易日" |
| 盘前/盘后时段 | 9:00前或15:30后获取的数据 | 标注"盘前/盘后数据"，行情为前一交易日收盘 |
| 午休时段 | 11:30-13:00之间 | 标注"午休时段，数据为上午收盘" |
| 集合竞价 | 9:15-9:25 / 14:57-15:00 | 数据可能剧烈波动，标注"集合竞价中，价格未最终确定" |

#### 第2层：API响应完整性验证
```
验证清单（每个API响应必须通过）：
□ rc=0          → 返回码为0表示成功，非0表示错误
□ data对象存在  → quote.data / kline.data 不为null/undefined
□ data非空      → klines数组长度>0，实时行情f43>0
□ 字段类型正确  → 价格字段为数字而非字符串"-"
□ 无截断        → JSON解析成功且结构完整
```

#### 第3层：数据交叉验证矩阵
| 验证对 | 验证方法 | 容差阈值 | 异常处理 |
|:---|:---|:---|:---|
| 实时价格 vs K线收盘 | `abs(quote.f43/100 - kline最后一行收盘价) / quote.f43/100` | <0.5% | 超阈值时以K线收盘为准，标注差异 |
| 总市值 vs 流通市值 | 小盘股两者应接近（差异<20%）；大盘股可能有限售股 | 视情况 | 差异>50%时检查是否有大额限售股解禁 |

## 模块一：个股六维诊断分析

### 输入要求
- 个股名称或代码（如"火炬电子"或"603678"）
- 买入成本价（用于盈亏分析和操作建议）

### 分析框架：六大维度40+核心指标

#### 第一维度：宏观行业与赛道定位（选对池塘）

**分析逻辑**：个股脱离行业就是无源之水。要看公司的"天时"是否到来。

核心指标：
- **行业生命周期**：判断处于导入期、成长期、成熟期还是衰退期（成长期看PS市销率，成熟期看PE市盈率）
- **政策面**：是否属于国家战略支持（新质生产力、碳中和）还是被严格管制（教培、地产）
- **产业链位置（微笑曲线）**：处于上游资源（看大宗价格）、中游制造（看毛利率）还是下游消费（看品牌溢价）
- **市场空间（天花板）**：行业总规模（TAM）是否在千亿级以上，渗透率是否处于5%-40%的甜蜜期

#### 第二维度：财务基本面（体检报告——排雷核心）

**分析逻辑**：排除财务造假的"地雷"，验证公司是否真的能赚钱。

**成长能力（看增速）**：
- 营收同比增长率（>20%为佳）
- 净利润同比增长率
- 扣非净利润（剔除一次性收益，看主业真实利润）

**盈利能力（看质量）**：
- ROE（净资产收益率）：巴菲特最看重，长期>15%才具备核心护城河。用杜邦分析法拆解：高ROE来自高利润率（茅台型）、高周转（沃尔玛型）还是高杠杆（银行型）
- 毛利率与净利率：毛利率>40%通常代表有定价权；净利率体现费用控制能力

**营运能力（看效率）**：
- 存货周转率（警惕存货激增且周转下降，可能是滞销）
- 应收账款周转率（应收账款占比过高，可能是放宽信用换收入，有坏账风险）

**偿债能力与现金流（看生存——排雷第一指标）**：
- **经营性现金流净额**：**必须为正！** 且最好大于净利润（"净现比">1），说明赚的是真金白银而非白条。**若经营现金流为负，即使营收增长也是黄色预警**——可能通过放宽信用（应收账款激增）或压货（存货激增）虚增收入。通过MCP财务API获取 `MGJYXJJE`（每股经营现金流）字段，若为负值必须在报告中醒目标注
- 资产负债率：传统行业<60%，科技/轻资产<40%相对安全。重点看有息负债（短期借款+长期借款）
- **现金流验证三连问**：①经营现金流是否为正？②净现比（经营现金流/净利润）是否>1？③若为负，是季节性因素（Q1采购集中）还是结构性恶化（连续多季为负）？

#### 第三维度：估值性价比（贵不贵）

**分析逻辑**：好公司买贵了也会亏钱。需要横向（比同行）和纵向（比历史）看。

**相对估值法**：
- PE（市盈率）：看历史百分位（若处于近5年PE的80%分位以上，通常偏高）
- PEG（市盈率相对盈利增长比率）：PEG = PE ÷ 净利润增速。PEG < 1 通常视为低估，>1.5则可能高估（适用于成长股）
- PB（市净率）：适用于银行、钢铁等重资产行业；若PB<1（破净），需判断资产是否真实

**绝对估值法（参考）**：
- DCF（现金流折现）：核心逻辑是"自由现金流"。若一家公司无法产生稳定自由现金流，DCF估值将归零

#### 第四维度：技术面与筹码博弈（买卖时机）

**分析逻辑**：解决"什么时候买"和"当前谁在持有"的问题。

**趋势结构**：
- 均线排列（多头/空头）
- 是否站上年线（牛熊分界线）
- MACD指标（金叉/顶背离）

**量价关系**：
- 缩量下跌（洗盘） vs. 放量滞涨（出货预警）
- 突破关键压力位时必须伴随显著放量

**筹码分布（A股特有）**：
- 筹码集中度：股东户数是否连续几个季度环比减少（户数减少=筹码向大户集中）
- 获利盘比例：若股价在高位且获利盘>90%，抛压较大；若在低位获利盘<10%，套牢盘惜售，容易反弹

#### 第五维度：股东与管理层（治理结构）

**分析逻辑**：公司到底是谁在管，他们自己的利益是否和散户一致。

- **大股东与机构**：前十大流通股东中是否有社保基金、QFII（外资）或顶级公募入驻（代表通过了严苛的尽调）
- **增减持动态**：核心高管近期是否在巨量减持（重大利空信号）；若在低位进行股份回购并注销（极度看好信号）
- **分红历史**：连续5年以上稳定派息，且股息率高于国债收益率（如>3%），是防御性品种的底线

#### 第六维度：预期差与催化剂（未来驱动力）

**分析逻辑**：股价反映的是未来，而不是过去。需要找到推动股价上涨的"导火索"。

- **订单与产能**：在手订单是否充足？新增产能何时投产？
- **新产品/新市场**：是否推出了重磅新品？是否出海打开了海外市场？
- **事件驱动**：是否即将纳入重要指数（如沪深300）？是否有并购重组预期？

### 终极诊断：六维评分体系与SWOT总结

**综合评分必须按以下权重加权计算，禁止凭感觉给分：**

#### 六维评分权重表
| 维度 | 权重 | 评分标准（1-10分） | 权重依据 |
|:---|:---:|:---|:---|
| 第一维度：宏观行业 | 15% | 10=行业爆发期+政策强支持；7=成长期+政策友好；4=成熟期+政策中性；1=衰退期+政策打压 | 选对池塘是前提，但非决定性因素 |
| 第二维度：财务基本面 | **30%** | 10=ROE>20%+现金流为正+营收增>30%；7=ROE>12%+现金流为正+营收增>15%；4=ROE>5%+现金流微正；1=亏损或现金流为负 | **排雷核心，权重最高** |
| 第三维度：估值性价比 | 20% | 10=PE<历史20%分位+PEG<0.8；7=PE<历史40%分位+PEG<1.2；4=PE处于中位；1=PE>历史80%分位+PEG>2 | 贵不贵决定安全边际 |
| 第四维度：技术面 | 15% | 10=多头排列+放量突破+站上年线；7=短期均线多头+缩量企稳；4=均线纠缠；1=空头排列+破位 | 决定买卖时机 |
| 第五维度：股东治理 | 10% | 10=社保/QFII入驻+高管增持+高分红；7=机构持仓+分红稳定；4=无减持无增持；1=高管巨量减持+不分红 | 辅助验证，非核心驱动 |
| 第六维度：催化剂 | 10% | 10=订单爆发+新品放量+指数纳入；7=有明确催化预期；4=无短期催化；1=负面事件预期 | 未来驱动力，不确定性较高 |

#### 综合评分计算公式
```
综合评分 = D1×0.15 + D2×0.30 + D3×0.20 + D4×0.15 + D5×0.10 + D6×0.10
```
- 每个维度评分1-10分，综合评分满分10分
- **一票否决项**：D2(财务)评分≤3时，无论综合评分多少，最终评级不超过"持有观察"
- **加分项**：D2和D6同时≥8分（基本面好+催化强），综合评分可上浮0.5分（不超过10分）

#### 评分→评级映射
| 综合评分 | 评级 | 操作方向 |
|:---:|:---|:---|
| ≥8.0 | 强烈推荐 | 重仓买入/持有 |
| 6.5-7.9 | 推荐 | 适度配置/持有 |
| 5.0-6.4 | 中性 | 观望/小仓位 |
| <5.0 | 回避 | 清仓/不参与 |

| 维度 | 优（+） | 劣（-） | 结论 |
| :--- | :--- | :--- | :--- |
| **优势（S）** | 毛利率高、现金流充沛 | —— | 进攻性（仓位上限） |
| **劣势（W）** | —— | 应收账款过高、有息负债大 | 防守性（止损线设置） |
| **机会（O）** | 政策扶持、PEG<1 | —— | 空间测算（目标价） |
| **威胁（T）** | —— | 行业价格战、高管减持 | 风险预案（最大回撤容忍度） |

### 仓位管理方法论

**禁止凭感觉给仓位，必须按以下规则计算：**

#### 1. 综合评分→仓位映射表
| 综合评分 | 建议仓位上限 | 含义 |
|:---:|:---:|:---|
| ≥8.0分 | 30%（满仓单票上限） | 赛道好+财务优+催化强，可重仓 |
| 6.5-7.9分 | 15-20% | 中等偏上，可持有/适度加仓 |
| 5.0-6.4分 | 5-10% | 中等，持有观察，不加仓 |
| <5.0分 | 0%（清仓/不参与） | 风险大于机会，应离场 |

#### 2. 风险预算法（单笔最大亏损控制）
```
建议买入股数 = (总资金 × 单笔最大亏损比例2%) ÷ (成本价 - 止损价)
```
示例：总资金10万，成本价43.1元，止损价38元，单笔最大亏损2%=2000元
→ 最大买入股数 = 2000 ÷ (43.1-38) = 2000 ÷ 5.1 ≈ 392股 → 仓位 ≈ 392×43.1/100000 ≈ 17%

#### 3. 加仓规则
- **首次建仓**：不超过仓位上限的50%（试探仓）
- **确认加仓**：符合加仓条件后补至满仓，加仓价必须低于首次成本（摊低成本）
- **禁止逆势加仓**：下跌趋势中每次反弹都不加仓，只有趋势反转确认后才加

### 止损方法体系（多重止损，取最严格者）

**止损价必须在报告中明确标注计算依据，禁止凭空给出数字。**

| 止损方法 | 计算公式 | 适用场景 |
|:---|:---|:---|
| **技术止损** | 跌破近期关键支撑位（前低/21日均线/趋势线） | 通用，首选 |
| **固定比例止损** | 成本价 × (1 - 止损比例)，短线-5%、中线-10%、长线-15% | 无明确技术位时 |
| **波动率止损(ATR)** | 成本价 - 2×ATR(14)，ATR为近14日平均真实波幅 | 高波动股 |
| **资金管理止损** | 单笔亏损达总资金2%时无条件离场 | 绝对底线 |
| **时间止损** | 持有N个交易日未达预期（短线5日、中线20日）则离场 | 趋势未如期发展 |
| **移动止损(保本)** | 浮盈>5%后将止损上移至成本价（保本止损） | 盈利后锁定 |

**执行优先级**：资金管理止损（绝对底线）> 技术止损 > 固定比例止损 > 时间止损

### 目标价测算方法

**目标价必须给出计算公式和代入数值，禁止凭空给出价格区间。**

#### 1. 估值法测算（适用于中长线）
```
目标价 = 预测EPS × 合理PE
```
- 预测EPS：基于最近季度年化或券商一致预期
- 合理PE：取行业PE中位数 或 历史PE中位数（非当前PE）
- 示例：预测EPS=0.80元 × 行业PE 65倍 = 目标价52元

#### 2. 技术位测算（适用于短线）
| 测算方法 | 公式 |
|:---|:---|
| 前高压力位 | 近期高点（如7/21涨停价46.76元） |
| 黄金分割位 | 低点 + (高点-低点) × 0.618 / 1.272 / 1.618 |
| 筹码密集区 | 上方套牢盘密集区下沿 |
| 缺口回补 | 近期跳空缺口位置 |

#### 3. 时间窗口定义
| 类型 | 持有周期 | 目标价测算方法 |
|:---|:---|:---|
| 短线 | 1-2周（5-10交易日） | 技术位测算（前高/黄金分割） |
| 中线 | 1-3月 | 估值法测算（EPS×行业PE） |
| 长线 | 3-12月 | DCF/估值法 + 成长性溢价 |

### 组合级风险管理

**单只个股的止损只是第一层，组合层面的风险控制同样重要：**

#### 1. 总仓位控制（按市场环境调整）
| 市场环境 | 判断依据 | 总仓位上限 | 策略 |
|:---|:---|:---:|:---|
| 牛市/强势 | 上证站上年线+两市成交>1.2万亿+涨停>80 | 80-100% | 顺势持仓，回调加仓 |
| 震荡市 | 均线纠缠+成交6000亿-1.2万亿+涨停30-80 | 50-70% | 高抛低吸，快进快出 |
| 熊市/弱势 | 破年线+成交<6000亿+涨停<30 | 20-30% | 防御为主，轻仓试探 |

#### 2. 集中度风险控制
- **单票上限**：不超过总资金的30%（无论多看好）
- **同行业上限**：同一行业板块持仓合计不超过50%（避免行业系统性风险）
- **相关性行业上限**：高相关行业（如半导体+消费电子）合计不超过60%
- **最大持仓数**：同时持有不超过5-8只个股（精力有限，过多则无法跟踪）

#### 3. 回撤控制
- **单日回撤**：组合单日回撤>3%时，减仓至70%以下
- **周回撤**：组合周回撤>5%时，全面审视持仓，减仓至50%以下
- **月回撤**：组合月回撤>10%时，清仓至30%以下，暂停交易1周冷静

### 特殊行情处理规则

| 特殊状态 | 识别方法 | 操作规则 |

### 避坑指南（实操原则）

1. **先排雷，再谈价值**：如果经营性现金流连续为负或存货/应收账款暴增，直接PASS，不要看估值。**特别警惕"增收不增利+现金流为负"的组合**——营收大增但净利下滑且经营现金流为负，说明收入增长可能依赖代理/贸易类低质量业务，而非核心主业驱动
2. **逻辑重于指标**：PE高达100倍但处于AI爆发初期，可用PS或订单增速解释；PE只有5倍但行业永久性萎缩（如传统燃油车配件），是"价值陷阱"
3. **交叉验证**：技术面（底部放量金叉）和基本面（业绩预告超预期）形成"共振"，是确定性极高的买入信号

### 选股方法论（四步法）

1. **题材体量优先**：只选能容纳大资金的题材（板块总市值大、成交活跃），小容量题材剔除
2. **涨停个数验证强度**：题材内今日涨停家数越多，说明资金共识与持续性越强
3. **消息催化**：叠加政策、大事件、行业数据
4. **个股精选**：在题材内挑低位+低价（一般<15元）且出现突破信号（一阳穿三线/站上6·21·60均线/突破近一周·一月·半年·一年高点）的标的

### 板块共振分析方法

**个股与板块的强弱对比是判断个股质量的核心方法：**

1. **板块强度排序**：通过API 8获取行业/概念板块涨跌幅排行，选取Top5热点板块
2. **板块内个股对比**：通过API 9 + 板块成分股(`fs=b:{板块代码}`)获取同板块所有个股涨幅
3. **龙一/龙二/龙三定位**：
   - 龙一：板块内涨幅最大/最先涨停的个股（资金首选标的）
   - 龙二：板块内涨幅第二/第二个涨停的个股（跟风标的）
   - 龙三及以后：板块内跟涨个股（补涨标的，风险递增）
4. **个股vs板块强弱判断**：
   - 个股涨幅 > 板块涨幅 × 1.5 → 龙头/强势（可追）
   - 个股涨幅 ≈ 板块涨幅 → 跟涨（观察）
   - 个股涨幅 < 板块涨幅 × 0.5 → 弱于板块（规避，可能有个股利空）
5. **最高板对标**：通过涨停池(API 7)获取连板数最高的个股，作为市场情绪标杆

### 龙虎榜使用规则

**通过API 11获取龙虎榜数据，按以下规则分析：**

1. **机构席位 vs 游资席位**：
   - 机构专用席位买入 = 中长线资金看好（正面信号强）
   - 知名游资席位（如东方财富拉萨、华泰证券总部）= 短线资金（需判断接力情绪）
2. **净买入金额**：机构净买入>5000万为强信号，<1000万为弱信号
3. **买卖力量对比**：买入席位合计金额 ÷ 卖出席位合计金额，>2为强买入，<1为净卖出
4. **席位集中度**：前5买入席位中机构数量≥3家 = 高质量买入

### 错误处理与降级策略

**数据可靠性验证详见上方「数据可靠性验证体系」6层验证，此处仅补充API调用层面的错误处理：**

#### MCP调用失败处理
1. **API超时/无响应**：重试1次，仍失败则标注"该数据项获取失败，以WebSearch数据替代"
2. **返回空数据**：检查股票代码是否正确（沪市6位数字以6开头，深市以0/3开头），检查secid前缀（沪市=1，深市=0）
3. **JSON解析失败**：确保PowerShell命令使用 `(Invoke-RestMethod -Uri '...') | ConvertTo-Json -Depth 5 -Compress` 格式，不要省略括号和-Compress参数
4. **龙虎榜URL编码**：日期filter中的单引号和比较符必须URL编码（`%27`/`%3E%3D`/`%3C%3D`/`%3D`），否则PowerShell会报错
5. **财务数据API返回HTML而非JSON**：WebFetch可能返回HTML包装的JSON，需从返回内容中提取JSON部分（搜索`{`开始到`}`结束的部分）
6. **资金流向lmt参数失效**：某些股票lmt=5只返回1天数据，属已知问题，需在报告中标注实际获取天数

#### 数据降级策略（当MCP数据不可用时）
| 优先级 | 数据项 | MCP不可用时的替代方案 |
|:---:|:---|:---|
| 1 | 实时价格/涨跌幅 | WebSearch搜索"股票代码 实时行情" → 东方财富网页 |
| 2 | PE/PB | 从财务API获取净利润和净资产，手动计算PE=市值/净利润、PB=市值/净资产 |
| 3 | K线数据 | WebFetch东方财富K线页面，提取最近30日数据 |
| 4 | 资金流向 | WebSearch搜索"股票代码 资金流向" → 东方财富资金流页面 |
| 5 | 财务指标 | WebSearch搜索"股票代码 财务报表" → 东方财富F10页面 |
| 6 | 涨停池 | WebSearch搜索"今日A股涨停" → 财联社涨停分析 |

**降级标注规范**：使用替代数据源时必须在报告中标注"⚠️ MCP数据获取异常，该项使用{替代来源}，可能存在延迟"

### 执行检查清单

**个股诊断报告生成前必须确认：**

*数据获取层：*
- [ ] 通过MCP获取了实时行情（价格、涨跌幅、PE、PB、成交额、换手率）
- [ ] 通过MCP获取了近30日日K线（fqt=1前复权，用于均线、趋势分析）
- [ ] 通过MCP获取了资金流向（主力/超大单/大单/中单/小单）
- [ ] 通过MCP获取了财务指标（含经营现金流，若为负必须醒目标注）
- [ ] 获取了财务数据最新一期日期，确认未过期（非>6个月前的数据）

*数据可靠性验证层：*
- [ ] API响应rc=0且data非空（通过第2层验证）
- [ ] K线收盘价与实时行情价格差异<0.5%（通过第3层交叉验证）
- [ ] 资金流向平衡验证通过（主力+小单+中单≈0）
- [ ] 无异常值触发（价格>0、PE非负或已标注、成交额>0）
- [ ] 停牌检测通过（成交量>0，非停牌状态）
- [ ] ST/*ST检测通过（或已标注警示）

*分析逻辑层：*
- [ ] 止损价标注了计算依据（技术位/固定比例/ATR，非凭空给出）
- [ ] 目标价标注了测算公式（EPS×PE / 前高 / 黄金分割）
- [ ] 仓位建议符合评分映射表（非凭感觉）
- [ ] 综合评分 = 六维评分按权重加权（D1×15%+D2×30%+D3×20%+D4×15%+D5×10%+D6×10%）
- [ ] D2（财务）评分≤3时已触发一票否决，评级不超过"持有观察"
- [ ] 经营现金流为负时已标注橙色预警

*输出规范层：*
- [ ] 数据来源标注包含"integrated_code_mode MCP东方财富API"
- [ ] 每项数据标注了时效性（截至日期、盘中/收盘）
- [ ] K线使用前复权（fqt=1），无虚假除权缺口

**市场报告生成前必须确认：**

*数据获取层：*
- [ ] 通过MCP获取了大盘指数（上证/深证/创业板/沪深300/科创50）
- [ ] 通过MCP获取了涨停池（含连板数、炸板次数）
- [ ] 通过MCP获取了板块排行（行业+概念）
- [ ] 通过MCP获取了条件选股数据（按「板块范围规则」过滤，默认主板，用户要求时含创业板/科创板）
- [ ] 通过MCP获取了资金流向排行
- [ ] 通过MCP获取了龙虎榜数据

*数据可靠性验证层：*
- [ ] 大盘指数数据非空且涨跌幅合理（非0%且非极端值）
- [ ] 涨停池数据非空，涨停数量与市场实际情况一致
- [ ] 板块排行数据非空，行业板块数量>20
- [ ] 选股数据二次过滤正确（按「板块范围规则」过滤：默认排除创业板/科创板，用户要求时包含；ST/*ST永远排除）

*分析逻辑层：*
- [ ] 计算了市场情绪指标（涨跌比/封板率/连板高度/炸板率/两市成交额）
- [ ] 判断了情绪周期阶段（冰点/发酵/高潮/退潮）
- [ ] 选股结果中每只个股标注了低位量化标准（回撤/分位数/跌幅）
- [ ] 关注行业/题材方案基于当日实时板块数据动态生成（非硬编码）
- [ ] 龙虎榜个股标注了机构/游资席位类型

*输出规范层：*
- [ ] ST股若出现已标注"严禁参与"
- [ ] 每只推荐个股标注了交易所和板块（沪市/深市主板/创业板/科创板）
- [ ] 报告顶部标注了本次选股板块范围（如"默认仅主板"或"用户指定包含创业板"）
- [ ] 数据标注了获取时间和来源
