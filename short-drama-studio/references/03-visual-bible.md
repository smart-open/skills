# 视觉圣经与连续性规范（角色 / 场景 / 声音 / 首尾帧）

目标：用 2D 图像接口 + 首尾帧视频接口，最大限度锁定全片人物、场景、声音的一致性。

## 1. 连续性总策略：三层锁定

1. **文本层锁定**：一次生成“角色圣经 + 视觉风格手册”，之后所有提示词原样复用同一段锚点描述，禁止改写。
2. **参考图层锁定**：每个主要角色先生成 1 张定妆照（2K、同画幅），后续每张关键帧都用
   多图合成把定妆照作为 `<Picture 1>`（多角色依次 `<Picture 2>`），并附前一张关键帧延续构图与光线。
3. **帧链层锁定**：全片只生成 N+1 张边界关键帧 K0..KN；镜头 i 以 Ki 为首帧、Ki+1 为尾帧，
   相邻镜头共享同一帧，转场天然连续。

## 2. 角色圣经（character bible）模板

每个角色固定以下字段，写入 production.json 并在所有 prompt 中复用：

```
姓名/称呼：老周
年龄与身份：52 岁，小区门口修表匠
外形锚点（不可变，每次原样引用）：瘦削，花白寸头，左眉一颗痣，国字脸，
  藏青色中山装，左手戴老式上海牌手表，手指有机油痕迹
性格标签+反差：抠门 / 却偷偷给亡妻订了三年鲜花
口头禅：“表坏了能修，人心坏了没零件。”
音色设定（配音用）：低沉略沙哑的中老年男声，语速慢，带轻微北方口音
```

规则：

- 外形锚点控制在 40–80 字，包含：年龄感、脸型、发型、1 个强识别特征（痣/疤/眼镜）、
  固定服装、固定随身道具。强识别特征是跨镜头认脸的关键。
- 全片主要角色 ≤4 个；每个角色 1 张正面半身定妆照；主角再加 1 张侧面/全身可选。
- 定妆照生成时固定 `seed`（写入 production.json），同角色重生成沿用同 seed + 同描述。
- 群演/路人在 prompt 中只写泛化描述（“几个穿便装的路人，面部模糊/虚化”），不建立圣经。

## 3. 视觉风格手册（style bible，全片唯一）

一次确定，追加在每条图像/视频 prompt 末尾的固定后缀：

```
电影感写实风格，35mm 胶片质感，自然肤色；统一冷青色调、暖色点光源（路灯/店内灯）；
浅景深，背景适度虚化；高动态范围，真实光影；无卡通感、无过度磨皮、无塑料质感、无水印文字
```

要素清单（按需替换，但全片统一）：写实度/介质（胶片 or 数字）、主色调与色板、
光质（硬光/柔光、时段光）、镜头焦段倾向、颗粒与反差、画幅。
喜剧可提高饱和与对比；忧愁段降低饱和、用暖黄单点光；悬疑段用低调照明、阴影与负空间。

## 4. 画幅与分辨率对齐

| 发布形态 | aspect_ratio | 关键帧 size/ratio | 视频输出 |
|---|---|---|---|
| 抖音/快手/视频号竖屏（默认） | 9:16 | 2K + 9:16（1472x2624） | 720x1280 |
| B站/YouTube 横屏 | 16:9 | 2K + 16:9（2624x1472） | 1280x704 |
| 方形信息流 | 1:1 | 2K + 1:1（2048x2048） | 720x720 |

关键帧与视频必须同画幅；禁止竖屏素材横用。

## 5. 关键帧生成作业法

脚本 `make_keyframes.py` 会**自动在 prompt 前注入参考图映射**
（`<Picture 1..M>` 是角色定妆照、`<Picture M+1>` 是上一关键帧），
因此 agent 撰写的 `first_frame_prompt / last_frame_prompt` **不要再出现 `<Picture N>` 占位符**，
只用纯文字把角色锚点、场景锚点写清楚即可。帧 prompt 固定五段式：

1. **角色锚点（纯文字）**：角色名 + 年龄感 + 脸型发型 + 强识别特征 + 固定服装
   （多角色逐个写清），例如“28岁清瘦外卖员，短寸黑发，右眉浅疤，发白的蓝色骑手冲锋衣、红色护腕”。
2. **画面内容**：场景 + 时间 + 角色 + 动作进行到的精确瞬间 + 表情 + 道具。
3. **摄影信息**：景别（大远景/远景/全景/中景/近景/特写/大特写）、机位高度、
   镜头焦段感（广角/标准/长焦压缩）、构图。
4. **光线氛围**：光源方向、色温、明暗、天气。
5. **固定风格后缀**：粘贴第 3 节风格手册原文（脚本也会在缺失时自动补齐）。

边界帧要求：

- K0（开场钩子帧）单独精修，信息最抓人；KN（结尾悬念帧）必须包含钩子道具/神秘元素。
- Ki 同时是镜头 i-1 的尾帧与镜头 i 的首帧，描述时要保证“动作可从前一镜自然接住、
  能向后一镜自然发展”，避免姿态走死（如角色已经坐下，下一镜却在走路）。
- 同一场景的连续帧保持机位轴线一致（180 度轴线规则），防止角色左右换位。

质检（用 agnes-3.0-flash 多模态能力，把关键帧 URL 传给模型核对）：

- 脸/发型/服装/痣等锚点是否与定妆照一致；不一致则带原图重生成（同 seed）。
- 相邻帧场景、光线、道具是否连续；尾帧姿态能否接到下一镜。
- 画面是否出现意外文字、水印、多指/穿帮。

落地脚本：`qa_frames.py`（会自动把“定妆照 + 待检帧 + 上一帧”喂给模型，按 face_match /
feature_match / hair_match / outfit_match / scene_continuity / pose_bridge 必须 true、
extra_hands / watermark_or_text 必须 false 逐项判定并写 `work/frame_qa.json`；
`--delete-bad` 删除不合格帧本地文件并清 assets，重跑 frames 补缺；`--offline` 可只看清单）。

### 5.1 第一人称视角（POV，默认 on）

- 全局默认 `camera_mode: "first"`：帧与视频 prompt 都把镜头写作**视角主角的眼睛**，
  画面是角色实见的场景与动作，观众代入其视线；除镜面/自拍特写外**不出现视角主角本人**。
  POV 指令由脚本自动注入（`make_keyframes.py` 注入帧，`make_clips.py` 注入 video prompt），
  agent 无需手写，但撰写 `scene_cn / 帧 prompt` 时要按“主角看到什么”组织画面。
- 单镜覆盖：必须让观众看到主角本人时置 `camera_pov: "third"`——例如主角**反应特写**（看到
  惊喜/惊吓的表情）、**镜面/自拍**、**大远景建立镜**。其余镜头尽量保持第一人称以增强代入。
- POV 下的帧链仍成立：相邻第一人称镜头共享同一张边界关键帧（都是主角视线所见的连续画面）。
- 开镜建议：冷开场用 1–2 个 POV 特写快速建立代入；情绪爆点（惊喜/反转）切到第三视角
  拍主角的脸，张力更强。

## 6. 镜头视频生成作业法（keyframe 模式）

- 每个镜头：`mode="keyframe"`、`first_frame=Ki`、`last_frame=Ki+1`、`seconds="10"`、
  `size="720P"`、对应 `aspect_ratio`，同场景沿用固定 seed。
- prompt 六段顺序（官方建议）：主体与场景 → 动作与变化 → 镜头运动 → 视觉风格 →
  声音与节奏 → 一致性要求。示例：

```
深夜便利店（延续首帧场景与人物）。老周攥着彩票，手指微微发抖，缓缓抬头看向店员，
嘴唇翕动却说不出话；店员皱眉前倾。镜头从特写缓慢推至近景并轻微手持晃动。
冷白荧光灯、窗外雨痕、浅景深。环境声：雨声、冰柜低频嗡鸣、挂钟滴答。
人物外貌、服装与首尾帧完全一致，不新增角色，不改变场景陈设。
```

- 运镜词汇表：固定镜头、缓推（dolly in）、缓拉、横移、升降、手持微晃、环绕、跟拍、
  甩镜（用于强转场）。10 秒内只设计一个主动机，避免运动过载。
- 不要让视频模型负责念台词/对白（口型不可控）：人物说话用“嘴唇微动/转头”动作描述，
  人声全部后期配音；prompt 只写环境声与动作声作为底噪。
- 失败重试策略：单镜最多 3 次；第 1 次失败换 seed，第 2 次简化动作描述，
  第 3 次改为仅首帧（去掉 last_frame）并在后期用匹配剪辑衔接。

## 7. 声音一致性方案（后期配音，不靠视频模型）

1. **角色音色档案**：角色圣经中的“音色设定”是唯一依据；每个角色用同一配音配置生成全部台词
   （落地见 `build_audio.py`），保证跨镜同音色。可给 `characters[].tts.edge_voice` 写死精确声线。
2. 产物按镜号命名：`s01.wav`（对白+旁白）、`s01_amb.wav`（环境声，可复用视频原声底噪）。
   未安装配音能力时，`build_audio.py` 生成 `audio/dub_plan.json`（逐镜逐句清单）供手动/Agent 兜底。
3. BGM 按段落情绪选 2–3 段（轻松/忧愁/悬疑），统一响度，笑点前留白、反转点卡点。
4. ffmpeg 混音链：对白 −0.5 LU 前景、BGM −18 LU 垫底、环境声 −12 LU；整体 −14 LUFS（移动端）。
5. 字幕：由分镜表台词与每镜 10s 时长自动生成 SRT，硬字幕烧录（移动端默认开）或软字幕封装。

字幕硬烧在 Windows 上默认取 Microsoft YaHei（`assemble.py` 自动探测 fc-list，无则取系统
`msyh.ttc`/`simhei.ttf`）；若连中文字体都没有才退软字幕。混音/拼接/烧字幕依赖**全功能 ffmpeg**
（concat demuxer、subtitles 滤镜、amix/loudnorm/apad/aresample），`assemble.py` 会自动探测并切换到
可用版本，PATH 里只有精简版时会明确报错而不是产出坏片。

## 8. 剪辑连续性

- 转场默认硬切；时间流逝用叠化（≤0.5s）；钩子/反转可用一次音效强化的甩切，全片 ≤2 次。
- 拼接前统一所有镜头规格：同分辨率、同帧率（建议 24fps）、同 SAR、yuv420p、AAC 音频。
- 顺序以分镜表为准；首尾帧已保证画面衔接，剪辑不再做跨镜重排。
