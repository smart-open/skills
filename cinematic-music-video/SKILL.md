# 电影级音乐 MV 制作 (cinematic-music-video)

把「一首歌 + 歌词」变成一支电影质感的音乐 MV。整条流水线用 Agnes 三个模型分工：
**agnes-3.0-flash 当导演兼质检**（分镜 + 人物视觉核验）、**agnes-image-2.5-flash 当摄影**
（角色设定表 + 逐镜首帧）、**agnes-video-2.5-flash 让画面动起来**（图生视频），最后 **ffmpeg 做剪辑与混音**。

> **本版本的三处核心升级。**
>
> **其一：人物一致性从"靠祈祷"变成"有门禁"。**
> 旧做法是「一张半身定妆照 → 派生全身照 → 逐镜头生成」，结果实测出现**首帧和定妆照明显不是同一个人**。
> 原因有四：半身照没有全身信息（模型只能编）、派生链是"复制品的复制品"（每过一手都掉精度）、
> 镜头是 16:9 远景而参考是 1:1 半身（尺度差太大）、身份描述被埋在长提示词中间（权重被稀释）。
> 现在改为：**一张角色设定表锁定真源 → 单独反读结构化参数 → 派生多角度白底参考图 →
> 每张含主角的首帧都过一遍视觉一致性核验，不达标自动带着"差异清单"重画。**
>
> **其二：人物"先定清楚再进分镜"。**
> 旧做法是规划器一边编剧情一边临时决定这个人穿什么、什么表情、在什么场景里——
> 结果"同一个人在每个镜头里都像刚被重新介绍了一遍"。
> 现在要求**在写任何镜头之前**，把主角按**七个维度**全部定死：
> **三视图、五官特征、发型结构、服装层次、表情库、标志动作、场景气质**。
> 定完之后分镜就退化成"把已经定好的人放进已经定好的场景"，跨镜头一致性也从"靠模型自觉"
> 变成"靠结构保证"。详见 **1.1 七维度角色档案**。
>
> **其三：地点也是资产，且身份被切成"不可变 / 本场可变"两桶。**
> 三个镜头写在"同一个雨夜街头"，就是三次独立生成——巷子宽窄、灯位、积水颜色都会漂，
> 观众不会说"巷子变了"，只会觉得"这不像一个片子"。现在**地点先在 `scenes[]` 里定义成资产**，
> 系统为它生成一张**无人空镜锚点图**，该地点的所有镜头（含空镜）都挂上它（见 **2.4**）。
> 同时角色卡被拆成 **不可变身份**（骨相 / 发构 / 肤色）与 **本场可变**（服装 / 淋湿 / 擦伤 / 速度）两桶，
> 分块注入——因为把"架构"和"天气"混成一段，就是换脸的起点（见 **2.2**）。
> **一致性 = 共享可复用资产 + 显式引用**，而不是"在提示词里重新描述一遍"。
>
> **外加一条工程约束：产物与机器环境解耦。**
> **所有结果与中间产物只写进当前会话工作目录下的 `out/`（`process.cwd()/out`），不写回技能安装目录**；
> 源码内不含任何绝对路径、盘符、用户名或 `home` 目录，歌曲/歌词会被复制进项目使项目可整体搬走。
> 详见 **输出契约** 一节，由 `test/paths.js` 强制守住。

## 何时调用

用户出现以下意图时调用本 Skill：
- "给这首歌做个 MV / 音乐视频 / 音乐短片"
- "根据歌词做一支电影感的视频"
- 提供了歌曲文件 + 歌词，要求生成带音乐的成片
- 要求"图生视频 + 保持人物一致 + 不丢帧 + 图音同步"的 MV 类交付

## 输出契约：一切都在当前会话的 `<cwd>/out/` 下

**这是硬约束，不是约定。** 所有结果输出与中间产物**只**写到**运行命令时的当前工作目录**下的 `out/`，
不写回技能安装目录；同一流水线的各阶段必须在**同一个 cwd** 下执行（或用 `CMV_OUT_DIR` 固定输出根）。

```
<cwd>/out/                          ← 唯一的输出根（跟随会话），可整体删除或打包
├── .state/                         # 跨项目共享的运行时状态
│   ├── .agnes-key-state.json       #   Key 轮询游标
│   └── vision-cache/               #   喂给视觉模型的降采样图缓存
├── mv-<歌名>/                       # 每首歌一个项目目录
│   └── 00_source/ … 05_output/      # 见「目录结构」
```

**为什么这样设计**（对应两条硬性要求）：

| 要求 | 实现 |
|---|---|
| 产物集中、可整体清理 | 所有路径由 `lib/paths.js` 统一推导，输出根锚定当前会话 cwd（`<cwd>/out`） |
| **不依赖本机环境**（绝对路径 / 用户名 / 盘符） | 源码内**零**硬编码绝对路径；`process.cwd()` 只允许出现在 `lib/paths.js`（锚定输出根），`test/paths.js` 会扫描源码强制这条 |

想换盘或挂到大容量目录时，**不要改代码**，用环境变量覆盖即可：

```bash
CMV_OUT_DIR="/d/mv-out" node "<skill-dir>/scripts/run.js" --song "夜曲.mp3" --keys "sk-aaa"
```

> **项目目录现在是可搬走的。** `plan.js` 会把歌曲（以及歌词文件）复制进 `00_source/`，
> 并在 `project.json` 里记录**相对项目目录**的路径。因此项目复制到另一台机器后，
> `assemble.js` / `verify.js` 仍能找到原声，不会因为"用户把歌挪走了"而失败。


## API Key 与轮询

Key 按优先级解析，**支持多个 Key 自动轮询**：

1. `--keys "sk-a,sk-b,sk-c"`（逗号/分号/空格分隔）
2. `--keys-file keys.txt`（每行一个，`#` 开头为注释）
3. `--api-key sk-x`（单个）
4. 环境变量 `AGNES_API_KEYS` → `agnes-api-key` → `AGNES_API_KEY`

轮询行为：**round-robin 游标持久化**在当前会话的 `out/.state/.agnes-key-state.json`，遇到 `401/403` 或 `429`
会把该 Key 打入冷却队列并自动切到下一个（冷却时长指数递增，上限 5 分钟）；多个 Key 全部冷却时
会等待最早恢复的那个。每个阶段结束会打印各 Key 的成功调用次数。
游标是**跨项目共享**的，所以连续做多首歌时请求会持续在 Key 之间分散，而不是每首歌都从第 1 个 Key 重新开始。

> **安全**：不要把 Key 写进任何文件或日志。脚本只通过参数/环境变量读取，日志里只输出掩码。

## 四阶段流水线

```
plan.js        →  images.js                          →  videos.js      →  assemble.js
七维度角色档案     设定表→反读参数→多角度参考→逐镜首帧   图生视频          精确拼接+混原声
+ 地点资产库         + 地点空镜锚点                       + 就绪预检
+ 分镜铁律          (过身份门禁 + 身份/本场分块注入)        + 一镜多拍选优
                       ↑___________________agnes-3.0-flash 视觉质检___________________↑
```

**三类资产，全部"先行"：** 角色（设定表 + 反读参数 + 多角度参考）、**地点**（无人空镜锚点）、
风格（基调板）。所有镜头只负责**引用**这些资产，而不是在提示词里重新描述一遍——
这是一致性从"靠模型自觉"转为"靠结构保证"的关键。

一步跑完（可断点续跑，已完成的阶段自动跳过）。**无需指定输出目录**——默认就是
当前会话工作目录下的 `out/mv-<歌名>/`：

```bash
node "<skill-dir>/scripts/run.js" \
  --song "夜曲.mp3" \
  --lyrics "夜曲.lrc" \
  --brief "城市里两个人在雨夜重逢又告别" \
  --style "霓虹雨夜，胶片质感，青橙色调" \
  --aspect 16:9 --shots 26 \
  --video-mode keyframe --motion-min 1.2 --motion-retries 2 \
  --transition dissolve --fade --normalize-audio \
  --concurrency 3 \
  --keys "sk-aaa,sk-bbb"
```

也可以分阶段执行，便于逐段审查（**推荐**，见下方"标准工作流"）。

## 阶段 1：分镜规划 `plan.js`

```bash
# 默认输出到 <cwd>/out/mv-夜曲/；要换位置加 --out <dir>
node "<skill-dir>/scripts/plan.js" \
  --song "夜曲.mp3" \
  --lyrics "夜曲.lrc" \
  --brief "创作要求：一段关于城市夜晚重逢的故事" \
  --style "赛博朋克霓虹" \
  --aspect 16:9 --shots 26 \
  --keys "sk-aaa,sk-bbb"
```

**它做什么**
1. **把输入收进项目**：歌曲（以及歌词文件，若来自文件）复制到 `00_source/`，
   `project.json` 只记录**相对项目目录**的路径。这样项目搬走后 `assemble.js` 仍能找到原声，
   不会因为原文件被移动、改名或换盘而失败。内联歌词本就已写进 `storyboard.json`。
2. 用 ffprobe 读出歌曲**真实时长**（后续所有时间轴的锚点）。
3. 读取歌词：支持纯文本、内联文本、`auto`（自动找同名 `.lrc`）。
   **LRC 带时间戳时**会解析出每句的真实时间点，分镜会尽量对齐，并在成片时把歌词挂到对应镜头上——这是最强的时间同步手段。
4. 让 `agnes-3.0-flash` 以「顶级 MV 导演」身份输出严格 JSON 分镜。**但它必须先交出一份完整的角色档案**：
   七个维度（三视图所需的体型比例、五官特征、发型结构、服装层次、表情库、标志动作、场景气质）
   全部定完之后，才开始写镜头。详见下面 **1.1**。
5. **校验 + 自动修复**：校验器会检查镜头时长是否在 4–12s、`video_prompt` 是否同时包含「摄影机运动 + 主体动作」、是否缺少必填字段、镜头数是否与时长匹配，以及**角色档案七个维度是否定全**。不合格就把**具体问题**回传给模型重写（默认最多 3 次）。档案维度缺失默认只警告并兜底；`--strict-profile` 时升级为硬失败。
6. **时间轴拟合** `fitTimeline()`：把所有镜头时长缩放到与歌曲时长**精确相等**，处理超长拆分、过短合并、余量兜底。每个镜头输出 `api_seconds`（向上取整到 4–12 的整数，供 API 使用）。

**产出**
- `00_source/` —— 歌曲（+ 歌词）副本，使项目自包含
- `01_plan/storyboard.json` —— 机器可读，后续阶段都读它
- `01_plan/storyboard.md` —— 人类可读分镜表（镜头表 + 逐镜头详案 + 提示词全文）

> **关键**：`plan.js` 结束后**必须用 Read 工具打开 `storyboard.md` 给用户过目**，确认故事方向、
> 人物设定、风格是否正确，再进入生图。这一步是整条流水线里最省时间的返工点。

### 1.1 先把人物"定清楚"：七维度角色档案

**这是本版最重要的方法升级。** 人物漂移的深层原因不是"模型画不准"，而是**人设根本没定全**——
规划器一边想剧情一边临时决定这个人穿什么、什么表情、在什么场景里，每个镜头各拍一次脑袋，
结果就是"同一个人在每个镜头里都像刚被重新介绍过一遍"。

正确顺序是：**先把一个人从"长什么样"一路拆到"怎么动、穿什么、适合出现在哪里"，再把这个人放进分镜。**
定完之后分镜工作就退化成"把已经定好的人放进已经定好的场景"。

七个维度、对应的字段、以及它被谁消费：

| # | 维度 | 字段 | 定什么 | 由谁填 | 被谁用 |
|---|---|---|---|---|---|
| ① | **三视图** | （由 params 自动生成） | 正面/侧面/背面全身 + 大特写 + 表情带 | 系统生成 | 身份真源 |
| ② | **五官特征** | `face_shape` `eye_shape` `iris_color` `eye_spacing` `eyebrows` `nose` `lips` `jaw_chin` `skin_tone` | 脸的可复现形体结构 | 规划器写 → 视觉反读覆盖 | 每张首帧的身份块 |
| ③ | **发型结构** | `hair_structure` `hair_color` | **长度 + 分缝 + 刘海 + 卷度 + 层次**（不许只写 "long hair"） | 同上 | 身份块 + 身份尾 |
| ④ | **服装层次** | `wardrobe_layers{inner,outer,bottoms,footwear,accessories,materials}` `garment_palette` `wardrobe` | 按穿着层次逐层拆（不许压扁成一句） | 同上 | 身份块（逐层进入提示词） |
| ⑤ | **表情** | `expression_bank[4]{name,en}` + 每镜 `shot.expression` | 4 个具名表情 + 各自的英文执行描述 | **规划器独有**（设定表是中性的，视觉读不出表情） | 首帧的独立 `EXPRESSION` 块 |
| ⑥ | **动作** | `signature_actions[3]` | 这个人特有的标志性动作/体态 | **规划器独有** | 镜头 `subject_action` 优先复用 |
| ⑦ | **场景气质** | `scene_affinity` | 适合的空间类型、材质与光线 | **规划器独有** | 含主角镜头的选景约束 |

**为什么③④要从图片反读，而⑤⑥⑦不能？**

设定表是一张**中性的、纯影棚的、单一服装的**图。它能告诉你头发怎么分层、衣服怎么穿，
但它**不包含**这个人的情绪范围、习惯动作、以及他属于什么样的世界。让视觉模型去"读"这三样，
它只会编。所以字段分两类，各归各的：

```
VISUAL_FIELDS   五官 / 发型结构 / 服装层次 / 色板 → 视觉模型从设定表真实反读（文字与画面必须一致）
CREATIVE_FIELDS 表情库 / 标志动作 / 场景气质 / 气质 → 规划器拥有，原样透传（不参与反读）
```

这条分工写死在 `lib/assets.js`（`VISUAL_FIELDS` / `CREATIVE_FIELDS`），有离线测试守着。

**表情为什么要单独走一条通道（而不是写在 `keyframe_prompt` 里）？**

因为"情绪"和"长相"是两种信息，混在一句里会互相污染。本版把表情提成独立字段：
规划器给每种表情一句英文执行描述，渲染时**单独注入一个 `EXPRESSION` 块**，并明确告诉图像模型：

> 表情只改变面部肌肉；骨相、眼型与眼距、鼻、唇、下颌线、肤色、发型必须与参考图完全一致。

于是"同一个人在哭"和"同一个人在笑"不会再变成"两个长得像的人"。空镜写 `none`，
主角刻意中性写 `neutral`——两者都不会注入任何表情块。

**约束强度可控**：默认七维度缺失只给**警告并用默认值兜底**（缺失的表情库自动补 4 个默认表情，
流水线照常跑完）；加 `--strict-profile` 则升级为**硬失败**，规划器必须补齐才能通过。
日常建议先用默认跑，看到警告后再针对性修正；要对交付质量有硬保证时再开 strict。

### 1.2 地点也要"先定清楚"：`scenes[]` 地点资产库

和人物一样，**地点也必须先定义成资产、再写镜头**。规划器要交出 2-4 个反复出现的地点：

```json
"scenes": [
  { "id": "SC1", "name": "雨夜霓虹街头",
    "description": "a narrow rain-soaked alley lined with shuttered storefronts…",
    "architecture": "wet asphalt, glazed brick walls, corrugated shutters",
    "lighting": "sodium street lamps overhead throwing warm pools onto the wet ground",
    "used_by": ["S01", "S03", "S07"] }
]
```

然后每个镜头用 `scene_id` 引用它。产出会在 `storyboard.md` 里渲染成一张**地点资产表**，
`引用镜头` 一列如果显示"无镜头引用"，说明这个场景白定义了。

校验器会报三类问题：`scene_id` 引用了不存在的场景（**硬失败**）、场景字段写得太粗、
以及场景没人引用。完整机制见 **2.4**。

### 1.3 三条分镜铁律（都是为了绕开模型的短板）

| 铁律 | 问题 | 做法 | 校验 |
|---|---|---|---|
| **动作安全区** | 多人肢体交互（拥抱/打斗/递物/牵手）是**穿模与肢体融合的重灾区**，模型会把两条手臂融在一起 | 改用**景别切换 + 反应镜头**：特写手指停住、特写对方表情、特写两只手之间那段没碰到的距离。真要接触就压在特写/中近景里完成，别用远景交代全身交互 | 多人同框 + 动作含交互词 → 自动警告并给出替代建议 |
| **情绪落点用稳镜头** | 运镜越花，越看不清脸；而全片最需要看清脸的就是那句关键歌词 | 副歌第一句 / Bridge 最高音配**固定机位或极缓推移**（`motion_intensity = 1`）；环境镜头、转场、鼓点密集处才放开到 3 | 写入规划约束（软性创作建议） |
| **地点要成资产** | 同一个地点在多个镜头里各自生成 → 巷子宽窄、灯位、积水颜色都会漂 | 见 1.2 / 2.4 | `scene_id` 引用有效性 |

另外 `shot.transient_state` 与 `shot.speed` 也是本版新增：前者是"天气"专用通道（淋湿的头发、
敞开的衣领），后者控制整段拍摄速度（`normal / slow-motion / fast-motion`）。
两者都进首帧的 `SHOT-LOCAL STATE` 块，**绝不混进身份描述**。

## 阶段 2：角色素材 + 生图 `images.js`

```bash

  --sheet-candidates 2 --identity-min 70 --identity-retries 2 --keys "sk-aaa,sk-bbb"
```

> 若有多个项目，脚本会**列出候选并要求你显式指定**，而不是猜一个——静默选错片子比报错更贵。

### 2.1 角色资产：三步走，每一步都依赖上一步

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | `02_images/ref_charsheet.png` | **角色资产设定表** —— 全片人物身份的唯一真源 |
| 2 | `02_images/character_lock.json` | **结构化身份参数 + 创意档案** —— 视觉反读的五官/发型/服装层次 + 规划器的表情库/动作/场景气质 |
| 3 | `02_images/ref_face.png`、`ref_body_<角度>.png` | 面部特写 + 各角度白底全身参考图（均由**面部特写**派生，见铁律一） |
| 4 | `02_images/ref_style.png` | 风格基调板（无人物），锁定色彩/光线/质感 |
| 5 | `02_images/ref_scene_<id>.png` | **地点锚点**：每个反复出现的地点一张**无人空镜**，锁定空间/材质/光位/色调（见 2.4） |
| 6 | `02_images/shot_S01.png` … | 逐镜头首帧（含主角的会过身份核验，并单独注入表情块） |

**第 1 步：为什么是"一张设定表"而不是"定妆照"**

设定表 = **一次生成**里按上下两带排布：

```
┌──────────────────────────────────────────────────┐
│ 上带 ~62%                     │                  │
│  ┌──────────────┐             │  正面 / 侧面 / 背面  │
│  │  大胸像特写    │             │  三个全身站立视图    │
│  └──────────────┘             │                  │
├──────────────────────────────────────────────────┤
│ 下带 ~30%   微笑  │  害羞  │  委屈  │  开心         │
│            四个表情头像（同一张脸，同框同构图）        │
└──────────────────────────────────────────────────┘
```

纯色影棚背景、无文字、共**七格同一个人**。关键收益：

- **一次生成内部天然自洽** —— 三视图与表情带共用同一张脸，而跨图生成做不到。
- **身份只需要跨越"一次跳转"** —— 下游全部从这张表派生，而不是"半身照 → 全身照 → 镜头"的链条。
- **表情一并定下** —— 情绪范围在第一步就被画出来，而不是等到写分镜时临时指定。

版式由 `--sheet-layout` 控制：`sheet-full`（默认，大特写 + 三视图 + **表情带**）、
`sheet`（只要大特写 + 三视图）、`turntable`（8 方向全身转台）。
`--sheet-candidates` 个候选**由视觉模型逐个打分，自动留下最好的那个**
（打分维度：七格是否同一张脸、视图是否齐全、**表情带是否存在**、发型结构是否可读、
服装层次是否可读、服装是否一致、背景是否干净、有没有文字、五官是否清晰；
"不是同一张脸""画面有文字""人体畸变"属于硬性否决；缺表情带只扣分不否决）。
落选候选保留为 `_sheet_rejected*.png` 供人工复核。

**第 2 步：为什么要把参数"从真实图片反读出来"**

规划器写的是它**想象**的长相，图像模型画的是它**实际**画的长相。如果下游提示词一直复述规划器的文字，
而参考图上却是另一张脸，**两个锚点在互相打架**，人物必然漂移。
所以用视觉模型读回设定表，输出可逐字复用的结构化参数：

```
五官     face_shape / eye_shape / iris_color / eye_spacing / eyebrows / nose / lips / jaw_chin / skin_tone
发型结构  hair_structure（长度+分缝+刘海+卷度+层次）/ hair_color
服装层次  wardrobe_layers{inner,outer,bottoms,footwear,accessories,materials} / garment_palette / wardrobe
体型     physique / distinctive_marks
```

文字与画面从此刻起是**对齐**的，这是稳住一张脸的根本。
结果写入 `character_lock.json`（`--force` 可强制重读；视觉不可用时会回退到规划器的参数，并在日志中注明来源）。
**`expression_bank` / `signature_actions` / `scene_affinity` 三项在旁边一并保留** —— 它们读不出来，
只能来自规划器（见 1.1 的字段分工）。日志里会打印一行"角色档案"摘要，一眼看出哪些维度定全了。

**第 3 步：为什么要派生"多角度白底参考图"**

每个镜头在生成时，会按 `characters_view`（规划器为每个镜头标注的主角朝向：
`front / three-quarter-left / three-quarter-right / side-left / side-right / back`）
**挑选同角度的全身参考图**，外加面部特写，一起作为多图输入。

原因很直接：**参考图的构图越接近镜头要画的东西，模型就越不需要"编"。**
把 1:1 半身照喂给 16:9 全身远景，模型必须同时重新发明体型和脸——这是实测漂移最大的单一原因。
参考图统一用 `9:16` 竖构图（`--ref-ratio`），让站立人像在画面里尽量大、细节尽量多。

### 2.2 逐镜头身份门禁（本版新增的关键机制）

每张含主角的首帧提示词按固定结构拼装，**每一类信息各占一块、互不掺杂**：

```
IDENTITY — …（「不可变」字段：五官 / 发型结构 / 肤色 / 体型；刻意不含服装）
SHOT-LOCAL STATE — …（本镜专属：本场服装 / transient_state / 拍摄速度；没有声明时不出现）
REFERENCE HANDLING — 逐张点名每张参考图的唯一用途
  • images 1 and 2 — the AUTHORITATIVE source for FACE / hair / skin / proportions
  • image 3       — the LOCATION anchor：只取空间、材质、光位，里面没有人，不要去找脸
  • NONE may dictate this frame's shot size / camera angle / composition
PRECEDENCE — 身份描述永远优先于下文任何顺带提到的湿发、风吹、衣领
SHOT: …（本镜头的环境、动作、构图）
EXPRESSION — the face in this frame carries exactly this emotion: …（仅当 shot.expression 有值时出现）
FRAMING / LIGHT / GRADE — …
CORRECTION FROM THE PREVIOUS ATTEMPT — …（仅重画时出现）
IDENTITY RE-CHECK — …（结尾再次强调是同一人，并说明服装以 SHOT-LOCAL STATE 为准）
```

**为什么身份要拆成两块（这是本版最重要的结构改动）**

一张角色卡里同时写着"骨相"和"天气"时，模型没有依据判断哪些词是架构、哪些词是临时状态，
于是它把两者一起重新诠释 —— 这就是换脸的起点。所以字段被强制分成两桶：

| 桶 | 字段 | 变化频率 | 注入方式 |
|---|---|---|---|
| **不可变身份** | 五官 / 眼型眼距 / 瞳色 / 眉鼻唇 / 下颌 / 肤色 / **发型结构** / 发色 / 体型 / 辨识特征 | 全片恒定 | 进 `IDENTITY` 块 |
| **本场可变** | 服装（`wardrobe` 或逐镜 `wardrobe_override`）/ `transient_state`（被雨淋湿、衣领敞开、颧骨擦伤）/ `speed`（拍摄速度） | 逐镜声明 | 进 `SHOT-LOCAL STATE` 块 |

`shot.transient_state` 是给"天气"准备的专用通道。把淋雨写进身份描述，就不只是描述错位，
而是给了模型一个换人的理由；写进 `transient_state`，它只会淋湿同一个人。

生成后，每张含主角的首帧连同参考图一起送回视觉模型做一次核验，返回：

```json
{ "same_person": true, "score": 92,
  "differences": ["眉形比参考图更粗", "发尾长度略短"],
  "has_readable_text": false, "protagonist_count": 1, "other_people_prominent": false }
```

- `same_person == true` **且** `score >= --identity-min`（默认 70）→ 通过。
- 不通过 → 把 `differences` 变成一段 `CORRECTION FROM THE PREVIOUS ATTEMPT` 明确指令，
  **重新生成**，最多 `--identity-retries` 次（默认 2）。
- 全程**只保留得分最高的那次**，落选的存为 `shot_S01.att2.png` 供比对。
- 画面文字的检测也顺手做掉了（这正好覆盖"霓虹招牌写出字"的老问题）。
- 空镜（不含人物）走另一条检查：确认**没有文字**、**没有人**。

阶段结束会打印一张一致性报告表，并把明细写入 `02_images/identity_report.json`；
低于阈值的镜头会明确点名，提示用 `--only S0X --force` 复检。

> **视觉链路的一个实测坑**：`agnes-3.0-flash` 文档说图片用"公网 URL"传入，但上游拉图有 **3 秒读超时**，
> 实测 3 次里有 1 次失败（2K PNG 约 1MB）。因此本 skill 的做法是
> **本地降采样到 768px 的 JPEG、以 base64 data URI 发送**（见 `lib/imgutil.js`），
> 实测 3/3 稳定，约 150 image tokens/张。降采样反而对任务有利：身份比对关心的是五官比例，不是毛孔。

### 2.3 两条踩坑换来的铁律（对任何图像生成流水线都成立）

这两条是本次调试中代价最大、也最反直觉的发现，值得单独记住。

**铁律一：参考图的"结构"会被继承 —— 多格输入必然产出多格输出**

把角色设定表（本身是 4 格拼贴）当作参考图去生成"单张全身照"，结果是
**15 次尝试、5 个角度、每张都带重试，全部返回了拼贴图**。模型忠实地复制了输入的结构。

改为**从单主体的面部特写派生**（单张人像输入）之后，同样的提示词立刻返回
**评分 100 / 100 / 98 的单张全身棚拍**。

> 结论：**参考图必须与期望输出的"结构"一致**。想要单张，就喂单张。
> 设定表只用于「人工审查 + 反读五官参数」，不要直接当生成参考图。

**铁律二：反向提示词会反噬 —— 写出"不要什么"就是在提示"要什么"**

第一版提示词为了保险，写了一大串否定：
`NOT a reference sheet / no panels / no collage / no inset thumbnails / reject these outcomes...`
结果**每一张都变成了拼贴图**——即使输入已经是一张干净单人人像。

改成**只描述画面"是什么"**（"一张全身棚拍照片""一个人占据画面""头顶与鞋底都在画内"），
把 `collage / split screen / contact-sheet / panel` 这些词从提示词里**全部删掉**，问题消失。
`EXCLUSION_SUFFIX` 也因此被收窄，只保留"没有文字"和"没有第二个人"这类安全项。

> 结论：**负向约束优先用"正向的构图描述"来表达**，实在要写否定，也只写"安全"的否定项
> （文字、水印、多余人），不要把排版类缺陷名词写进提示词。

**铁律三：门禁要能"说出差异"，而不只是"打个分"**

有效的一致性质检必须返回**可执行的差异清单**（"下颌线比参考图更宽""发色偏蓝紫"），
因为这份清单会直接变成下一次生成的修正指令。只给一个分数的门禁无法自愈。
本 skill 的 `compareIdentity` / `auditStudioRef` / `scoreCharacterSheet` 都强制要求模型列出
`differences` / `issues`，并在重试时把清单注入提示词 —— 这是"自动重画能成功"的原因。

**每个 PNG 都会生成一个 `.url` 旁挂文件记录公网 URL** —— 这一步是整条流水线的关键枢纽：
Agnes 图像 API 返回的 `https://cos-platform-outputs.agnes-ai.cn/...png` 是**公开可访问**的，
所以不需要任何外部图床就能把图片喂给视频 API。实测可直接 200 拉取。

**为什么所有参考图都必须是"纯净背景"（重要设计决策）**
参考图会被当作**图生图输入**回喂给镜头，这意味着**它里面的一切都会被带过去**：布景、招牌、光位、机位。
实测教训：第一版定妆照生成在霓虹街道上，结果后续一个描述完全不同的镜头里出现了**一模一样的店铺招牌**（连文字都一样）。
因此设定表与所有角度参考图强制：纯色无缝影棚背景、均匀正面柔光、无彩色光、无道具、无文字，且不套用全片场景风格词。
同时提示词里明确写出**优先级**：身份参数永远压过镜头描述里顺带提到的"头发湿了""衣领"等临时状态，
避免模型把临时状态当成换脸的理由。

其他能力：`--only S01,S05` 单张返工、`--force` 全量重做、断点续跑（已存在的自动跳过）、
生成后自动校验 URL 公网可达、`--no-verify` 关闭全部视觉检查（更快但失去身份门禁）。

### 2.4 地点锚点：让"同一个地方"真的是同一个地方

人物一致性解决的是"是不是同一个人"。**地点一致性是另一条独立的漂移线，而且更隐蔽** ——
观众不会说"这条巷子变了"，只会觉得"这不像一个片子"。

三个镜头都写在"雨夜霓虹街头"，就是三次独立生成。只靠文字描述，
巷子的宽窄、灯的位置、地面积水的颜色、主光的方向都会在镜头之间悄悄变化。

解法是把地点也变成**资产**（一致性 = 共享可复用资产 + 显式引用，这一点在多个外部项目里被反复验证）：

```
plan.js    scenes[] 里定义 2-4 个反复出现的地点（空间 / 材质 / 光位 / 色调）
           每个镜头用 scene_id 引用 —— 含主角的镜头与空镜都要填
                        ↓
images.js  为每个被引用的地点生成 1 张【无人空镜锚点图】ref_scene_<id>.png
           门禁：零人物 / 非拼贴 / 空间可辨 —— 出现任何清晰人物即硬失败，带缺陷重画
                        ↓
每个镜头的参考图 = [ 角色全身(同角度) , 角色面部 , 地点锚点 ]
           身份在前、地点在后，提示词里逐张点名每张图的唯一用途
```

四条设计要点：

- **锚点图必须是空的。** 场景参考图里只要有一张脸，它就会和角色参考图抢画面控制权 ——
  这正是"多格输入必然产出多格"的同一种冲突。
- **锚点对空镜同样有效。** 不含主角的环境镜头也挂上地点锚点，于是第 4 镜的巷子和第 2 镜是同一个巷子。
- **场景越少越好。** 每新增一个地点就多一张锚点图、多一份光照一致性风险。
  校验器会警告"已定义但没有任何镜头引用"的场景 —— 那是白花的成本。
- **只在某句歌词里闪过一次的地点不要建场景**，直接把环境写进 `keyframe_prompt` 即可。

关掉它：`--no-scenes`。分镜里没有 `scenes[]` 时（旧项目）行为与旧版完全一致。

## 阶段 3：图生视频 `videos.js`

```bash
node "<skill-dir>/scripts/videos.js" --project "./mv-夜曲" --mode keyframe --concurrency 3 --keys "sk-aaa,sk-bbb"
```

**默认 `--mode keyframe`：`first_frame` = 我们生成的首帧。**
这是「画布统一 + 人物不漂移」最可靠的做法——片段的**第 0 帧就是那张图**，构图、色彩、服装、光线全部锁死。
- `--chain`：同一段落内相邻镜头再传 `last_frame = 下一镜首帧`，让镜头之间融为一体。
- `--mode reference`：把角色定妆照和首帧一起作为 `images[]`，提示词里用 `<Picture 1>`/`<Picture 2>` 指代，
  适合有大幅动作、需要身份强引导的镜头（注意：reference 模式**可能重新构图**）。

**解决「画面不动」——两层防线**

第一层 **提交前提示词校验**（`lintMotionPrompt`）：
逐条检查 `video_prompt` 是否写了①摄影机运动 ②主体动作 ③环境次级运动，缺哪项自动补哪项，
再追加"整段画面始终处于连续、自然的运动中，严禁静止帧、严禁定格"以及排除文字/水印。

第二层 **生成后客观运动量检测**（`motionScore()`）：
下载后用 ffmpeg 按 4fps 抽帧、缩到 64×36 灰度，逐帧计算相邻帧平均绝对差，得到运动量分数：

| 分数 | 判断 |
|---|---|
| < 0.9 | 基本是静止图 |
| 0.9 – 1.2 | 运动过弱（默认阈值 `--motion-min 1.2`） |
| > 1.2 | 运动可见，通过 |
| > 6 | 强运动（跟拍/摇臂/快切） |

低于阈值会**自动用强化版运动提示词重新生成**（最多 `--motion-retries` 次）。
这是一道**客观门禁**，不靠"看起来还行"来判断。

**第三层防线：一镜多拍，自动留最好的一条**（`--candidates N`，默认 1）

前两层解决"不达标就重做"，但同一条提示词本来就会产出**质量不同的多条结果**——
这正是"10701 张图里挑 107 张"那种筛选意志可以被自动化的地方。加上 `--candidates 3`，
脚本会为每个镜头生成 3 条，逐条测运动量，**保留运动量最高的一条**并把其余删掉：

```
S03 3 条候选运动量: 2.41 / 0.83 / 1.96  → 保留 2.41
```

- 默认 1 条不变（行为和账单都与旧版一致）；只有在困难镜头（快动作、面部特写、复杂运镜）上才值得开。
- 视频成本≈ ×N，所以推荐**只对个别镜头开**：`--only S03,S07 --candidates 3`。
- 选优规则刻意选"最活的"而不是"最接近某个中位数"：本阶段要防的失败模式就是**不动**。

**提交前的镜头就绪预检**

在投放任何任务之前，脚本会打印一张就绪表，把"素材齐不齐"从运行中意外变成事前可见：

```
  shot   首帧     参考        场景    时长    状态
  S01    ok      角色(身+脸)  SC1     6.0s    READY
  S03    ok      场景         SC1     6.0s    ok
  S05    MISSING -            SC2     6.0s    首帧缺失
```

检查项：首帧是否有公网 URL（视频 API 读不到本地文件）、时长是否落在 API 区间、
分镜里声明的地点是否真有锚点图。不齐的镜头会被跳过并在结尾以 `SHOTS_NOT_READY=` 报出。

**关于 API 的硬限制**（`agnes-video-2.5-flash`）
- `size` **只能是字符串 `"720P"`**，其他值直接 400。
- 画幅用 `aspect_ratio` 选：`16:9`→1280x704、`9:16`→720x1280、`1:1`→720x720、`4:3`→960x720、`3:4`→720x960、`21:9`→1680x720。
- `seconds` 为字符串 `"4"`–`"12"`，`n` 固定 `1`。
- reference 模式：`images` ≤ 5 张、`audios` ≤ 3 段，**不支持 `videos`**。
- **不支持** `width/height/fps/num_frames/num_frames/quality/steps` 等字段（传了会 400）。
- 查询结果用 `video_id` + `model_name=agnes-video-2.5-flash`；**完成后的下载地址在顶层 `url`**（也兼容 `metadata.url`）。

## 阶段 4：组装 `assemble.js`

```bash
node "<skill-dir>/scripts/assemble.js" --project "./mv-夜曲" --transition dissolve --fade --normalize-audio
```

**这一步决定成片是否「不丢帧、不跑偏」**，算法刻意以**帧**而不是秒为单位：

1. **画布统一**：取所有生成片段的**众数分辨率**作为组装画布（默认即 Agnes 原生输出尺寸，
   不放大不失真）。每个片段 `scale`（保持宽高比，强制偶数对齐）→ `pad`（居中补边）→ `setsar=1`，
   所以既不会拉伸变形，也不会因为奇偶尺寸导致色度错位。
2. **时间轴**：`总帧数 = round(歌曲时长 × fps)`，再按各镜头时长用**最大余数法**把总帧数分配到每个槽位，
   保证**各槽位帧数之和精确等于总帧数**。因为每个槽位都切成整数帧、整数之和又精确，**拼接不可能累积漂移**——
   这是防「图像和声音慢慢对不上」的根本手段。
3. **切片**：每段重编码为**恒定帧率**并切成精确帧数。片段比槽位短时，用 `tpad` **克隆末帧补足**，
   而不是截断音乐。
4. **拼接 + 混流**：拼接时**整体重编码**（单一连续 GOP，避免 stream-copy 的时间基错位）。
   然后**把原声混进去**：优先 `-c:a copy`，**原声字节不动、不重新生成、不被模型音频替换**。
   刻意**不用** `-shortest`，而是把画面用 `tpad` 补到**恰好等于歌曲长度**，保证音乐永远完整。
5. **校验**：解码成片并逐项检查（见下表），任一不过会以退出码 3 结束。

**交叉溶解**（可选）：`--transition dissolve --transition-duration 0.5`。
帧数账同样是精确的——除了最后一镜，每个槽位多切 `overlap` 帧，第 k 次 `xfade` 的 `offset`
取累计槽位时间减 `transitionDuration`，因此溶解后**总长仍精确等于 `总帧数`**，不会破坏同步。
若某个环节失败会自动**回退到硬切**并明确告知，绝不让同步性出问题。

## 阶段 5（可选）：歌词字幕烧录 `subtitles.js`

纯本地 ffmpeg 操作，**不消耗任何 API 额度**。时间轴来自项目 `00_source/` 内歌词副本：
LRC 时间戳 → 逐句精确对齐；纯文本歌词 → 按片长均分（前奏约 8s 内不出字）。

```bash
# 项目模式（默认读 05_output 里最新成片，歌词取 00_source 副本）
node "<skill-dir>/scripts/subtitles.js" --project "./mv-夜曲"

# 只导出 SRT 外挂字幕，不烧录
node "<skill-dir>/scripts/subtitles.js" --project "./mv-夜曲" --srt-only

# 直连模式：任意视频 + 歌词
node "<skill-dir>/scripts/subtitles.js" --video "成片.mp4" --lyrics "歌词.lrc" --out "成片_字幕.mp4"

# 微调：字号 / 单句最长挂屏 / 全局偏移
node "<skill-dir>/scripts/subtitles.js" --project "./mv-夜曲" --font-size 40 --max-line 6 --offset 0.3
```

- **样式**：`--style gold`（默认，亮鎏金字 + 黛青描边）或 `--style pink`（桃粉字）；字体 `--font 楷体`（Windows 自带，可换 `Noto Serif CJK SC` 等）；逐句 `\fad(250,250)` 淡入淡出。
- **版式**：默认小号单行——字号 `playResY/28`（720x1280 下 46px），`WrapStyle: 2` 不自动换行，左右边距 48px，可用 `--font-size` 覆盖。
- **行尾封顶**：单句最多挂屏 `--max-line` 秒（默认 8s），间奏期旧歌词自动消失，不再一直挂到下一句开头（旧版会挂 20s+ 造成"字幕不同步"观感）。
- **对齐微调**：若整体偏移可用 `--offset ±秒` 平移全部字幕。
- **LRC 时间戳可信度**：AI 估算的 LRC（如 Suno 生成歌曲自配时间戳）可能与真实音频差到 10s 级，**不要直接信任**。用 `scripts/whisper_align.py` 做 ASR 实测对齐：

  ```bash
  # 依赖: faster-whisper（pip install faster-whisper；模型 small ~460MB，走 hf-mirror）
  # 用法: whisper_align.py <音频> <歌词.txt|lrc> <输出.lrc> <报告.txt> [hf_endpoint] [模型目录或名称]
  python scripts/whisper_align.py song.mp3 lyrics.txt lyrics_aligned.lrc report.txt \
      https://hf-mirror.com "C:/Users/<user>/.cache/whisper-small"
  # 产物 lyrics_aligned.lrc 放入项目 00_source/（.lrc 优先于 .txt 被 subtitles.js 读取）
  ```

  原理：faster-whisper 转写（initial_prompt 注入歌词文本做偏置）→ 歌词行与识别段做
  "允许多行共段的单调 DP"匹配 → 词级时间戳定位行首 → 未命中行邻句插值 → 输出标准 LRC。
  实测对本项目 Suno 歌曲：原估算 LRC 主歌整体早了约 10s，对齐后逐句命中。
- **产物**：`04_build/<成片名>.srt`（外挂备用）+ `04_build/<成片名>.ass` + `05_output/<成片名>_字幕.mp4`（视频重编码 CRF18，音频字节直通）。
- 烧录后建议跑一次 `verify.js --file <字幕版>` 复查帧连续性与音画同步。

## 质量门禁

`assemble.js` 自动执行，也可随时用 `verify.js` 复查：

```bash
node "<skill-dir>/scripts/verify.js" --thumbs 12
```

| 门禁 | 检查内容 | 对应痛点 |
|---|---|---|
| `has-video` / `has-original-audio` | 视频流 + **原声**音轨都存在 | 声音一致性 |
| `constant-frame-rate` | 输出为恒定帧率（CFR） | 丢帧 / 撕裂 |
| `square-pixels` | SAR = 1:1 | 画布不协调 |
| `frame-continuity` | 解码帧数 ≈ fps × 时长（容差 1 帧） | 丢帧 / 重复帧 |
| `no-audio-truncation` | 视频不短于歌曲（漂移 ≤ 0.15s） | 图音不同步 |
| 逐片段 `canvas` | 每段分辨率 == 成片画布 | 画布不协调 |
| 逐片段 `motion` | 运动量 ≥ `--motion-min` | 画面不动 |

## 标准工作流（强烈推荐按此执行）

> 下面提到的相对路径（`storyboard.md`、`ref_charsheet.png`、`identity_report.json` …）都在
> 当前会话工作目录下的 **`out/mv-<歌名>/`** 之内。

1. **确认输入**：歌曲文件路径 + 歌词（有 `.lrc` 就用，时间同步最准）+ 一段创作要求（`--brief`）+ 风格倾向（`--style`）。缺歌词就问用户要，或确认走纯器乐叙事。
2. **只跑阶段 1**：`plan.js`，然后 **Read `storyboard.md`**，把主题/故事/主角设定/**地点资产表**/风格/镜头数展示给用户确认。**这一步不要跳。**
   顺带扫一眼结尾的校验警告：场景是否被引用、有没有"多人肢体交互"镜头需要改成分镜表达。
3. **跑阶段 2**：`images.js`。**先 Read `ref_charsheet.png`**（这是身份真源，七格必须是同一张脸、
   背景必须干净无文字），再 Read `ref_scene_*.png` 确认**里面没有人**、空间光位清楚；
   然后看 `identity_report.json` 里的一致度是否达标，Read 2–3 张 `shot_*.png` 与参考图对照，确认是同一个人。
   任一镜头被点名低分，用 `--only S0X --force` 重画首帧。
4. **跑阶段 3**：`videos.js`。**投放前先播报预算**：向用户报告本次视频调用总量
   （镜头数 × 各镜 `api_seconds`，720P 刊例价约 ¥0.06/s；Agnes 限时免费期实际 ¥0，但仍受
   限流约束、视频约 1 次/分钟），确认后再投放（预算防线：先确认，后花钱）；
   然后看**就绪预检表**（有 `MISSING` 就先回去补素材，别浪费视频额度）；
   再留意 `LOW_MOTION=` 行。困难镜头（快动作、面部特写、多人同框）可 `--only S03 --candidates 3` 多拍几条挑最好的。
5. **跑阶段 4**：`assemble.js`，确认所有门禁 PASS。
6. **复查**：`verify.js --thumbs 12`，**Read 缩略图**，检查画面连贯性、色调统一、无明显穿帮。
7. **交付**：用 `present_files` 把成片 MP4 给用户，并附一句话说明（时长、画幅、镜头数、转场方式）。

| 项目 | 实测值 |
|---|---|

## 已知局限

1. **霓虹/商业街景里可能残留画面文字。** 图像模型对"霓虹招牌"有很强的生成文字先验，提示词排除只能减轻。
   已通过让规划器改用"抽象发光色块/光带/光晕/bokeh"来规避，但无法根除。
   挑片时优先选字少、字处于焦外虚化的镜头；或在 `--brief` 里明确要求"避免商业街区，用自然光或室内场景"。
2. **视频 API 单段上限 12 秒、下限 4 秒**，`size` 固定 720P。因此 4K 交付需要外部超分，本流水线不做。
3. **`reference` 模式可能重新构图**，对画布一致性的控制弱于 `keyframe`。需要严格构图一致时请用默认的 `keyframe`。
4. **音频参考需要公网 URL**。`--audio-ref` 只能接受可公开访问的音频链接；本 skill 不内置音频上传。
   常规做法是把原声交给最后的 ffmpeg 混流阶段，同步效果更可靠。
5. **人物一致性依赖首帧质量。** 若某镜头的首帧就把人画错了，视频只会忠实地把这个错误动起来——
   发现后应立刻 `images.js --only S0X --force` 重画首帧，而不是反复重跑视频。
   现在这道防线已被自动化：`identity_report.json` 会直接点名未达标的镜头并给出重跑命令。
6. **`--text-strict` 默认关闭。** 因为模型对"霓虹招牌"有极强的生成文字先验，若把"出现文字"一律判为失败，
   城市夜景镜头可能反复重试仍不达标。默认策略是**记录并报告**（`identity_report.json` 里能看到每张图
   检出的文字内容），需要严格无文字交付时再开 `--text-strict`，并配合 `--brief` 要求避开商业街区。
7. **"路人"判定为「醒目才算失败」。** 远景街景天然会有虚化行人，因此门禁只把
   **主角不是恰好 1 个**、或**配角醒目（面部可辨认 / 占画面比例大）**判为失败。
8. **角度参考图可能被整体丢弃。** 若某个角度连续多次都通不过「单人 / 非拼贴 / 头到脚」校验，
   脚本会**删掉该参考图**而不是留一张坏图（坏参考会污染所有同角度镜头），
   下游自动回退到 `front` 或面部特写。日志里会明确打印 `[drop]`。
9. **设定表从 4 格变 7 格，一致性难度上升。** 表情带让设定表多了 3 张脸（大特写 + 三视图 + 4 表情 = 7 格），
   模型要在同一张图里画 7 次同一个人。实测通常可行，但若候选普遍掉分，可退到 `--sheet-layout sheet`
   （回到 4 格），表情库仍可用——它本来就是文字字段，不依赖设定表把表情画出来。
10. **表情库的英文描述由规划器写，没有视觉校验。** 「害羞」「委屈」这类情绪定义本来就是主观的，
    无法像五官那样客观比对；本流水线只保证**它们与长相互不污染**，不保证"这张脸害羞起来一定好看"。
11. **标志动作与场景气质只是约束，不是门禁。** 规划器被要求遵守，但生成端没有检测"这个动作是否
    属于 signature_actions"。若发现人物行为不连贯，先看 `storyboard.md` 里这两个字段是否写得太虚。
12. **地点锚点锁的是"空间/材质/光位"，不是像素级复刻。** 锚点图给模型的是一个可参照的空间与光照，
    不是把镜头背景替换成锚点图。同一地点在不同镜头里仍可能有视角与陈设细节的差异，
    但会明显收敛到"同一个地方"。需要严格复刻时用 `--chain` 让相邻镜头首尾帧接力。
13. **肢体交互门禁只做"文本层"识别。** 校验器靠 `subject_action` / `visual` 里的词判断风险，
    它不会阻断生成，只给警告与替代建议。真正的穿模仍然要靠出片后人工挑选
    （这也是 `--candidates` 存在的理由：多拍几条，挑没穿模的那条）。
14. **`scenes[]` 需要规划器主动产出。** 若某个模型偷懒没写 `scenes[]`，本版会**降级为旧行为**
    （每个镜头各自生成场景）并给出警告，而不是报错——因为锚点缺失是质量问题，不是可执行性问题。

## 常见问题与真实坑点

| 现象 | 原因 | 处理 |
|---|---|---|
| 轮询返回 HTTP 429「查询过于频繁」 | 账号级频率限制，轮询过快 | 脚本已内建退避（默认 8s，遇 429 递增至 30s）。属正常，不要当成失败 |
| 视频创建返回 400 `size must be 720P` | 给 flash 传了 `"1080P"` 或像素尺寸 | 只用 `"720P"`，画幅用 `aspect_ratio` |
| 400 提示不支持某字段 | 传了 `width/height/fps/num_frames/steps` | 这些字段不被支持，删掉 |
| 图片无法作为参考图 | 传了本地路径 | 视频 API 只收**公开 URL**。用本 skill 生成的图会自带 `.url`，直接用 |
| `num_frames must follow 8n+1` | 用的是旧版接口参数 | `agnes-video-2.5-flash` 用 `seconds`，不用 `num_frames` |
| 生成的片段像静止图 | 提示词没写运动 | 已被 `lintMotionPrompt` + `motionScore` 双保险覆盖；也可调高 `--motion-min` 并针对 `--only` 重跑 |
| **人物长相在不同镜头间漂移** | ①参考图信息量不足 ②身份描述被长提示词稀释 ③参考图与镜头尺度不匹配 ④没有任何客观检查 | 已系统性修复：角色设定表锁真源 → 反读结构化五官参数 → 派生**同角度**白底全身参考 → **逐镜身份门禁 + 带差异自动重画**。若个别镜头仍不过，看 `identity_report.json` 的差异清单，再 `--only S0X --force` |
| 派生的参考图变成了"多格拼贴" | 参考图自身是多格设定表，模型会复制输入的**结构** | 已修复：全身参考图改为从**单主体面部特写**派生；提示词也不再出现 `sheet / panel / collage` 等词（见 2.3 两条铁律） |
| 首帧里出现了两个人 | 模型把"女性主体"渲染成了并排双人；街景远景也会带入路人 | 门禁会区分「主角出现次数」与「配角是否醒目」：主角≠1 一律失败，配角只有**醒目**才算失败 |
| 参考图背景/光线泄漏到镜头里 | 参考图的一切都会被 i2o 带过去 | 已修复：所有参考图强制纯净影棚背景 + 无文字；提示词显式声明"只取身份，不复用参考图的背景/光线/机位/构图" |
| 画面出现了文字 | 模型对"霓虹招牌"有很强的生成文字先验 | 规划器被要求用"抽象发光色块/光带/光晕/bokeh"替代招牌类词汇；门禁会**检出并报告**文字内容。需要严格无文字时加 `--text-strict`。**这是已知的残留局限** |
| `--skip-refs` 后人物就不一致了 | 旧行为是彻底跳过参考图逻辑 | 已修复：`--skip-refs` 现在会**复用磁盘上已有的角色素材**，只跳过重新生成 |
| 每个镜头里的主角"像重新介绍了一遍" | 人设没定全，规划器边写镜头边临时决定服装/表情/场景 | 已修复：改为**先把七个维度定全再写分镜**（见 1.1）。规划结束会打印角色档案摘要；加 `--strict-profile` 可强制 |
| 同一张脸在不同镜头里情绪不稳定 / 表情把脸带跑了 | 情绪与长相混在同一个提示词字段里，互相污染 | 已修复：表情提为独立字段 `expression_bank` + `shot.expression`，以独立 `EXPRESSION` 块注入，并明确声明"表情只动肌肉不动骨相" |
| 设定表缺了表情带 | 图像模型只画出了 4 格 | 不否决（只扣 12 分）；日志会提示。可 `--force` 重出设表，或 `--sheet-layout sheet` 明确表示不需要表情带 |
| 拼接后音画逐渐错位 | 槽位不是整数帧 | 本 skill 用整数帧分配 + 全程重编码，已规避；不要改用 `-c:v copy` 拼接 |
| 成片比歌曲短 | 用了 `-shortest` | 本 skill 刻意不用 `-shortest`，而是把画面补到歌曲长度 |
| 输出文件 0 字节 | 工作区可能清空非只读文件 | 重跑对应阶段；必要时对成片设置只读属性 |
| **同一个地点在不同镜头里长得不一样** | 地点只有文字描述，没有共享资产 —— 三个镜头就是三次独立生成，巷子宽窄/灯位/积水颜色都会漂 | 已修复：规划器先在 `scenes[]` 定义地点，系统生成**无人空镜锚点图**，该地点的所有镜头（含空镜）都挂上它。见 1.2 / 2.4 |
| **两个人在画面里抱在一起 / 手融进对方手臂** | 多人肢体交互是 i2v 模型的结构性短板 | 校验器会警告并建议改用「景别切换 + 反应镜头」。出片阶段用 `--only S0X --candidates 3` 多拍几条挑没穿模的 |
| **换了件外套 / 淋了雨之后，人的脸变了** | 服装与临时状态被写进身份描述里，模型无法区分"架构"与"天气" | 已修复：身份被拆成**不可变**与**本场可变**两桶；淋雨、敞领、擦伤走 `shot.transient_state`，换装走 `wardrobe_override`，都不进 `IDENTITY` 块 |
| **同一地点镜头挂上锚点后人物反而变差** | 参考图里若含人物，会与角色参考图抢画面控制权 | 锚点图门禁把"出现任何清晰人物"判为硬失败并重画；参考图顺序固定为「身份在前、地点在后」，提示词逐张点名用途 |
| **产物写进了技能安装目录 / 不知道跑哪去了** | 旧行为把输出根挂在技能自身目录下 | 已修复：输出根锚定当前会话 cwd（`<cwd>/out/`，`lib/paths.js`）。固定输出根用 `CMV_OUT_DIR` |
| **`No project found in out.`** | `out/` 下还没有任何项目 | 先跑 `plan.js`；已有项目但报"多个项目"，用 `--project <dir>` 指定 |
| **项目复制到另一台机器后 `assemble.js` 找不到歌** | 旧行为只在 `project.json` 里存了原文件绝对路径 | 已修复：`plan.js` 会把歌复制进 `00_source/` 并只记录**相对项目**的路径；找不到时还可用 `--song` 覆盖 |
| 换成新机器后脚本报"绝对路径不存在" | 不应存在这种代码 | 这是回归缺陷。跑 `test/paths.js`，它会扫出源码里的盘符/用户名/home/`process.cwd()` |

## 参数速查

**plan.js**：`--song`（必填）`--lyrics` `--brief` `--style` `--aspect` `--shots` `--title` `--artist` `--lang` `--out`（默认 `out/mv-<歌名>`）`--max-repairs`
　└ **角色档案相关**：`--strict-profile`（要求七个维度全部定全，否则规划失败；默认只警告并用默认值兜底）

**images.js**：`--project`（可选，默认取 `out/` 下唯一项目）`--concurrency` `--size`（1K/2K/3K/4K，默认 2K）`--only` `--force` `--skip-refs` `--no-enhance` `--retries` `--check-url`
　└ **人物一致性相关**：`--sheet-candidates`（默认 2）`--sheet-layout`（默认 `sheet-full`，可选 `sheet`/`turntable`）`--angles`（默认 `front,3q-left,3q-right,side,back`）`--ref-ratio`（默认 9:16）`--identity-min`（默认 70）`--identity-retries`（默认 2）`--ref-retries`（默认 2）`--vision-max-px`（默认 768）`--text-strict` `--include-sheet` `--no-verify`
　└ **地点一致性相关**：`--no-scenes`（不生成地点锚点图；分镜无 `scenes[]` 时本就不生成）

**videos.js**：`--project`（可选）`--mode`（keyframe/reference）`--chain` `--concurrency` `--motion-min` `--motion-retries` `--candidates`（每镜生成 N 条、留运动量最高的一条，默认 1，成本 ×N）`--only` `--force` `--dry-run` `--skip-motion-check` `--audio-ref` `--seed` `--max-wait`

**assemble.js**：`--project`（可选）`--transition`（cut/dissolve）`--transition-duration` `--canvas`（auto/WxH）`--fps`（auto/24/30）`--crf` `--preset` `--fade` `--normalize-audio` `--audio-gain` `--thumbnails` `--allow-partial` `--song`（覆盖原声路径）`--output`

**verify.js**：`--project` 或 `--file` `--song` `--motion-min` `--thumbs` `--skip-motion` `--json`

**run.js**：接受以上大部分参数 + `--stage`（all/plan/images/videos/assemble）`--force-stage` `--dry-run`
　└ `--sheet-layout` 与 `--strict-profile` 会被透传到对应阶段

**环境变量**：

| 变量 | 作用 |
|---|---|
| `CMV_OUT_DIR` | 覆盖整个输出根（默认 `<cwd>/out`），用于换盘或挂到大容量目录 |
| `CMV_CHAT_TIMEOUT` | chat/规划请求超时毫秒数（默认 900000）。服务端高峰响应可能超 600s，超时可调大 |
| `AGNES_API_KEYS` / `AGNES_API_KEY` / `agnes-api-key` | 无 `--keys` 时的 Key 来源 |
| `FFMPEG` / `FFPROBE` | ffmpeg 不在 PATH 时指定可执行文件路径 |

所有阶段脚本都支持 `-h` 查看完整帮助。
