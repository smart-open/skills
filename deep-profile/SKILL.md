# 全网深度画像助手（deep-profile）

以个人或企业的极少量种子信息为起点，通过全渠道、全模态、全生命周期数据采集与语义融合，自动「扩展 → 关联 → 验证 → 推理 → 推演」，生成一个**可解释、可追溯、可对话**的深度身份画像，并落地为**单个自包含 HTML 报告**（含关系拓扑图、时间线、置信度评分与数字孪生推演）。

**核心逻辑骨架**：拒绝信息堆砌，以「**社会面具 — 核心矛盾 — 底层驱动**」为认知主轴，把一切采集到的数据注入三维认知矩阵，回答的不是「他有哪些标签」，而是「他为什么是这样、下一步会做什么」。

---

## 何时使用

- 用户要求「人物背景调查 / 公司尽调 / 反欺诈 / 招聘背调 / 合作方核实」
- 用户要求「客户画像 / 供应商风险评估 / 竞品与关键人物建模」
- 用户要求「深度画像 / 数字孪生 / 身份图谱 / 全网搜索某个人或公司」
- 用户给出一个姓名、手机号、邮箱、公司名、域名、社交昵称等种子，希望「查一查这个人/这家公司」
- 用户要求「核实这个人背景真伪 / 是否造假 / 做背调核验」（以核验视角贯穿画像报告，默认本人书面授权成立）

## 第一步：目标识别与输入解析

1. **判定实体类型**：个人 or 公司。
2. **提取结构化字段**：手机号、邮箱、域名、身份证号片段、统一社会信用代码、URL。
3. **提取非结构化实体**：姓名、昵称、地理位置、机构名、学校、职位。
4. **格式清洗**：邮箱统一小写、域名标准化、手机号补国家码、姓名生成拼音/英文名/昵称变体。
5. **生成初始「线索池」**：所有可扩展的检索词与待验证假设。
6. **图片种子**（如有）：触发 OCR、人脸检测、EXIF 提取（描述性处理，输出为线索而非硬结论）。

> **先判「公众度 / 数据丰度」，再定证据主轴**（对象分为：科技/商业 KOL 型、非公众从业者型、本人/工作区型，对应三种不同的可靠证据层与产出形态，详见 `references/methodology.md` 第七章）。判错型会把人硬挖成另一个人或虚构履历。
>
> **最低启动门槛**：1 个高置信度身份标识即可启动（LinkedIn 主页 URL、企业邮箱、天眼查链接、专利署名等）。若种子过于模糊（如仅有「张伟」），必须先进入「智能提问」做身份消歧（见下）。

## 八维数据源矩阵（概要）

| 维度 | 数据类型 | 典型来源 |
|---|---|---|
| ① 公开数字足迹 | 社交内容、新闻、博客、公开视频字幕 | 微博/知乎/小红书/B站/领英/X/GitHub、搜索引擎、新闻媒体 |
| ② 半公开结构化 | 工商、司法、知识产权、学术、招聘、开源 | 天眼查/企查查/裁判文书网/专利库/ORCID/GitHub |
| ③ 用户授权数据 | 邮箱收件箱、聊天导出、CRM、本地文档 | 用户上传、OAuth2.0、IMAP、本地文件 |
| ④ 设备与行为信号 | 浏览历史、APP 使用、搜索词 | 用户侧本地 Agent（仅上传脱敏特征） |
| ⑤ 多模态生物信号 | 演讲视频、会议照片、微表情/语速 | YouTube/B站/公开直播 |
| ⑥ 知识图谱补全 | 通用/行业知识、政策法规 | Wikidata/DBpedia/UMLS/政策库 |
| ⑦ 域名/IP/资产暴露面 | 域名、IP、子域名、端口、证书 | WHOIS/DNS/证书透明日志/Shodan/Fofa/ZoomEye |
| ⑧ 威胁情报/暗网 | 泄露库比对、黑市交易、钓鱼样本 | 威胁情报平台 |

> 详版见 `references/methodology.md`。**执行原则**：公开数据优先；授权数据仅在用户明确提供后使用并标注来源；跨源关联统一使用不可逆哈希标识符（如 `SHA-256(email+salt)`）作为节点，salt 本地生成。

## 核心工作流（八阶段）

| 阶段 | 动作 | 关键产出 |
|---|---|---|
| 0 需求确认 | 确认目标类型、用途与输出范围；**授权默认具备（招聘/背调/合作核实/反欺诈），不反复询问**；确认产出单一深度画像 HTML 及内嵌核验视角 | 明确用途、敏感度与核验基调 |
| 1 种子标准化 | 格式清洗 + 别名生成 + 图片 OCR/人脸/EXIF | 线索池 |
| 2 公开扩展 | 多引擎并行 + 组合搜索语法 + 收集新线索 | 原始证据集 |
| 3 账号关联 | 用户名枚举 / 头像反查 / 邮箱反查 / 手机号关联 / 写作指纹 | 跨平台账号映射 |
| 4 交叉验证 | 双源确认 + 时间线/地理逻辑 + 图片真实性 | 置信度标注 |
| 5 深度挖掘 | **个人轨迹四线重建**（职业线：LinkedIn/脉脉/BOSS直聘/猎聘/智联；技术线：GitHub/Gitee/博客；内容线：微博/知乎/B站/抖音/视频号/公众号；生活线：常驻/出行/作息/消费，见 methodology 第八章）+ **核心公司穿透**（法人/实控人/控股链/CEO/CTO 等高管/司法风险，见第九章）+ **社交人物关系网**（互动圈/共现圈/六圈分类/核心圈-桥接圈-中心性分析，见第十章）+ 关系拓扑 + 时间线 + 资产暴露面 + 核心矛盾 + 底层驱动 + 决策风格 | 深层认知 |
| 6 画像生成 | 按模板输出 HTML 报告 + 来源/置信度标注 | 自包含 HTML |
| 7 持续更新 | 可选：实时监听新数据 + 推送变更 | 更新报告 |

**执行要点**：
- 阶段 2 使用**多引擎并行检索**与组合搜索语法（如 `"姓名" AND ("公司" OR "单位")`、`site:linkedin.com 姓名`、`姓名 邮箱`）。
- 阶段 3 用**写作指纹**（用词习惯、标点、句式、常错字）辅助账号同一性判定，避免仅凭昵称误判。
- 阶段 4 对每条关键结论做**双源确认**；单源结论降级为 C/D；矛盾信息保留多版本并标注冲突。
- **同名消歧优先尝试中英文名绑定**（中文名 ↔ 拼音全名 ↔ 英文名 ↔ 邮箱前缀），一旦命中可一次锁死教育/地域/职业三点（详见 methodology 第七章 7.2）。
- **任职冲突按年份重构为「多段任职轨迹」**，而非现职二选一或简单排除同名（见 7.4）。
- 职业数据聚合器（RocketReach/ZoomInfo/Datanyze）单用最高标 B，现职/所在地可能滞后，跨源不一致当作时间线采样点而非矛盾（见 7.3）。

## 智能提问（人机协同）

遇到无法靠公开数据解决的缺口时，用 `AskUserQuestion` 提问。**优先级：身份确认 > 高价值线索 > 普通补充**。

| 缺口类型 | 提问示例 |
|---|---|
| 身份消歧 | 「搜索到 3 个同名『张伟』，请确认城市/单位？」 |
| 数据源不可达 | 「目标在小红书无公开账号，是否授权扫描线下名片？」 |
| 信息模糊 | 「请确认：1) 公司全称？2) 是否曾任职华为/阿里？3) 近三年公开演讲？」 |
| 主观判断 | 「管理风格：A) 周会后单独聊细节 B) 全员投票 C) 邮件常用『必须/务必』」 |

> 每次提问均附带**依据溯源**（为何有此缺口、依据哪条线索），保证透明可审计。

## 深层挖掘方法论

- **七阶解构法**（定性深度）：基础锚定 → 社会面具测绘 → 核心矛盾挖掘 → 底层驱动溯源 → 关系网络拓扑 → 时空行为建模 → 留白与推演。
- **五阶穿透推理**（置信度量化）：原子事实层 → 行为模式层 → 意图推断层 → 关系拓扑层 → 数字孪生层。

> 两套方法论可叠加：七阶解构负责「挖得多深」，五阶推理负责「信得有多准」。完整表格见 `references/methodology.md`。**实战补充（第七章）**：高重合名/不同公众度人物的分层证据策略、中英文名绑定、职业轨迹时间演进重构、职业数据聚合器使用纪律、社交/控股/隐私三类追问的合规产出形态、软包装头衔与微信生态内容 IP 识别、委托方合规方案的「合规执行框架区块」落地（7.8）、**授权默认成立 + 背调核验融为画像报告的默认视角而非独立产物（7.9）**——做尽调前先读，可显著降低错配与虚构风险。**个人轨迹重建（第八章）**：职业线（LinkedIn/脉脉/BOSS直聘/猎聘/智联）、技术线（GitHub/Gitee/技术博客）、内容线（微博/知乎/B站/抖音/视频号/公众号）、生活线（常驻/出行/作息/消费）四线战术与统一时间线对齐规则。**核心公司穿透（第九章）**：每家核心公司的工商注册/股权与实控穿透/高管层（CEO/CTO 等）/司法风险关键信息卡、人↔公司双向关联与同名公司排除。**社交人物关系网（第十章）**：互动圈/共现圈/组织圈六类关系人发现、六圈关系分类、强度与方向判定、核心圈-桥接圈-中心性结构分析与圈层化拓扑布局。

## 授权与核验基调（默认成立，勿反复询问）

**默认已具备目标本人书面授权，场景默认为「招聘 / 背调 / 合作核实 / 反欺诈」**。据此：
- 公开采集可放开到尽调所需范围；**敏感原始证件（身份证号、住宅地址、手机号、家庭信息）仍不入报告、不誊录**，仅作为需要目标本人出示的凭证项列出，由委托方在授权下核验。
- 无需向用户反复确认授权；只有当信息明显自相矛盾、或需用户提供某份本人凭证的电子档时，才作一次性提示。
- 画像的每一项关键结论，除 A/B/C/D 置信度外，**同时标注「公开已坐实 / 待本人凭证核验」**，把"背调核验"作为贯穿报告始终的默认视角（不是另开一份文档）。

## 产物定位（单一深度画像报告，内嵌背调核验）

**只产出一种 HTML：深度画像报告**（文件 `{目标姓名|公司名}_深度画像-{YYYY-MM-DD}.html`），不另开"背调核验框架"独立文件，也**不新增独立的"合规执行框架 / 背调核验总表"章节**。背调/核验信息与逻辑**融合进画像报告的相关节点**（教育→§3 教育表、任职→§3 任职表 + §8 时间线、工商/股权→§7 公司节点 + §10、司法/合规风险→§10），授权默认成立。

报告在保留深度画像叙事（社会面具—核心矛盾—底层驱动、关系拓扑、时间线、数字孪生推演）的同时，把以下**核验视角**贯穿全篇，回答的不是"他有哪些标签"，而是"这些结论里哪些已被公开坐实、哪些必须靠本人凭证核验真伪"：

1. **融合到节点而非另起章节**：核验状态（🔵 已坐实 / 🟡 待本人凭证）直接标注在对应的字段/任职段/公司/风险项上，不设独立的总表/框架章节。
2. **教育背景**：在基础身份章给一张"教育背景核验"表（阶段 / 学校专业学位 / 公开侧状态 / 需本人凭证·核验方式 / 影响判断）——学信网备案 + 学位证在线验真伪，主校本部与独立学院须区分。
3. **任职经历**：在基础身份章给一张"任职经历核验"表（按 7.4 时间演进逐段列出：任职段 / 雇主·职级 / 公开侧状态 / 需本人凭证·核验方式 / 角色跃迁），任职真实性以社保/个税/在职/离职证明 + HR 侧向为硬证据（职业平台自填非证明，最高 B），核心同一性疑点段标红置顶。
4. **工商 / 任职 / 股权**：在关系网络章的公司节点下方或风险章，给"工商 / 任职 / 股权穿透"表（对象 / 关联类型 / 公开侧工商结论 / 股权·最终受益人核验），并列同名工商主体的甄别排除；本人名下查无控股则如实给否定性结论 + 授权付费库收口路径。
5. **司法 / 合规风险**：在风险章给"司法 / 合规风险交叉核验"表（失信/涉诉/处罚/经营异常/知产/竞业，各带公开侧结论 + 收口核验方式）。
6. **头衔"软包装"甄别**：宣称的资质（认证/服务过的 500 强）与真实履历比对，标 C 待证书/可回访项目佐证。
7. **信息缺口即"需本人凭证清单"**：报告末尾的待确认线索，明确标注"哪一条需目标本人提供什么凭证才能从 C/D 抬升到 A/B"。

> 定位原则：**深度画像 = 骨架与叙事，背调核验 = 贯穿始终、融合到相关节点的默认证据纪律**。二者合一于一份报告，不拆成两份，不设重复的收尾总表章节。

## 画像生成与 HTML 报告（本技能核心编排）

### 第 9.1 步 · 建立设计系统（内置，无需外部技能）

按 `references/design-system.md` 执行设计定调（情报档案气质），核心纪律：

- **单一强调色**（金琥珀 `#d4a24e`）；统一圆角体系；无 emoji 图标；无空卡片。
- 三轨字体：标题衬线（权威）+ 正文无衬线 + mono 技术标签（证据感）。
- 不对称 Hero + 疏密分区 + 交错入场动效（CSS-only）。
- 所有间距用 `clamp()` 流式排版；`text-wrap: balance` 处理标题。

### 第 9.2 步 · 生成技术图表（内置，无需外部技能）

按 `references/diagram-craft.md` 的 SVG 绘制规范（Python 列表法生成 + XML 校验），为报告生成 **2–4 张**内联 SVG 图表：

1. **关系网络拓扑图**（必选）：目标为核心节点，外延家庭/同事/商业伙伴/对抗关系（显性=实线、隐性=虚线、对抗=红色）。
2. **时空行为时间线**（必选）：教育 → 职业 → 关键事件的演化路径 + 能力进化/突变点标注。
3. **五层穿透式信息融合引擎架构图**（可选）：L1 数据源 → L2 维度解析 → L3 场景建模 → L4 关系拓扑 → L5 动态孪生（方法附录）。
4. **数字孪生四层图**（可选）：静态锚点层 / 动态行为层 / 语义理解层 / 关系网络层。

> 图表统一使用暗色终端风（bg `#0f0f1a`、accent `#d4a24e`），最小字号 12px，防碰撞检查 + XML 校验通过后内联进 `.chart` 容器。

### 第 9.3 步 · 撰写自包含 HTML

基于 `references/html-template.md` 模板，生成**单个** HTML：

- 内联 `<style>` 与 `<script>`；内联 SVG 图表；无外部 `.css`/`.js`（Google Fonts 可降级）。
- 通过 `file://` 即可打开，无需服务器。
- **默认不生成 AI 配图**（画像报告以数据/图表为核心，保证证据可追溯）。

### 第 9.4 步 · 报告章节（Hero + 11 个带 id 的内容节，共 12 块）

报告始终为**一份深度画像 HTML**。背调核验作为默认视角**融合到相关节点**（教育/任职/工商/司法/竞业等各自落在对应的章节表格里），**不设独立的合规执行框架或背调核验总表章节**。正文结构 = **Hero（无 section id）+ 结论前置摘要至信息缺口共 11 个 `<section id="section-2">…` 至 `<section id="section-12">`**，合计 12 块。内容如下：

1. Hero（目标姓名 + 一句话灵魂定义 + 综合置信度徽章 + 画像类型 + **授权与核验基调徽章（已具本人书面授权·招聘背调口径）** + 生成日期 + 标签）
2. 结论前置摘要（社会面具 / 核心矛盾 / 底层驱动 / 风险 3–5 条；每处关键结论标注核验状态）

### 第 9.5 步 · 置信度与证据

- 每个字段/结论标注来源与 A/B/C/D 置信度（规范见 `references/profile-schema.md`）。
- 关键身份字段 ≥ A/B；高风险标签必须 A 级；矛盾保留多版本并标注冲突。
- 附「待确认线索」清单，供人工复核。
- **核验状态列（贯穿）**：每个关键字段/任职段加「🔵 公开已坐实」/「🟡 待本人凭证」状态徽章（用文字/色块，不用 emoji）。判定标准：多源权威一致 = 已坐实；单源/职业平台自填 = 待凭证；任职真实性最终须以社保/个税/在职/离职证明 + HR 侧向为硬证据（职业平台非证明）。

## 校验清单（每次生成报告后执行）

1. 报告为**单个自包含 HTML**，`file://` 可直接打开；不另产出"背调核验框架"独立文件，也无独立的合规执行框架/背调核验总表章节。
2. 无 `src="../`、`href="../` 等父目录引用；无外部 `.css`/`.js`（Google Fonts 除外）。
3. Hero + §2–§12 共 12 块齐全（§2–§12 共 11 个节各带 `id="section-2"…"section-12"`，Hero 不带 id；不设 §13 独立核验章节）；TOC 容器 `id="toc"` 存在。
4. 至少 2 张内联 SVG 图表（关系拓扑图 + 时间线为必选）。
5. 每个关键结论带 A/B/C/D 置信度徽章与来源脚注。
6. **核验视角融合到节点**：§3 含「①核心身份锚定 + ②教育背景核验 + ③任职经历核验」三表；§7 含「工商/任职/股权穿透」表（含同名甄别排除）；§10 含「司法/合规风险交叉核验」表（含竞业必核项；若工商穿透表未放 §7 则放 §10）；任职真实性以社保/个税/在职/离职证明为硬证据口径表述。
7. 报告不含身份证号/住址/手机号等敏感原始证件字段（仅列为需本人出示的凭证项）。
8. 风险标签与「待确认线索」以警示样式呈现；核心同一性疑点（任职轨迹）标红。
9. 无 emoji 图标、无紫蓝渐变、无空卡片（反俗套自查）。

## 合规声明

报告末尾固定声明：「以上基于公开可获取信息整理，仅供合法合规用途参考。对敏感/低置信度结论请以人工复核为准。」

**核验纪律（默认本人书面授权，融于单份画像报告）**：
- 授权默认成立（招聘/背调/合作核实/反欺诈场景），无需反复确认；但授权不等于可披露敏感原始证件——报告仍**不采集、不誊录**身份证号/住宅地址/手机号/家庭信息，仅将它们列为"需本人出示的凭证项"，由委托方在授权下核验。
- 报告只写「核验结论 + 依据」，敏感字段仅以「需本人提供某凭证」形式出现；可让候选人仅现场展示原件、不回传电子档。
- 职业数据平台（LinkedIn/脉脉/职业聚合器）自报性质最高标 B，**不得单独作为任职/学历证明**；任职真实性以社保/个税/在职/离职证明 + HR 侧向背调为准。
- 用户/委托方越界索要敏感隐私（出生精确年月/身份证/住址/家庭）时，明确拒绝但给合规替代路径（本人提供凭证 → 防伪造核验），不假意配合后编造。
