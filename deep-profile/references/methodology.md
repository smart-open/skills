# 方法论详版（deep-profile 执行参考）

本文件是 `deep-profile` 深度挖掘阶段的完整方法论，供 LLM 在「公开扩展 → 交叉验证 → 深度挖掘 → 画像生成」各阶段引用。目标是让画像**连得准、信得过、挖得深**，而非标签堆砌。

---

## 一、八维数据源矩阵

| 维度 | 数据类型 | 典型来源 | 技术手段（LLM 执行映射） |
|---|---|---|---|
| ① 公开数字足迹 | 社交内容、新闻、博客、公开视频字幕 | 微博/知乎/小红书/B站/领英/X/GitHub、搜索引擎、新闻媒体 | 多引擎并行 `WebSearch` + 组合搜索语法 + 视频字幕转写 |
| ② 半公开结构化 | 工商、司法、知识产权、学术、招聘、开源 | 天眼查/企查查/裁判文书网/专利库/ORCID/GitHub | `WebFetch` 结构化页面 + 图谱映射 |
| ③ 用户授权数据 | 邮箱收件箱、聊天导出、CRM、本地文档 | 用户上传、OAuth2.0、IMAP、本地文件 | 事实抽取 + 独立向量库隔离（标注来源） |
| ④ 设备与行为信号 | 浏览历史、APP 使用、搜索词 | 用户侧本地 Agent | 本地特征提取，仅上传脱敏特征 |
| ⑤ 多模态生物信号 | 演讲视频、会议照片、微表情/语速 | YouTube/B站/公开直播 | 描述性分析（姿态/语速/情绪），输出为线索 |
| ⑥ 知识图谱补全 | 通用/行业知识、政策法规 | Wikidata/DBpedia/UMLS/政策库 | 背景知识补全，不作为硬证据 |
| ⑦ 域名/IP/资产暴露面 | 域名、IP、子域名、端口、证书 | WHOIS/DNS/证书透明日志/Shodan/Fofa/ZoomEye | 资产测绘（公司画像重点） |
| ⑧ 威胁情报/暗网 | 泄露库比对、黑市交易、钓鱼样本 | 威胁情报平台 | 哈希比对、泄露影响评估（标注风险） |

**执行原则**：
1. 公开数据优先，授权数据仅在用户明确提供后使用并标注来源。
2. 跨源关联统一使用**不可逆哈希标识符**（如 `SHA-256(email+salt)`）作为节点，salt 本地生成。
3. 维度 ③④⑤⑧ 多为受限/敏感源，落到报告中必须标注置信度与合法合规边界，不可默认视为已获得。

## 二、七阶解构法（定性深度）

| 阶段 | 解决的问题 | 核心方法 | 输出示例 |
|---|---|---|---|
| 1 基础锚定 | 是谁 | 全字段身份核验 + 政务/学术/GitHub 交叉比对 | 唯一 ID、姓名变体、脱敏地域 |
| 2 社会面具测绘 | 如何被世界使用 | 高频动词提取 → 决策风格；互动统计 → 影响力半径 | 「危机稳定器」型管理者 |
| 3 核心矛盾挖掘 | 什么让其与众不同 | 兴趣悖论 / 行为张力 / 价值观冲突 TF-IDF 反差 | 「技术极客 vs 文艺哲思」 |
| 4 底层驱动溯源 | 什么暗中推动 | 恐惧层/欲望层/使命层三层驱动建模 | 「对技术失控的深层恐惧」 |
| 5 关系网络拓扑 | 嵌入何种生态 | 显性(股权/协作) + 隐性(思想同盟) + 对抗关系 | 影响者图谱 |
| 6 时空行为建模 | 如何随环境演化 | 能力进化曲线 + 认知疆域地图 + 突变检测 | 技能迁移路径 |
| 7 留白与推演 | 下一步做什么 | 未竟之志预测 + 未来内容生成 | 3 种可行路径概率 |

**落地映射（LLM 可执行）**：
- 阶段 2「高频动词」= 对采集文本做动词词频统计与语境归纳（如「主导/推动/协调」→ 结果导向；「倾听/共识/尊重」→ 关系导向）。
- 阶段 3「TF-IDF 反差」= 对比不同场域（技术文 vs 社论 vs 私人随笔）的高频词差异，定位身份张力。
- 阶段 4「三层驱动」= 从回避话题（恐惧）、反复追逐目标（欲望）、公开表态的价值主张（使命）反推。
- 阶段 6「突变检测」= 对比时间线相邻阶段的行为模式跳变（如突然从技术岗转向管理/公益），标注突变点并追因。

## 三、五阶穿透式推理框架（置信度量化）

| 阶段 | 目标 | 方法论 | 输出 |
|---|---|---|---|
| L1 原子事实层 | 校验基础属性真实性 | 多源交叉验证 | 置信度 98.2% 的基础身份 |
| L2 行为模式层 | 发现稳定行为规律 | 时序聚类 + 周期分解 + 异常检测 | 作息与消费规律 |
| L3 意图推断层 | 解析行为背后动机 | LLM 意图推理 + 因果发现 | 正在筹备某事（证据链） |
| L4 关系拓扑层 | 揭示隐性社会连接 | 图嵌入 + 社区发现 + 影响传播 | 核心节点、扩散层级 |
| L5 数字孪生层 | 构建可交互仿真体 | 行为预测 + 反事实推演 | 「若改变 X，将如何」 |

**落地映射（LLM 可执行，不训练真实模型）**：
- L1 = 多源一致即高置信；单源/推断降级。
- L2 = 从公开时间线提取「稳定的作息/发布/消费/出行」规律，异常即标记。
- L3 = 综合近 3–6 个月的密集动作（连续发文、频繁会面、注册商标、招聘扩编）推断动机并列出证据链。
- L4 = 关系共现分析（同一活动/项目/公司/社群反复出现的人与机构）。
- L5 = 反事实 What-if：改变某个变量（资金、职位、合作伙伴）推演 3 条概率路径。

## 四、关系拓扑

| 关系类型 | 判定依据 | 报告呈现 |
|---|---|---|
| 显性关系 | 股权、任职、合作、家庭成员、同学 | 实线 |
| 隐性关系 | 思想同盟、共同社群、同频发言、互推 | 虚线 |
| 对抗关系 | 诉讼、竞争、公开争议、观点对立 | 红色 |

**落地映射**：从共现、利益、立场三个维度给关系定性：
- 共现：是否反复出现在同一时空/项目/组织。
- 利益：是否存在股权/交易/雇佣等可量化利益纽带。
- 立场：公开观点是否同向或对立。

## 五、数字孪生四层 + 推演

| 层 | 含义 | 报告映射 |
|---|---|---|
| 静态锚点层 | 唯一强标识为根节点的身份骨架 | 基础身份锚定 |
| 动态行为层 | 时序意图流 | 时空行为建模 |
| 语义理解层 | 「兴趣—动机—价值观」语义向量 | 核心矛盾 / 底层驱动 |
| 关系网络层 | 社交圈层/供应链/知识协作 | 关系网络拓扑 |

**未竟之志预测**：基于 SOUL 主文件中的未完成事项 + 资源匹配度，生成路径概率（3 条）。
**反事实 What-if**：把 Neural ODE / GAN 的概念映射为 LLM 路径推演——「若改变 X（职位/资金/合作/监管），目标最可能转向哪条路径」，输出概率与依据。

## 六、社会面具 — 核心矛盾 — 底层驱动（逻辑骨架）

深度画像不是「列标签」，而是回答三层问题：

1. **社会面具**：他如何被世界「使用」（职位、头衔、公众角色、他人对他的期待）。
2. **核心矛盾**：他「内在张力」是什么（兴趣悖论、价值观冲突、行为反差），这是区别于同类的独特性。
3. **底层驱动**：真正「推动他」的是什么（恐惧/欲望/使命三层），这是预测未来行为的钥匙。

> 三者构成一句话灵魂定义（SOUL）：「一个以【社会面具】示人、被【核心矛盾】拉扯、最终被【底层驱动】推动的人/组织」。

## 七、高重合名 / 不同公众度人物的实战战术（新增 · 来自多轮真实尽调沉淀）

> 大量实战对象是**姓名极常见 + 有/无公开足迹**的人（如「张伟」「梁黎明」「陆骏伟」）。纯靠泛搜会淹没在无数同名者里。以下按「公众度」分层，是连得准的关键。

### 7.1 先判断对象的「公众度 / 数据丰度」，再选证据主轴

| 对象类型 | 判别信号 | 可靠证据层（由高到低） | 正确产出形态 |
|---|---|---|---|
| **科技/商业 KOL 型**（有强公开职业足迹） | 高管公开讲座、媒体专访、LinkedIn、权威机构聘任 | ① 职业数据平台聚合（RocketReach/ZoomInfo/Datanyze）② 权威机构讲座/聘任页 ③ LinkedIn 人物索引 ④ 同主题行业活动报道 | 完整职业主线 + 同名冲突多版本并列 + 头衔「软包装」甄别 |
| **非公众从业者型**（无个人公开足迹） | 泛搜全为同名撞车、本人零足迹 | ① 行业级生态锚点（雇主=哪家公司、产业链位置、同类人）② 用户补充的半公开种子（脉脉名片 URL 元数据等）③ 工作区行为留痕（若是本人） | 「行业级生态锚点 + 待证推断」为主，强制身份消歧提问，**不虚构履历** |
| **本人 / 工作区对象型** | 目标是用户自己或本地项目主角 | 工作区日志 + 技能目录 + 项目脚本本身 = 最高置信行为证据 | 以本地留痕为核心证据层，公开层仅作消歧对照 |

**核心纪律**：先判型，再定证据主轴；不要把「非公众型」硬挖成「KOL 型」，也不要用泛搜的行业噪声冒充本人履历。

### 7.2 中英文名绑定 = 最高性价比的同名消歧一击

当对象可能是「外企/出海高管」时，**优先尝试把中文名与英文名绑定**：

- 检索 `site:linkedin.com 中文名拼音`、`"Lewis Lu" 陆`、`<拼音> <公司> VP` 等组合。
- 一旦命中「中文名 = 拼音全名 + 学校(CN) + 城市 + 雇主」，可一次锁定教育/地域/职业主线三点，把整份画像从「疑似」抬到「B 级锚定」。
- 常见变体：中文名（陆骏伟）↔ 拼音（Lu Junwei / Junwei Lu）↔ 英文名（Lewis Lu）↔ 邮箱前缀（lewis.lu@…）。写作时明确列出这些变体作为关联键。

### 7.3 职业数据聚合器（RocketReach/ZoomInfo/Datanyze 等）的使用纪律

- **价值**：免费页可读到结构化的完整职业履历（教育/每段雇主/职级/所在地/邮箱域名），是「一生轨迹」最省力的一手底座。
- **局限（必须内化）**：
  1. 数据是**用户自报 + 抓取聚合**，非官方 → 单用最高标 **B 级**，绝不上 A。
  2. 「现职 / 当前所在地」字段可能**滞后**（显示老雇主 Beijing HQ 而实居苏州；或停在上一家）。跨多个聚合器出现「现职不同」时，不要当矛盾，而要当**时间线采样点**。
  3. 邮箱/电话字段多数打码（`18❅❅❅`），属于半公开线索，写报告时以「存在个人域名/邮箱」表述即可，不逐字披露。

### 7.4 任职轨迹的「时间演进重构」而非「现职二选一」

当同一人姓名在不同年份的媒体上挂着**不同雇主/头衔**时（如 2021 百望 VP、2024-25 用友产品总监、2026 独立专家）：

- ❌ 错误：把它们当「两个同名候选人」简单排除其一，或当「当前现职」硬选一个。
- ✅ 正确：按**年份排序成一条多段任职轨迹**（哪年哪个雇主什么头衔），判断「同一人跳槽/转岗」还是「确属同名」时看三个信号：① 主题是否强相关（财税→供应链→企业AI 落地，主题连续 = 倾向同一人）；② 职级是否合理演进（外企 VP→下家「产品总监」属**职级落差**，可能是口径差异/事业部名，需标注存疑）；③ 有无任离职公告、在职证明可断开/焊死这条线。
- 无法定论时**保留 A/B 两版本并列**，并把「最近雇主/现职」标为该画像**最高优先待确认点**，在结论前置摘要与时间线都按此口径写，前后一致。

### 7.5 「社交 / 控股 / 隐私」三类追问的正确产出形态（合规且有用）

用户在尽调中常追加这三类请求，逐类的正确回应：

| 用户请求 | 正确产出 | 必须避免 |
|---|---|---|
| **多挖社交** | 社交实质盘点 + 最强社交锚点（如 LinkedIn 中英文名绑定、校友会/学会职务）；如实说明「B 端专家无高活跃大众号是正常形态」 | 为凑数虚构其不存在的微博/知乎/小红书号 |
| **加控股公司** | 如实给「否定性结论」（职业经理人通常查无实控/持股）+ 甄别并**排除无关同名工商主体**（给每个的凭据） | 臆造其名下公司 |
| **挖私有/隐私** | 声明合规边界 + 指出更优替代路径（学历/证书/雇佣证明的**反伪造交叉核验**，比搜隐私更有价值） | 越过合法尽调边界去取身份证/住址/家庭等敏感信息 |

> 三条共同底线：**公开可得才写、给每条的来源与甄别依据、不可得时明确讲边界而非硬编**。

### 7.6 「软包装」头衔与内容 IP 的识别

- **媒体头衔偏营销化**：报道里的「全球企业数智化转型专家 / 曾服务 Apple/Nike/阿里/京东/招行提供顶层设计咨询 / 工信部认证」常高于可权威证实的任职细节。对策：与真实职业主线比对——其履历若真服务过这些客户（如外企供应链软件背景），则措辞虽营销但底色可信，标 C；若毫无对应履历支撑，则标「头衔夸大风险」。
- **微信生态内容 IP（公众号/视频号/小报童/知识星球）Web 端基本不可抓**：只能靠 ① 用户提供的种子信息 ② 账号定位与其公开授课主题「同构性」作间接佐证，并明确要求人工在微信内确认。不要把「查无」误报为「不存在」。
- **同生态关键人物需区隔**：对象所在圈子常有高度相似人设的其他人（如同做 OPC/OpenClaw 布道的「姑苏阿伟」、同城市另一 AI 讲师），务必在报告中显式区隔，避免读者/后续调用把两者混淆。

### 7.7 「政策/生态背景」让行为可解释

若对象是行业布道者/顾问，把它反复宣讲的概念（如「OPC 一人公司」「OpenClaw 智能体」）放到**对象所在地的真实政策与社区生态**中核对（本地政府/园区官网、官方社区、同期活动）。吻合则：
- 其布道不是空谈，而是踩中产业政策红利的真实行为 → 增强「底层驱动=使命/价值主张」的可信度；
- 也提示其潜在的商业动机（政策扶持 → 咨询/培训/孵化变现），可写入数字孪生路径依据。

## 八、个人轨迹专项挖掘（多平台人生时间线重建）

> 轨迹重建 = 把分散在各平台的「带时间戳的公开行为」对齐成**一条统一人生时间线**，分四条线索：**职业线 / 技术线 / 内容线 / 生活线**。每个轨迹点必须带「平台 + 时间 + 证据 + 置信度」四元组，最终汇入报告第 8 章「时空行为建模」。

### 8.1 职业轨迹线（LinkedIn / 脉脉 / BOSS直聘 / 猎聘 / 智联）

| 平台 | 可采信号 | 检索/取证方式 | 置信度上限 |
|---|---|---|---|
| LinkedIn | 经历段（年份/雇主/职级）、教育、技能背书、推荐语、动态/文章、人脉重叠 | `site:linkedin.com/in/ 拼音名`、中英文名绑定（见 7.2）、Google 快照 | B（自报履历） |
| 脉脉 | 职业认证、公司/职位、同事可见评价、匿名区提及 | Web 端强登录墙：靠用户种子 URL、搜索引擎快照、第三方转载 | C（间接） |
| BOSS直聘 | 招聘方（HR/老板）主页认证公司 + 在招职位；求职侧活跃状态 | 公开职位页反查招聘者；`site:zhipin.com 姓名` | B（公司认证）/ C（个人） |
| 猎聘 | 高管档案（部分公开）、猎头评价线索 | 公开档案页检索 | C |
| 智联 | 招聘方主页、职位发布历史 | 公开职位页 | C |

**产出**：多段任职轨迹（年份 × 雇主 × 职级，见 7.4 时间演进重构）、跳槽节奏（平均在职年限）、职级演进合理性、技能栈变化、由在招职位反推其**团队扩张方向**（= 意图推断层证据）。

**纪律**：招聘平台数据均为「自报 + 聚合」，单用最高 B；现职字段可能滞后（见 7.3）；BOSS直聘/猎聘上的「求职者简历」不公开，**不得虚构**，只能通过「在招/活跃」状态作时间线采样点。

### 8.2 技术轨迹线（GitHub / Gitee / 技术社区）

**GitHub（技术人物最高价值源之一）**：
- 账号发现：用户名枚举（姓名拼音全拼/缩写/常用 ID 变体）、`site:github.com 拼音名`、邮箱前缀反查、博客/简历中的链接回溯。
- 仓库语言演化 → **技能迁移曲线**（如 2019 Java → 2021 Go → 2024 AI/LLM 项目）。
- Commit 活跃度 → 项目周期与投入度；**contribution graph 时区特征 → 作息线索**（长期深夜提交 = 夜型工作习惯）。
- Follow/Star 圈 → 技术兴趣圈与隐性思想同盟（接 L4 关系拓扑）。
- Organization 成员身份 → 任职自证（与职业线互证可把雇主字段抬到 A）。

**其他技术源**：Gitee（国内镜像/自研项目）、Stack Overflow（问答领域权重）、掘金/CSDN/博客园/个人博客（域名 WHOIS 注册时间 = 技术生涯起点线索）、npm/PyPI 包发布史。

**产出**：技术栈进化曲线、开源自证链、活跃突变点（转管理后 commit 骤降、创业期新仓库爆发）。

### 8.3 内容与兴趣轨迹线（微博 / 知乎 / B站 / 抖音 / 视频号 / 公众号 / 博客）

| 平台 | 可采信号 | 要点 |
|---|---|---|
| 微博 | 注册时间、发帖频率曲线、IP 属地、签到/定位、超话、互动圈 | 属地展示可校准常驻城市（城市级即可，不细化） |
| 知乎 | 回答话题演化 = **认知疆域地图**、领域权重（优秀答主标签）、专栏文章、关注列表 | 话题从 A 领域漂移到 B 领域 = 转型信号（接阶段 6 突变检测） |
| B站 | 投稿/收藏/关注分区、充电与弹幕互动、更新频率 | 技术区 up 主身份可与 GitHub/博客互证 |
| 抖音 | 账号定位、IP 属地、作品更新节奏 | Web 端部分受限，靠用户种子 + 同构性佐证 |
| 微信视频号/公众号 | 账号存在性、内容定位 | 封闭生态 Web 基本不可抓（见 7.6），「查无 ≠ 不存在」，要求人工微信内确认 |
| 博客/独立站 | 域名 WHOIS、文章归档、RSS、web.archive.org 快照 | 快照可恢复已删文章（改稿/删稿本身是行为信号） |

**产出**：兴趣演化时间线、内容 IP 归属、影响力半径（粉丝/互动量级）、**写作指纹跨平台一致性**（接阶段 3 账号关联）。

### 8.4 生活轨迹线（常驻地 / 出行 / 作息 / 消费）

- **常驻地**：社交平台 IP 属地、签到、会议/演讲所在城市、照片 EXIF（如有授权）；只精确到**城市级**，不推门牌。
- **出行足迹**：公开演讲行程、参会名单、游记/晒图中的城市序列 → 出行密度与活动半径。
- **作息规律**：发帖时间分布（微博深夜活跃、GitHub commit 时区、直播时段）→ 昼型/夜型、工作日/周末模式。
- **消费与生活方式**：公开晒单、测评内容、品牌互动 → 消费偏好标签（接 L2 行为模式层）。

**隐私红线**：只写**公开发布**的信息；位置模糊到城市；不聚合推演住址/家庭住址/身份证件（接 7.5 合规边界）。

### 8.5 四线融合：统一时间线对齐规则

1. **对齐**：以「年份/月份」为横轴，职业线为主干，技术/内容/生活线为副轴叠加（报告第 8 章时间线图可采用双轴：主轴职业事件、副轴内容/生活事件）。
2. **冲突处理**：跨平台时间矛盾按证据强度排序；聚合器滞后值当时间线采样点不当矛盾（见 7.3）；仍冲突保留多版本（见 7.4）。
3. **突变点标注**：跳槽/转行/搬家/创业/停更沉寂/爆发更新 —— 每个突变点标注「四线中哪几条同时出现信号」（多线共振 = 高置信转折）。
4. **与七阶解构对接**：四线轨迹是阶段 6「时空行为建模」的数据底座；能力进化曲线 = 技术线+职业线合成；认知疆域地图 = 内容线（知乎话题/博客主题）合成。

## 九、核心公司穿透（人 ↔ 公司双向关联）

> 个人画像常涉及若干**核心公司**（现职/历任雇主、担任法人/股东/实控的主体、合作方）。对每家核心公司输出「关键信息卡」，既支撑职业线轨迹与关系拓扑，也是排除无关同名工商主体（见 7.5）的依据。

### 9.1 公司关键信息清单（每家核心公司必采）

| 信息块 | 字段 | 来源 | 置信度 |
|---|---|---|---|
| 工商注册 | 公司全称/简称、统一社会信用代码、**法定代表人**、注册资本（认缴/实缴）、成立日期、经营状态、企业类型、注册地址、经营范围、参保人数 | 国家企业信用信息公示系统 | A |
| 工商注册（聚合） | 同上 + 关联图谱 | 天眼查 / 企查查 / 爱企查 | B |
| 股权与控制 | 股东及持股比例、**控股类型**（自然人/法人/国资）、**实际控制人**、最终受益股份、**股权穿透链**（自然人 ← 中间控股 ← 目标公司）、对外投资（子公司/参股） | 公示系统（A）/ 聚合平台（B） | A/B |
| 高管层 | **董事长 / CEO / CTO / COO / CFO**、董事、监事、经理名单及任职起始日期、核心团队公开履历、高管变动（离任/新任 = 治理信号） | 官网 / 年报 / 公示备案（A/B）/ 新闻（C） | A–C |
| 司法与风险 | 涉诉、被执行人、失信被执行人、限制消费令、股权冻结、行政处罚、经营异常名录 | 裁判文书网 / 执行信息公开网 / 信用中国 | A |
| 知识产权 | 专利（发明/实用新型）、商标、软件著作权 | 国家知识产权局 / 专利库 | A |
| 经营信号 | 融资历史与投资方、招投标中标、招聘规模（在招职位数 = 扩张/收缩信号）、新闻舆情 | IT桔子 / 聚合平台（B）/ 新闻（C） | B/C |
| 数字资产 | 官网域名（WHOIS）、APP 备案、公众号/视频号 | 维度⑦ 资产暴露面 | B |

### 9.2 人 ↔ 公司双向关联

- **从人找公司**：任职记录（职业线）、法定代表人身份、董事/监事/经理备案、股东名册、疑似实控关系。
- **从公司找人**：高管名单反查履历；股东穿透到自然人，判断目标是否实控/最终受益。
- **交叉验证**：
  - 履历声称「某公司 CTO/VP」但公示高管备案查无此人 → 头衔存疑（接 7.6 软包装甄别，标「头衔待证」）。
  - 「法定代表人 + 大股东 + 执行董事」三合一 = **强控制信号**，写入底层驱动与数字孪生路径依据。
  - 挂名法人（持股 0 + 无任职 + 无关联交易）→ 标注「疑似挂名」，不作为控制证据。
- **同名公司排除**：对每个被排除的同名工商主体给出凭据（注册地/行业/成立时间与本人轨迹不匹配）。

### 9.3 公司角色权重（写入关系拓扑）

- 角色权重：**法定代表人/实控人 > 控股股东 > CEO/CTO 等高管 > 普通任职 > 合作方** —— 决定关系图节点大小与边的粗细。
- 高管角色变更（CTO → CEO、董事退出）本身是职业线轨迹点，纳入时间线。
- 公司风险传导：核心公司被执行/失信 → 作为个人画像的风险标签（标注「关联风险」而非本人风险）。

## 十、社交人物关系网挖掘

> 关系网回答「他嵌在什么人群结构里」。目标：从公开互动与共现中重建**圈层化的人物关系网**，识别核心圈 / 桥接圈 / 对抗圈，并让关系网变化本身成为轨迹信号。产出汇入报告第 7 章（关系拓扑图 + 圈层说明）。

### 10.1 关系人发现（节点从哪来）

| 来源 | 具体信号 | 平台示例 |
|---|---|---|
| **互动圈** | 高频评论/点赞/@、转发互动、互相关注 | 微博、知乎、B站（弹幕/充电）、X |
| **关注网络** | follow 列表、粉丝重叠度、互推 | GitHub follow、领英人脉、微博 |
| **共现圈** | 同项目/同活动/同论文/同专利/同署名 | GitHub 协作者、论文合著、专利共同发明人、大会同台 |
| **公开提及** | 专访提及、致谢名单、推荐语（双向） | 媒体专访、书籍致谢、LinkedIn Recommendation |
| **组织圈** | 校友、前同事、协会/学会职务、开源社区 | 校友会、脉脉同事、Apache/开源 PMC |
| **商业圈** | 联合创始人、投资人、客户/供应商、竞对 | 工商备案（接第九章）、融资公告 |

> 发现纪律：每个关系人必须给「发现凭据」（哪条互动/哪份共现），不凭「看起来认识」建边。

### 10.2 关系类型学（六圈分类）

| 圈层 | 关系子类 | 判定依据 | 图上呈现 |
|---|---|---|---|
| 亲属圈 | 家庭、姻亲 | 公开同框/讣告/婚礼/族谱式报道 | 实线（密） |
| 职业圈 | 上级、下属、同事、导师/门生 | 任职重叠、汇报关系、师承表述 | 实线 |
| 商业圈 | 合伙人、投资人、客户、供应商 | 股权/交易/雇佣（接第九章穿透） | 实线（粗） |
| 思想圈 | 思想同盟、互相引用、同频转发 | 观点同构、互推、引用链 | 虚线 |
| 社群圈 | 校友、协会同好、开源社区 | 组织成员重叠 | 虚线 |
| 对抗圈 | 诉讼对手、公开争论、竞对 | 裁判文书、公开笔战、同赛道竞争 | 红色 |

### 10.3 关系强度与方向判定

- **强度四信号**（由强到弱）：① 利益绑定（股权/合伙 > 雇佣 > 项目合作）② 共现频次（同台/合著/协作次数）③ 互动密度（评论/点赞/@ 频率与双向性）④ 人生节点在场（发布会站台/婚礼/悼念文）。
- **方向性**：师承/提携（不对称，单向输出）、互惠（双向互动均衡）、竞争（零和）。不对称关系在图上用单向箭头。
- **称呼佐证**：公开称呼升级（「同事」→「老搭档」→「联合创始人」）是关系演化的文字证据，纳入时间线。

### 10.4 网络结构分析（LLM 可执行的中心性映射）

- **度中心性**：连接数最多的关系人 = 目标的**社交枢纽**（信息/资源必经之路）。
- **桥接性**：同时出现在目标两个不同圈层里的人 = **信息掮客**（如既同学又投资他的人）。
- **圈层密度**：核心圈（强连接，通常 5–15 人）/ 桥接圈 / 弱连接长尾；核心圈空缺（查无强连接）本身是发现（孤狼型/封闭型）。
- **传播放大器**：目标观点被谁转发放大（大 V 好友、媒体人脉）→ 影响力半径的真实结构。
- **风险传导链**：核心圈成员的司法风险/争议沿强连接传导（标注「关联人风险」并给凭据）。

### 10.5 报告映射与轨迹联动

1. **关系拓扑图圈层布局**：目标居中，核心圈近、桥接圈中、弱连接外（三环布局，见 diagram-craft.md）；节点大小按关系强度，边样式按 10.2 圈层。
2. **关系网随时间变化也是轨迹**：新合伙人加入、核心圈断裂（取关/删文/诉讼）、圈层迁移（技术圈→投资圈）—— 作为突变点写入四线轨迹（第八章 8.5 多线共振检查）。
3. **与公司穿透联动**：商业圈成员若为法人/高管，回填核心公司穿透卡（第九章）。
