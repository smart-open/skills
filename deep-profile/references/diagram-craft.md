# SVG 图表绘制规范（deep-profile 内置，蒸馏版）

本文件是 deep-profile 报告图表的**自包含绘制规范**（蒸馏自 fireworks-tech-graph，已按本技能「档案」主题适配），不再依赖任何外部图表技能。报告需要 **2–4 张内联 SVG 图表**，其中「关系网络拓扑图」与「时空行为时间线」为必选。

---

## 一、图表类型与布局规则

### 1. 关系网络拓扑图（必选）

**语义**：目标实体为核心节点，外延家庭 / 同事 / 商业伙伴 / 对抗者等关系节点。

**布局规则**：
- **三环圈层布局**（推荐）：目标居中；**核心圈**（强连接 5–15 人）最近一环；**桥接圈**（跨圈层人物/合作伙伴）中间环；**弱连接长尾**最外环。环间距 ≥60px，核心圈节点更大（r≈28）。
- 备选均匀辐射：一级关系节点绕中心均匀分布（360°/N 等分）。
- 二级节点从一级节点以 30–45° 偏角分出，用**三次贝塞尔曲线**（`M x1,y1 C cx1,cy1 cx2,cy2 x2,y2`），不用直线。
- 同类关系（如「同事圈」「家族」）可用**虚线圆角矩形容器**分组，容器标注组名；或直接用三环距离表达亲疏。
- **关键人物标注**：社交枢纽（连接数最多）、信息掮客（桥接两圈）、传播放大器（大 V/媒体）用双描边或角标突出。
- 节点间距：节点边缘之间 ≥60px；画布边距 ≥40px。
- **关系线语义**（必须配图例）：

| 线型 | 样式 | 语义 |
|---|---|---|
| 显性关系 | 实线，`stroke: var(--accent)`，1.5px | 股权 / 任职 / 合作 / 家庭 |
| 隐性关系 | 虚线 `stroke-dasharray="4 4"`，`#5b9bd5`，1.5px | 思想同盟 / 共同社群 / 同频互动 |
| 对抗关系 | 实线，`#e05656`，1.5px | 诉讼 / 竞争 / 公开争议 |

**形状词表（语义→形状，全图一致）**：

| 概念 | 形状 |
|---|---|
| 画像目标 | 双层描边圆（大圆 r≈34，视觉最重） |
| 人物 | 圆形节点 r≈26 |
| 公司 / 组织 | 圆角矩形 |
| 事件 / 争议 | 菱形 |
| 突变点 | 实心圆 `#e05656`，r 略大 |

### 2. 时空行为时间线（必选）

**语义**：教育 → 职业 → 关键事件的演化路径 + 突变点标注。

**布局规则**：
- 横向时间轴：X 轴为时间（年份），主线为水平粗线（`stroke-width: 2`）。
- 里程碑：轴上实心圆（r=8，accent 色）；**突变点**用红色实心圆（r=10）并在上方标注原因。
- 标注：年份在节点上方 13px，事件短名在节点下方 12px；相邻标签错开（一上一下）避免碰撞。
- 密集事件可叠加第二行平行时间轴（主轴**职业线**任职段 / 副轴**技术·内容·生活线**事件），两轴间距 ≥80px；副轴事件用小一号节点区分。
- 典型 viewBox：`0 0 960 400`；节点多时加宽到 `0 0 1200 400`。

### 3. 五层穿透式信息融合引擎架构图（可选，方法附录）

- 水平分层（自上而下）：L1 数据源层 → L2 维度解析层 → L3 场景化建模层 → L4 关系拓扑层 → L5 动态孪生层。
- 每层一个通栏圆角矩形 + 层名（mono 小写字距标签）+ 一行职责描述；层间用短竖向箭头。
- viewBox：`0 0 960 600`。

### 4. 数字孪生四层图（可选）

- 四条堆叠横条（静态锚点层 / 动态行为层 / 语义理解层 / 关系网络层），左侧层名 + 右侧说明；自下而上箭头表示抽象层级提升。

|---|---|---|

## 三、SVG 技术规则

1. **viewBox**：默认 `0 0 960 600`；时间线 `0 0 960 400`；宽版 `0 0 1200 400/600`。内联进 HTML 后 `width: 100%; height: auto; min-width: 480px`。
2. **字体**：样式写在 SVG 内 `<style>`，`font-family` 用系统栈（sans-serif / monospace），**禁止外部 @import**（离线不可达）。
3. **字号**：最小 12px；节点标签 13–14px；副标注 12px；图名 14–16px。
4. **`<defs>`**：箭头用 `<marker id="arrow" markerWidth="10" markerHeight="7">`，引用必须写全 `marker-end="url(#arrow)"`；每个 `url(#...)` 引用都必须有对应定义。
5. **绘制顺序（画家模型，底层→顶层）**：画布背景 → 虚线容器/分组 → 关系线/箭头 → 节点形状 → 文字标签 → 图例。线在文字之下，保证可读。
6. **滤镜边界**：带 `filter` 的元素须离 viewBox 边缘 ≥ 元素尺寸 20%（或直接不用滤镜，靠颜色对比分层）。

## 四、防碰撞与可读性检查（生成后必查）

1. **线不穿节点**：关系线不得穿过节点内部；无法避开的交叉用**跳线弧**（半径 5–9px 半圆，同色 `fill="none"`），两条直线段绝不裸交。
2. **文字不溢出**：估算 `文字长度 × 7px ≤ 形状宽度 − 16px`，超出则换行或缩短（标签 ≤3 词）。
3. **标签错位**：线标注放线中点、偏移 6–8px（水平线放上方，垂直线放左右），不压线；多线汇聚处标签按 15–20px 错开。
4. **锚点贴边**：线段端点必须落在形状边缘，不得悬空或扎进形状中心。
5. **图例**：出现 ≥2 种线型/形状语义时必须在图表内右下角或下方配图例。
6. **marker 完整性**：所有 `marker-start/mid/end` 的 URL 均能解析到 `<defs>` 中的定义。

## 五、生成方法（防截断）

**首选 Python 列表法**逐行生成 SVG（防止长字符串截断与手写语法错）：

```python
lines = []
lines.append('<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 960 600" role="img" aria-label="关系网络拓扑图">')
lines.append('  <style>.n{fill:#15171d;stroke:#d4a24e;stroke-width:1.5}.t{fill:#e8e6e0;font-size:13px;font-family:sans-serif}</style>')
# ... 每行独立 append
lines.append('</svg>')
pathlib.Path('topology.svg').write_text('\n'.join(lines), encoding='utf-8')
```

**生成后校验**：

```bash
python -c "import xml.etree.ElementTree as ET; ET.parse('topology.svg')" && echo "Valid XML"
```

校验通过后，把 `<svg>...</svg>` 整体**内联**进报告 HTML 的 `.chart` 容器（替换模板中的示例 SVG），并在其上保留 `.chart-title` 说明行。

**无 Python 环境时的降级方案**：直接逐行书写 SVG（同样遵循防碰撞与锚点贴边规则），完成后仍必须通过 XML 校验（任何可用的校验方式均可）方可内联；两条路径的产物要求完全一致。

## 六、视觉自审门槛

XML 校验通过 ≠ 视觉正确。内联前逐项目检：

- [ ] 线是否穿过节点/文字？→ 改走节点间隙（正交绕行）
- [ ] 标签是否互相重叠或压线？→ 错开 15–20px
- [ ] 图例是否遮挡内容？→ 移到空白区
- [ ] 挤不下时**加宽 viewBox**，不要硬塞
- [ ] 中文标签是否全部正确渲染（无乱码/无截断）

发现问题修正后重新内联，最多两轮聚焦修正；仍不行则简化图表（减少二级节点/合并同类关系）。
