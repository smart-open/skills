# 画像字段 Schema + 置信度 + 智能提问（deep-profile 执行参考）

本文件定义画像报告的字段结构、置信度评分体系与智能提问模板，供 LLM 在「画像生成」阶段引用，保证输出口径统一、可审计。

---

## 一、个人画像字段表（10 维度）

| 维度 | 字段 |
|---|---|
| 基础身份 | 姓名、曾用名、性别、出生日期、民族、地域 |
| 联系方式 | 手机号、邮箱、QQ、微信、Telegram、地址 |
| 社交账号 | 平台、账号 ID、昵称、粉丝数、活跃度、注册时间 |
| 教育与职业 | 学校、专业、学历、公司、职位、工作年限、同事 |
| 职业轨迹 | 任职段（年份×雇主×职级）、跳槽节奏、职级演进、技能栈变化、招聘平台档案（LinkedIn/脉脉/BOSS直聘/猎聘/智联，自报数据最高 B） |
| 技术轨迹 | GitHub/Gitee 账号、仓库语言演化（技能迁移曲线）、commit 活跃度、开源组织身份、技术博客（掘金/CSDN/博客园/独立站） |
| 内容轨迹 | 各平台注册时间、发帖频率曲线、话题演化（认知疆域）、粉丝增长、影响力半径、写作指纹一致性 |
| 核心公司关联 | 每家公司：本人角色（法定代表人/实控人/控股股东/CEO/CTO 等高管/任职/合作）、关键工商信息摘要、控股链、司法风险、关联风险标注 |
| 关系网络 | 家庭、好友、同事、商业伙伴、共同社群 |
| 资产与消费 | 房产、车辆、消费偏好、品牌倾向 |
| 位置轨迹 | 常驻城市（城市级，不细化）、IP 属地、签到历史、通勤路线、旅行记录 |
| 生活轨迹 | 作息规律（发帖/commit 时段分布）、出行足迹（演讲/参会城市序列）、消费与生活方式标签 |
| 兴趣偏好 | 政治倾向、宗教、兴趣、阅读偏好 |
| 深层人格 | 核心矛盾、底层驱动、决策风格、Big Five 评分 |
| 风险标签 | 涉诉、失信、行政处罚、舆情负面、异常行为 |

## 二、公司画像字段表（10 维度）

| 维度 | 字段 |
|---|---|
| 工商信息 | 公司全称/简称、统一社会信用代码、**法定代表人**、注册资本（认缴/实缴）、成立日期、经营状态、企业类型、注册地址、经营范围、参保人数 |
| 股权结构 | 股东及持股比例、**控股类型**（自然人/法人/国资）、**实际控制人**、最终受益股份、**股权穿透链**、对外投资（子公司/参股） |
| 人员信息 | **董事长/CEO/CTO/COO/CFO**、董事、监事、经理名单及任职起始、核心团队履历、高管变动记录、人员规模 |
| 产品与品牌 | 产品线、品牌名、APP 名称、商标、专利、软件著作权 |
| 数字资产 | 域名（WHOIS）、IP、子域名、证书、代码仓库、APP 备案 |
| 社交媒体 | 官网、公众号、微博、领英、其他平台账号 |
| 经营状况 | 营收、融资历史与投资方、招投标、招聘规模（在招职位数）、扩张/收缩信号 |
| 司法风险 | 涉诉、被执行人、失信、限制消费令、股权冻结、行政处罚、经营异常 |
| 供应链 | 上下游、客户、供应商、合作伙伴 |
| 综合风险评分 | 财务/法律/舆情/经营 综合评级 |

## 三、置信度评分体系

| 等级 | 定义 | 示例 |
|---|---|---|
| A | 多源交叉验证，官方/权威来源 | 工商注册信息 |
| B | 单一可信来源，或两个独立来源一致 | 社交账号归属 |
| C | 单一来源、推断或历史数据 | 家庭关系推测 |
| D | 未验证线索，需人工确认 | 论坛匿名发帖 |

**规则**：
1. 关键身份字段（姓名、公司全称、统一社会信用代码等）必须 ≥ A/B。
2. 高风险标签（涉诉、失信、行政处罚、舆情负面）必须 A 级方可作为确定结论，否则标注「待确认」。
3. 信息矛盾时保留多版本并标注冲突，不强行合并。
4. 每项结论附带来源脚注（URL 或来源名），生成「待确认线索」清单。

**置信度配色（HTML 报告内统一）**：

| 等级 | 颜色 | 语义 |
|---|---|---|
| A | `#4ade80`（绿） | 高置信 |
| B | `#5b9bd5`（蓝） | 中高置信 |
| C | `#d4a24e`（琥珀） | 中低置信/推断 |
| D | `#8a8a94`（灰） | 未验证线索 |

> **注意**：C 级琥珀 `#d4a24e` 与报告的强调色（`--accent`）同值，二者语义不同——C 只表示「中低置信/推断」，不是「重要/高亮」。报告里凡出现 C 级徽章，务必让它待在徽章（`conf conf-c`）语境里，不要在图表/文字里用同色单独圈出 C 级字段当强调，避免读者把"置信度低"误读成"被强调/重要"。

## 四、智能提问模板

| 缺口类型 | 触发场景 | 提问示例 |
|---|---|---|
| 身份消歧 | 同名/昵称撞车，无法锁定唯一目标 | 「搜索到 3 个同名『张伟』，请确认城市/单位？」 |
| 数据源不可达 | 目标在特定平台无公开账号 | 「目标在小红书无公开账号，是否授权扫描线下名片？」 |
| 信息模糊 | 关键字段缺失，无法继续扩展 | 「请确认：1) 公司全称？2) 是否曾任职华为/阿里？3) 近三年公开演讲？」 |
| 主观判断 | 深层人格维度需定性输入 | 「管理风格：A) 周会后单独聊细节 B) 全员投票 C) 邮件常用『必须/务必』」 |
| 同名公众度判型 | 泛搜全是同名撞车，无法判断目标是「公众 KOL 型」还是「非公众从业者型」 | 「此人是否有公开讲座/专访/高管身份？若无，其是否曾任职 XX 公司（作为行业锚点）？」 |
| 任职轨迹多版本 | 不同年份媒体挂不同雇主/头衔，无法串成一条主线 | 「请确认其可证实的最近一家雇主与当前状态（在职 A / 在职 B / 独立顾问 / 自创）？是否有在职证明或官网个人页？」 |
| 微信生态内容 IP | 目标内容在公众号/视频号等封闭生态，Web 不可抓 | 「《一分钟拆解 AI》确为本人运营？可否提供账号截图/链接核对头像简介与公开履历是否一致？」 |
| 隐私类缺失 | 用户要求挖出生/住址/家庭等敏感信息，公开源无且越界 | 「公开源无该信息；本次既有本人授权，请目标本人出示相关凭证，我据凭证做防伪造核验，不采集敏感原件」 |

**授权与核验基调（默认成立，勿反复询问）**：默认具备目标本人书面授权、场景为招聘/背调/合作核实/反欺诈——不要在每次生成时询问授权。核验作为**融合到相关节点的默认视角**：教育/任职/工商/司法/竞业各自落在对应的章节表格里（基础身份章的教育+任职核验表、风险章的工商/股权+司法/合规核验表），而**非另设独立的"合规执行框架/背调核验总表"章节**，也非另产一份"背调核验框架"文件。授权成立不等于可披露敏感原始证件：身份证号/住址/手机号/家庭信息仍不入报告、不誊录，仅作为需本人出示的凭证项列出。需付费工商库收口（全量股权穿透/涉诉）时单列说明该项待接入授权数据源（详见 methodology 7.9）。

**优先级**：身份确认 > 高价值线索 > 普通补充。

**提问纪律**：
1. 一次最多用 `AskUserQuestion` 问 1–3 个关键问题（4 选项内，含「其他」由系统提供）。
2. 每次提问附**依据溯源**（为何有此缺口、依据哪条线索）。
3. 用户明确给出目标类型/用途后，跳过可自行推断的问题，避免冗余追问。
4. **先判型再提问**：对象是「公众 KOL 型」还是「非公众从业者型」决定提问方向——前者问任职轨迹/内容 IP 归属，后者问雇主/行业锚点/是否本人。
